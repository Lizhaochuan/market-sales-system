# V3.2-107｜M02 隔离来源签名 × PostgreSQL 水位端到端回归

## 已核实上游

基于 V3.2-106 Draft PR #113，HEAD `20bcae39008c99b2e5aaa38adeb9e3c3d8f3be34`，临时 PostgreSQL Actions #43661791907 已完成并通过。测试库是 GitHub Actions 一次性 PostgreSQL 16 服务，不等于组织内部生产级数据库验收。

## 交付及行为边界

本阶段**不开发新的生产适配器**，而是通过 `tests/integration/v3-2-107-m02-signed-postgres-e2e.test.mjs` 将以下已有实现直接组合起来：

1. `src/cross-module-source-trust-fence.mjs`（V3.2-104）：使用临时 Ed25519 私钥签名三域销售、财务、教务测试来源和独立治理名册，核对密钥标识、版本水位、撤销及来源签名。
2. `tests/helpers/v3-2-106-m02-postgres-checkpoint.mjs`（V3.2-106）：在临时 `v106_isolated` PostgreSQL 数据库内，使用按机构与异常分区的事务及 RLS 将来源水位提交到审计 checkpoint 表。
3. `src/cross-module-readonly-verification-facade.mjs`（V3.2-101）：在测试中读取实际签名来源和 SQL 版本水位，对签名失败、审计拒绝继续 fail closed。其其他行政审批依赖仍是独立的模拟只读报告，绝不代表真实机构批准。

## E2E 验收清单

| 编号 | 隔离测试目标 | 必须保持的边界 |
|---|---|---|
| E2E-01 | 来源签名验证后提交一次真实 SQL checkpoint，并回读版本和有效 keyId | 只有模拟来源一致性，不是资金授权 |
| E2E-02 | 提升三域来源和撤销水位后，关闭并重开应用 Pool 与验证器，重放签名旧数据 | 数据库保存高水位，旧证据拒绝 |
| E2E-03 | 伪造签名、单域故障、超时、错误治理方签名 | 没有 checkpoint 写入 |
| E2E-04 | 新签名密钥必须有治理名册版本上升和旧 keyId 撤销证明 | 不得延用旧密钥 |
| E2E-05 | 同版本改写证据、三域异常代数分歧 | 必须阻断；旧 checkpoint 不改变 |
| E2E-06 | 真实 SQL 在 COMMIT 前被注入错误 | 全部回滚，安全重试方能成功 |
| E2E-07 | 两个不同签名视图同时争用同一机构/异常 | 最多一个同版本证据成功 |
| E2E-08 | 使用另一机构的数据库受限角色提交合法签名来源 | RLS 拒绝越权写入 |
| E2E-09 | 接入 V3.2-101 并证明签名正确、checkpoint 已提交也不授予六项外部权威 | 所有生产业务许可始终 false |

在 CI 中使用一次性 PostgreSQL 服务以及 V3.2-106 测试角色和 schema。新测试程序也检查 `V106_ISOLATED_PG=YES_TEST_ONLY`。本期不修改 `src/server.mjs`、`src/app.mjs`、生产数据库、生产 API、`edu-management-system`、真实资金及教务表；不会添加生产迁移 039。

## 尚未完成的正式验收

测试密钥、签名机构、角色、流水、业务记录皆是虚构。V3.2-106 的数据库是实际 PostgreSQL，但短暂 CI 容器并未验证 DB 服务真实掉电、跨实例复制或正式灾难恢复。本期通过“关闭应用 Pool 再创建”演示应用重启后的持续水位；这**不能**宣称数据库服务重启后的持久性已验证。

此外，V3.2-104 的双读来源与随后 SQL 提交之间仍存在并发来源更新竞态；即便 SQL 成功，也不等于三域业务来源构成原子快照。V3.2-101 的其余正向报告为模拟依赖，其“内部当前”状态仍绝不可升级为真实财务、教务或交接批准。

16 项外部准入、R01—R10 和六项真实外部权威（财务签名、教务签名、订单资金对账、课时履约对账、三方验收、原子交接）仍未核验，正式合同 `proposed-unimplemented`。学生为主要管理单位，家庭仅在同一家庭确有多个学生时按需关联；原订单、收付款、SaleEvent、课时与补偿历史全部保留。

固定 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。本阶段继续 Draft，不合并、不部署；市场销售技术文档单独保留，不提前与现有 CRM 文档融合。
