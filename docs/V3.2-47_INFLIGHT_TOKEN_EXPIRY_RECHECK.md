# V3.2-47｜在途读取中 JWT 过期：响应前令牌与数据库身份双重复核

> **本期仅针对隔离 PostgreSQL、虚构学生/来源记录和本机 UAT 只读 API**，基于 V3.2-46 Draft PR #53（完整 GitHub Actions CI 成功）。不处理真实银行、财务、CRM 和生产身份提供者。

## 1. 已确认的安全间隙

V3.2-44—46 已在数据读取后检查 `ms.scoped_employee_identity_valid(issuer,subject)`，并覆盖员工撤销、数据库错误及最终授权返回 false 的情况。不过，在某次慢请求开始时，签名 JWT 可能仍然有效；数据库读取过程中 JWT 自身过期，此时原有的**数据库员工身份**检查仍可返回 true。

因此仅重做员工身份检查，不足以确保**响应发送时 JWT 仍有效**。

## 2. 已实施的改动

`src/uat-preview-api.mjs` 的统一 `confirmStillAuthorized()` 分支，在重新查询数据库员工授权之前，先再次执行已存在的 `verify(token)`（RS256 签名、发行方、受众、有效期检查）。结果：

- 已过期或不再符合校验条件的令牌由既有验证器产生 HTTP **401 / AUTH_REQUIRED**，不返回报告数据。
- 员工身份已经撤销则继续由受限数据库登录判定，返回 **403 / FORBIDDEN**。
- 两种拒绝均采用 `Cache-Control: no-store, max-age=0`；任何验证器或数据库异常都不能直接发送已读取的 JSON、Markdown、历史、冻结状态等内容。
- 这没有引入额外身份源、特殊令牌跳过规则、新数据库权限或生产连接。

## 3. 可运行动态回归

直接扩展 `tests/security/uat-preview-api.test.mjs`，用本机生成的签名测试 JWT 和当前受限数据库 LOGIN。每个请求的**初次验签由真实验证器完成**，数据库也实际完成受保护内容查询。测试仅在检测到该 SQL 读已返回后，将该测试进程中的受控时钟推进超过 JWT 的 `exp`，再交由现有 API 执行最终鉴权并发送结果。

| HTTP 路径 | 过期后的要求 |
|---|---|
| 来源申请列表 | 401，不返回机构列表 |
| UAT 报告 JSON | 401，不返回任务/原始来源 |
| UAT 报告 Markdown | 401，不导出文本 |
| 冻结状态 | 401，不返回状态快照 |
| 历史记录 | 401，不返回事件 |
| 历史差异 JSON | 401，不返回差异 |
| 历史差异 Markdown | 401，不导出差异 |

**7 条实际路径共享 6 条受保护的成功响应分支。** 每条均要求 `AUTH_REQUIRED`、无 `data`、无来源申请编号和 `no-store`。测试结束必须恢复原系统时间函数及连接包装；没有过期的签名令牌仍要返回本机构模拟报告的 HTTP 200。

这只验证隔离测试时钟下的过期处理；不能声称用户签发机构、公钥轮换、生产负载平衡时间偏差、所有在途请求取消、网络发送与撤销的原子性已经通过。

- 真正错绑且已有下游订单/收款/履约的学生关联持续 `hold_active`；原订单、SaleEvent、支付、消课历史不可改写。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 16 项真实准入、R01—R10 仍阻断。财务和 CRM OpenAPI 均为 `proposed-unimplemented`。
- 不创建迁移 039，不连接真实财务/CRM，不合并、不部署，不修改旧 `edu-management-system`。
