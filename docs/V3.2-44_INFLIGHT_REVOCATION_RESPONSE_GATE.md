# V3.2-44｜撤销与在途只读请求的竞态保护：末次授权复核

> 状态：隔离测试代码更改，**尚未验收**。基于 V3.2-43 Draft PR #50；仅测试本机 UAT 虚构数据，不接生产财务和 CRM。此前 V3.2-43 保证撤销提交后的新请求拒绝，而本期覆盖**请求开始时身份有效，但数据查询期间身份被撤销**的窗口。

## 1. 实际更改

- `src/uat-preview-api.mjs` 新增 `confirmStillAuthorized()`，每一条需要授权的成功数据返回路径在**数据库读取完成后、响应写出前**，使用同一个受限 DB 登录重新查询 `ms.scoped_employee_identity_valid(issuer,subject)`。
- 若撤销已经提交，返回 HTTP `403`、`Cache-Control: no-store, max-age=0`，不回传已查询的报告、历史、导出或来源编号。
- 覆盖 6 条受保护的响应分支：来源列表、冻结状态、历史差异 JSON、历史差异 Markdown、报告 JSON、报告 Markdown。公开静态页面不带个人业务数据，不依赖员工身份。
- **没有**改变数据库用户/权限/迁移、业务数据、令牌真实性验签逻辑或资金/课时系统接口。

## 2. 新增动态竞态回归

在既有 `tests/security/uat-preview-api.test.mjs` 中复用已经创建的测试员工签名和两个测试机构。先在已建立的非所有者 PostgreSQL 连接确认身份有效，然后通过测试专用的 Pool 包装器**仅延迟一次已经完成的列表 SELECT 的返回**，确保请求正处于“读取后、发送前”的可控窗口。

此时独立测试管理员提交 `staff_identity_bindings.revoked_at`，验证原有数据库连接立即将该员工视为失效，再释放挂起的查询。该 HTTP 请求必须返回 `403`，而不是泄漏查询完成前已读到的业务数据。之后保留 V3.2-43 的 12 条撤销后并发请求拒绝回归。

这不是人工睡眠模拟竞态：测试同步点被挂在真实 PostgreSQL 查询完成的位置，检查真实服务代码的**末次复核**。

## 3. 保留的局限

末次复核减少了查询完成后撤销导致的数据泄漏窗口，但**并非**撤销和网络字节发送的原子事务：如果撤销恰好在末次复核成功之后、发送前发生，仍有有限竞态。本期不保证取消撤销前已开始的所有请求，也不证明 TLS 代理缓冲/真实身份提供者失效传播。

后续若要求严格强一致撤销，需要设计跨请求/撤销方共享的同步原语、锁次序、并发边界和超时降级，独立评审后方可实施。对不确定结果始终按拒绝处理；不得以虚构 CI 通过宣称生产金融、CRM 安全完成。

## 4. 恒定禁止事项

- 学生是主要管理单位，家庭按需关联；兄弟姐妹、家庭付款不能自动改变订单资金或课时归属。
- 真正错绑且有下游订单/付款/履约的学生关联持续 `hold_active`，原订单、SaleEvent、资金、实上/消课历史不可改写。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 16 项真实准入及 R01—R10 仍未通过；两份 OpenAPI 继续 `proposed-unimplemented`。
- 只准独立隔离 CI；不合并、不部署、不接入真实财务/CRM、不修改原 CRM `edu-management-system`、不创建 migration 039。

必须使用本 PR 最新 HEAD 的完整 PostgreSQL 001—038、受限数据库角色与机构隔离、全量 Node 安全回归、Chromium 浏览器回归和 V3.1 合同测试全部成功，才可记录“本期**隔离**技术验收成功”；自动化 CI 不等于实际生产 UAT。
