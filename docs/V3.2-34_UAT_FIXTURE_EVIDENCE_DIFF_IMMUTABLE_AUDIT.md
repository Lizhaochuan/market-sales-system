# V3.2-34｜UAT 虚构证据差异、不可变历史与受限审计导出

**性质：仅在独立市场销售仓库的隔离数据库中进行虚构演练。** 真实财务/CRM 未授权，不修改真实学生、付款、订单、课时、旧 CRM 代码或正式技术文档。

**已验收基础：** V3.2-33 Draft PR #40，HEAD c208b7b5，PostgreSQL 001—036 与 8 项 Chromium 测试通过。本阶段新增迁移 037。

## 1. 不可突破的安全边界

虚构证据引用的新增、撤销或数量增加，**都不代表真实权威来源验收通过**。V3.2-31 的 16 项联调关口仍缺少真实财务、教务及信息安全审批。production_integration_allowed、execution_allowed、release_allowed 始终为 false；错误学生关联且已有订单、款项或实际授课的案件继续维持隔离。原订单、SaleEvent、资金和 CRM 消课历史不可更改。

## 2. 数据库与权限

迁移 db/migrations/037_immutable_fixture_uat_evidence_diff.sql 新增：

- ms.fixture_uat_evidence_events：只追加的测试引用事件。各来源申请独立从版本 1 开始连续编号，动作仅 fixture_added 和 fixture_withdrawn。
- 引用编号仅允许 fictional_ 前缀的安全字符；不保存真实凭证、银行卡、合同原文、学生姓名或 API 密钥。
- 撤销事件必须引用同一来源、同一检查项、同一编号中尚未撤销的新增事件；撤销只追加新版本，不删除原记录。
- 来源申请锁串行化版本号分配；同一操作键同内容幂等，修改同键内容或重复撤销均拒绝。
- ms.record_fixture_uat_evidence：仅模拟财务、教务、销售和安全审核账号可依其真实数据库角色追加对应领域的虚构事件。UAT 页面只读数据库账号没有调用资格。
- ms.readonly_fixture_uat_diff(request,from,to)：复用先前已保护的 SESSION_USER 与机构范围校验，返回版本范围内的事件、新增数、撤销数、前后有效虚构引用数和固定拒绝业务状态。
- 每段差异最多 200 条；窗口过大拒绝，不会静默截断。每个来源各有独立版本，不泄露其他机构活动量。
- 历史 UPDATE/DELETE 被不可变触发器拦截；没有新增任何真实财务、CRM 写入和解除隔离命令。

## 3. 中文页面与安全导出

新增 GET 接口：

| GET 路径 | 目的 |
|---|---|
| /api/v1/uat-preview/reports/:uuid/history | 当前全部虚构历史 |
| /api/v1/uat-preview/reports/:uuid/diff/:from/:to | 指定版本之间的只读差异 |
| /api/v1/uat-preview/reports/:uuid/diff/:from/:to/markdown | 重新鉴权后导出脱敏 Markdown |

沿用本地专用数据库 LOGIN + RS256 签名员工身份，针对每次 GET 都检查身份是否已批准、未撤销、与当前机构一致；不会相信 JWT 自报角色或机构。无 POST、PUT、PATCH、DELETE，页面不保存凭据到本地存储、Cookie 或 URL。

页面增加“虚构证据历史”板块，按来源显示版本、增撤事件、有效数量及时间线。允许指定两个版本核对差异。导出之前重新查询当前版本：若此时又发生了新增或撤销，旧预览不能按最新报告导出，必须重新加载。文本仅通过 textContent 展示，防止脚本注入。

## 4. 独立 UAT 检查步骤

1. 用模拟机构 A、B 分别登记独立来源，确保 A 不可读取 B 的历史、差异和导出。
2. 由 A 的财务审核人增加虚构对账引用，确认版本 0→1，有效引用 0→1。
3. 追加撤销事件，确认版本 1→2，有效引用 1→0，但版本 1 仍能只读追溯。
4. 直接篡改或删除历史、撤销其他机构、跨部门填报、重复撤销、伪造真实材料编号或“已通过”状态，均必须失败。
5. 在 Chromium 中文页面查看历史后新添撤销事件；旧预览的导出必须拒绝并要求刷新。
6. 身份绑定撤销后，下一次历史查询和 Markdown 导出必须被拒绝。
7. 在手机窄屏验证页面可用、报告脱敏和下载文件内容，执行 PostgreSQL 001—037、Node、Chromium、V3.1 合同的最新 HEAD 全量回归。
