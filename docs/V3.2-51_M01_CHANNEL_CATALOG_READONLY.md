# V3.2-51｜M01 渠道目录第一阶段：隔离 HTTP 只读实现

> 本阶段提供可调用的渠道目录业务接口、层级校验和真实 PostgreSQL/HTTP 自动化测试。**不是完成整个 M01**：渠道新增/编辑/停用工作流、独立严格员工数据库授权、学生首次来源归因、商机双口径业绩、正式活动费用和运营界面尚未完成。

## 1. 对齐既有真实仓库模型

沿用迁移 001 的 `ms.marketing_channels`，字段为 `id,organization_id,name,parent_id,channel_type,status`，不再创建新表或重复迁移。现有线索 `contact_events.channel_id`、商机 `opportunities.source_channel_id` 已预留渠道引用，但这不证明真实获客归因和成交金额已经核实。

本版 `GET /api/v1/marketing-channels` 只从**已验证的隔离用户机构**查询渠道并返回 `m01-isolated-channel-catalog-v1` 结构；没有写入渠道、销售金额、其他学生、家庭、资金或订单的操作。

## 2. 新增实现

- `src/marketing-channel-catalog.mjs`：纯函数 `buildIsolatedChannelCatalog(rows,orgId)`。逐条校验来源机构、合法 UUID、名称、父渠道、状态、唯一性，并识别父级不存在、跨机构 parent 引用、环形引用和过深层级。校验失败立即抛错，不返回“貌似完整”的渠道列表。
- `src/app.mjs`：增加隔离 HTTP GET 路由，只在当前老版 demo 的已鉴权机构事务中按 `organization_id=$1` 查表；最多允许 200 条，SQL 取 201 条用于检测数据过多。相同机构销售人员可读取机构公共渠道目录，不能看到其他机构的渠道 ID、名称或父子关系。
- 响应包含 `channel_id,parent_channel_id,name,channel_type,status,effective_status,depth`。父渠道已停用时，子渠道即使本身是 active，也标记为 `inactive_inherited`，但**不会篡改数据库中的原状态**。
- 标识 `source_attribution_verified=false`、`sales_event_amount_aggregated=false`、`production_integration_allowed=false`。家庭按需关联，渠道查看不能推断学生为同一家庭。

## 3. 严格模式仍关闭（关键）

新增渠道路由**未列入** `migratedLegacyReads`，在 `strictStaffMode` 下返回 `403 STAFF_ROUTE_UNMIGRATED`。不允许因“已有 GET”就回落到机构级旧 DB 登录，不能直接授予员工原始 `ms.marketing_channels` 表权限。

真正的严格模式渠道目录需将单人专用 PostgreSQL 登录、独立受限视图/SECURITY DEFINER 或预审的函数投影、最小角色、真实 IdP、双机构隔离和旧接口拒绝写入单独评审后实施。当前只证明本机模拟登录路径的隔离行为。

## 4. 实测验收用例

`tests/core/m01-isolated-channel-catalog.test.mjs` 包含：

- 不属于同一机构的渠道行、重复 ID、未知父渠道、自引用/循环、非法状态、空名称及超上限请求**全部拒绝**。
- 不变更原记录，仅返回层级、可用性和继承停用信息。
- 真实 PostgreSQL16 插入两套虚构机构和独立签名员工，HTTP `GET` 只返回本人所在机构渠道；未登录 401、机构声明造假 403。
- 现有 schema 的 `parent_id` 外键只检查是否存在，**尚没有同机构父渠道保证**：专门注入另一机构父渠道并要求读接口 fail closed，不泄漏另一机构 ID。
- 人工制造同机构环路，接口必须拒绝；不影响其他独立用例。
- HTTP 错误输出不能回传未授权行或 SQL/内部堆栈。

## 5. 未做及不得做的事项

- 无正式渠道 CRUD、活动费用处理、全面归因、成交金额统计、生产工作台、营销通知或 CRM 联调。
- 学生仍是主要管理单位，家庭按需关联；不能用一条渠道记录合并学生或自动分摊兄弟姐妹付款。
- 真正错绑且已有订单、资金、SaleEvent 或履约记录始终 `hold_active`；原业务历史不得改写。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 16 项外部权威准入与 R01—R10 仍未完成，两份外部 OpenAPI 均为 `proposed-unimplemented`。
- SQL 迁移固定 001—038；本阶段不增加 039，不合并、不部署、不修改旧 `edu-management-system`。

## 6. 阶段完成条件

在本 Draft PR 最新 HEAD 的完整 PostgreSQL、严格角色、Node、Chromium 与 V3.1 合同 CI 成功后，仅可认定“**M01 隔离只读渠道目录技术回归通过**”。不能将它标记为 M01 全功能或生产完成。
