# V3.2-25｜销售、财务、教务三方纠错方案审批（隔离数据库）

**状态：隔离功能实现草稿；Draft PR；不代表财务/教务真实审批授权已经上线。**
**依赖：** V3.2-24 Draft PR #29、V3.2-23 双主管隔离与人工升级机制。
**适用环境：** PostgreSQL 16 隔离虚构数据、受限员工专属数据库 LOGIN；不部署、不接入真实学生、合同、银行、课时或 CRM。

## 1. 本轮实现与未实现的准确边界

- 新迁移 `028_three_party_correction_plan_approvals.sql` 增加**只追加的方案版本**与**各部门签字记录**，方案、签字都通过 UPDATE/DELETE 触发器禁止改写；每版本最多三次部门决定。
- **申请人**必须是仍负责原正式线索的错误关联申请人，案件保持 `hold_active`，并有 V3.2-23 第一主管签署 `wrong_student_confirmed` 和第二主管 `escalate_manual` 的实际历史。
- 只能提出**本机构另一名明确学生**作为纠正目标；材料均为虚构的引用说明，不能由同姓名、电话或家庭关系推断正确学生。提案期间不建立任何目标学生关联，也不扩大其他学生访问权。
- **销售审核**只认本机构有效 `sales_manager`；**财务审核**只认独立 `finance_correction_reviewer`；**教务审核**只认独立 `academic_correction_reviewer`。这些是 V3.2-25 **模拟审批角色**，不是正式财务资金写入权或教务课时写入权。
- 只允许通过 `ms.propose_cross_module_student_correction` 和 `ms.sign_cross_module_student_correction` 两个专用函数提交。实际执行人从 PostgreSQL `SESSION_USER` 的受保护映射解析，不从客户端读取身份或机构号。
- 申请人不能签署自己的方案；同一个自然人即使同时拥有两种角色，也不得在同一版本签署两个部门；各部门本版本只能有一条不可变决定。
- 审批一旦被驳回或退回，当前版本不再接受新的签字；必须提交新版本并重新走三方审批。即使旧版本曾获得三方通过，只要产生新版本，旧版不再被视作**当前有效方案**。
- 受限只读投影 `ms.scoped_cross_module_correction_plans` 仅提供方案 ID、版本、日期、待处理状态、已同意部门数量和是否为当前有效“三方已同意方案”。不提供银行数额、儿童证件、原文证据、订单正文或 CRM 课时信息。
- PostgreSQL 事务锁定案件、生成单调版本号、执行当前有效版审核和追加中文审计；提案与部门签署支持严格幂等，原键不同内容必须拒绝。

### 明确未实现

**没有**原订单学生更改、资金冲正、付款重分配、退款执行、业绩重算、课时转移、CRM 发课、已消课删除、合同替换、对账完成认定和最终解除隔离的函数或后台任务。**三方批准只代表“方案审核通过但尚未执行”**；案件必须继续 `hold_active`。已存在的 V3.2-23 `release_verified` 仍限于原学生实际上正确、完全无报价/订单/收退款/履约影响的误报，不能用于本轮真正错绑的案件。

## 2. 实际数据库对象

| 类型 | 对象 | 约束 |
|---|---|---|
| 只追加方案 | `ms.cross_module_correction_plans` | 同案件版本唯一、原/目标学生不同、同申请人防重编号唯一、原案件仍隔离并有错绑双主管记录 |
| 只追加部门签署 | `ms.cross_module_correction_signoffs` | 同版本部门唯一、同版本签署人唯一、员工防重编号唯一、必须是最新版本 |
| 专用写入角色 | `ms_cross_module_plan_writer` | 只有两个 `SECURITY DEFINER` 函数 EXECUTE，没有原表 SELECT/UPDATE |
| 专用只读角色 | `ms_cross_module_plan_reader` | 只读受限审批概况投影，不访问资金或身份原表 |
| 确认部门资格 | `ms.assert_cross_module_department_authority` | 权限判断内部使用，不授予普通员工直接 EXECUTE |
| CI 专用人员 | A 提案、销售 M、财务 F、教务 A、双角色 M2、机构 B 财务 | 真实独立 PostgreSQL LOGIN；不能越机构审查 |

## 3. 状态与业务含义

`approved_department_count=0`：未完成任何部门签署。

`approved_department_count=1/2`：仅部分部门同意，仍待其他部门签署。

`approved_department_count=3` 且 `three_party_plan_approved=true`：最新方案已被三名不同人员分别通过；**还没有执行实际纠错，更未解除隔离**。

`has_rejection_or_return=true`：本版本被驳回或退回，只能新增修改版本，不能改写原审批。

`is_latest=false`：旧版已失效，历史仍保留，不能用于当前执行决定。
