# V3.2-23｜已有下游商机的双主管核对与安全解除隔离

**独立市场销售技术文档。** 本期仅用于虚构 PostgreSQL 16 和受限员工数据库账号隔离测试，依赖 Draft PR #26；未合并，不部署，不接真实 CRM、教务、合同、资金及客户身份数据。

## 核心区分

- **核实为误报，允许安全释放：** 原来关联的指定学生经 V3.2-21 独立人工核实为正确，仍有该学生同一线索的未完成商机，但无报价、销售订单、试课、收退款分配、销售认定、履约权益等额外下游记录。第一主管提交学生、商机、金融三类材料的独立核对结论；另一名从未参加案件申请、原隔离审批和第一复核的主管对最新影响快照复核后，方可安全解除销售隔离。
- **真正错误或已有下游资金订单：** 不允许自动重绑学生或转移商机、订单、业绩和收退款。第一主管记录实际错误或风险，第二主管提交人工升级处置，仍保持原销售隔离。这里的“处置记录完成”不等于“实际纠错已经完成”。
- **学生是核心管理单位。** 每次只处理原线索明确关联的一名学生。同一联系人或一个家庭中的其他学生不受自动调整。核实的是销售业务关联，不证明监护身份。

## 数据库与事务

新增 migration 027：
- 两张不可变表：ms.downstream_student_reconciliation_findings 与 ms.downstream_student_reconciliation_resolutions，分别留存第一主管核对结论和第二主管最终处置。
- 员工只能通过专属 PostgreSQL LOGIN 关联的受限函数提交。ms.attest_downstream_student_reconciliation 检查第一主管本机构有效资格、非原申请人、线索当前权限及该名学生商机。ms.resolve_downstream_student_reconciliation 要求第二主管不同于案件申请人、原隔离审批人和第一核对人。
- 第二主管请求 release_verified 时，数据库重新核查该名学生关联仍处于 verified、第一主管已经确认原关联正确、商机仍未完成、当前影响快照与第一次核对一致，并且报价、订单、收退款、试课、销售认定、权益计数均为零。不满足任意条件一律拒绝释放，原 hold_active 保持。
- 请求 escalate_manual 时只存最终处置结论和当前影响快照；不释放隔离、不改动订单、学生或财务。已有授权的权威支付事实可以在案件处理期间新增，快照不等于最终资金余额。
- 新增状态 released_verified。既有数据库销售推进守卫只在 pending 和 hold_active 时阻止推进；原数据不改变，安全释放后才恢复原来允许的操作。
- 第一、第二审批、审计、状态变更处于事务中，并使用幂等编号、唯一约束及原案件与线索锁定。两类决定均不得 UPDATE 或 DELETE。
- 不赋予任何员工对原表、资金、学生、合同或原始咨询的直接 SQL 写入权限。CI 中第二主管 M2 使用额外受限数据库账号，独立于原销售主管 M。

## 中文接口及工作台

- GET /api/v1/downstream-reconciliations：本人案件、已审核案件及本机构有效主管待处理案件的最小信息。
- POST /api/v1/downstream-reconciliations/:case_id/finding：第一主管提交原学生是否真正正确的结论、学生核实材料、商机核对材料、资金影响清单及原因。
- POST /api/v1/downstream-reconciliations/:finding_id/resolution：第二名主管独立批准误报安全释放或维持隔离、升级人工处理。
- 页面上明确写出“已确认原学生正确”“仍需另一主管审核”“两名主管复核后安全解除隔离”“确认错误或存在财务影响，继续隔离”。不能把核对证据引用展示成已经完成真实世界身份认证。

## 验收与后续界限

最新 HEAD 必须通过 PostgreSQL 001—027、双机构与真实数据库 LOGIN 限权、全部 Node 安全与业务回归、Chromium 中文第二主管实际操作、V3.1 合同回归，失败为零。重点验证：申请人不能自批、第一主管不能代第二主管、真正错误关联不得释放、已有订单/新增权威付款事实不得释放、错误案件升级后继续阻断销售、允许释放的误报不修改任何学生和商机原始归属、决定不可篡改。

**未实现的高风险业务：** 已经产生真实合同、已收款或已经发放权益的错误学生关系，需要未来单独建立销售、财务与教务权威联动，核实正确学生、原责任归因、合同更正、付款/退款及权益补偿、最终安全解除隔离。绝不能直接 UPDATE 商机或订单的 student_id 或删除历史财务行来伪造纠错完成。
