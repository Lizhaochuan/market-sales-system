## 一、接口与一致性要求

| 检验 | 条件与阻断 |
|---|---|
| 来源签名 | 三个域的公钥分别固定；签名无法验证、跨域密钥或正文篡改则拒绝 |
| 范围 | `organization_id` 和 `incident_id` 精确匹配；跨机构、跨异常与额外字段拒绝 |
| 时效 | 只接收未过期、非未来签发的测试包；最长模拟有效期 300 秒，**非生产 SLA** |
| 版本 | 同域来源 epoch 与 revision 单调，异常代数和撤销序号不回退 |
| 撤销证据 | 三域撤销序号及摘要一致；同序号换摘要被视为不可信 |
| 同版本更改 | 同一域同一 epoch/revision 的证据摘要变化即拒绝 |
| 跨模块 | 三域来源 epoch、异常代数、撤销序号和摘要一致，否则 fail closed |
| 异常与超时 | 单域超时、不可用、错误格式、时钟回退均拒绝 |
| 检查期间变化 | 再读取三域包并比较整体摘要；中途变更即拒绝，不沿用旧值 |

统一返回 `getFixtureWatermark(organization_id,incident_id)`，它符合 V3.2-101 的 `getFixtureWatermark` 注入形状：`source_epoch`、聚合 `source_revision`、`revocation_sequence`、`revocation_digest`、`incident_generation` 和 `evidence_digest`。跨源修订不会丢失在聚合最大值中，因为 `evidence_digest` 同时绑定全部三域独立证据和版本。成功时 `inspect` 只返回 `BLOCKED_FIXTURE_SIGNED_SOURCES_NO_EXTERNAL_AUTHORITY`；失败时返回明确阻断原因，不返回任何放行权限。

**限制**：内存中的版本高水位和签名公钥没有持久可信根；进程重启后无法防止可信源之外的历史重放。双读检查也不是原子事务，不能阻止返回后的并发更新或提供真实撤权推送。因此本阶段不把签名判定提升为业务授权。

## 二、来源责任与尚需实施的真实适配

销售系统需提供学生及来源主记录、异常关联与订单上下文；财务系统需提供原始收付款、资金归属、独立批准与撤销；教务系统需提供课时及履约证据、独立批准与撤销。人员组织角色撤权、可信时间、生产密钥轮换、持久审计、跨系统一致性和原子交接回执仍需要独立权威系统；此处的三个测试公钥不能替代上述来源。

机器契约：`spec/v3-2-102-m02-signed-source-contract.json`。本期单元与接口测试直接把新来源边界接入 V3.2-101 校验入口，验证证据来源错误时 V3.2-101 必须 fail closed。独立 CI 同时执行 V3.2-101 集成回归、V3.2-100 的十八组聚合回归与静态审查，不代替真实 PostgreSQL、Chromium 或正式合同 UAT。

## 三、不可越界的业务边界

所有结果固定 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。真实财务/教务签字、原订单/付款/课时核对、三方验收及跨模块原子交接均未完成，16 项外部准入与 R01—R10 仍未核验。正式合同仍是 `proposed-unimplemented`。

学生为主要管理单位，家庭按实际兄弟姐妹关联按需建立；错误学生关联形成的订单、资金、SaleEvent、课时和补偿历史不得覆盖。保持 Draft，不合并、不部署、不修改 `edu-management-system`、`src/app.mjs` 或 `src/server.mjs`；生产迁移仍由既有 001—038 规格约束，本阶段不新增 039。市场销售技术文档继续单独保留。
