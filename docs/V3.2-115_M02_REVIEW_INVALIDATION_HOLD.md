# V3.2-115｜M02 审核失效强制暂停与追加式审计（隔离实现）

## 上游及目标

基于 V3.2-114 Draft PR #121，HEAD `4473ad201fed5e2001df49d3169056ee039179fa`。其 PostgreSQL 审计测试 GitHub Actions #43665601173、V3.2-100 聚合安全测试 #43665601194 都是 `completed/success`。

V3.2-114 能保留模拟审核人回避/替换事件，却没有一个与原审核指派分开的**持续暂停账本**。V3.2-115 增加可审计、不可解除的隔离 HOLD 记录：发现旧审核人撤权、证据更新、审核生命周期变化或独立签名状态无法核验时，只允许追加暂停事件，绝不自动恢复审核、资金、教务或跨模块交接。

本阶段是**一次性 CI PostgreSQL 16 + 模拟 Ed25519 身份源**实验，不接入生产数据或真实组织人员。所谓“强制暂停”是在新隔离观察接口始终返回 `hold_active=true`，并在测试账本持久保留暂停状态；**没有开发或接通真实生产系统的事件监听、业务写入阻断或自动暂停调度**。因此不宣称真实业务已暂停。

## 来源、失效和不可授权规则

新增 `src/cross-module-reviewer-invalidation-hold.mjs` 的 `createIsolatedReviewerInvalidationHold`，使用只读 V3.2-113 原审核记录、V3.2-112 证据 intake 最新 head、V3.2-114 完整审核生命周期事件链、独立测试用 Ed25519 审核状态签名以及持久 SQL HOLD 账本。

观察触发类别：

| 触发类别 | 测试定义 | 安全含义 |
|---|---|---|
| `REVIEWER_REVOKED` | 正确固定测试签名表示当前人员撤权 | 只能认定**测试**来源声明撤权，不能证明真实员工撤权 |
| `SOURCE_PROOF_UNVERIFIED` | 签名伪造、来源故障、身份跨机构或过期 | 当**未知**处理，不把无效签名解释成真实“已撤权” |
| `EVIDENCE_UPDATED` | V112 证据最新提交与 V113 原审核快照不一致 | 旧审核当时的证据可能不再适用 |
| `REVIEWER_CHANGED` | V114 出现回避或替换生命周期事件 | 旧审核人指派已发生变化 |
| `REVIEWER_UNASSIGNED` | 生命周期显示现任审核人为 null | 无有效待审核人，继续暂停 |

即使所有模拟来源稳定、没有新的 HOLD 事件，查询返回 `BLOCKED_REVIEW_PENDING_REAL_AUTHORITY` 或 `BLOCKED_NO_RECORDED_HOLD_STILL_UNAUTHORIZED`，仍然 `hold_active=true`，**没有记录 ≠ 可以放行**。所有客户端额外传入 `hold_active=false`、`finance_authorized=true`、`handoff_allowed=true` 的请求均拒绝。

每条事件只保留机构、异常、学生复合作用域、当前模拟审核人标识、触发类别、来源签名摘要、原指派 SHA、V112/V114 head SHA、上一条 HOLD 事件摘要、同原因去重 digest 和模拟记录时间。不会存储原始学生、订单、收款、课时资料和私钥。事件以 `HOLD_PENDING_EXTERNAL_AUTHORITY` 保存，从不伪造正式审批意见。

## PostgreSQL 执行边界

- `tests/fixtures/v3-2-115-m02-review-hold.sql`：仅在 GitHub Actions 临时 `v106_isolated` 库的 `v106_test` schema 建立 `fixture_review_hold_events`、`fixture_review_hold_heads`。适用 PostgreSQL FORCE RLS，机构 A/B 专用测试角色只可读取和插入事件；无法 UPDATE/DELETE 历史事件或读取修改业务收款数据。
- head 的 `hold_active` 为 `NOT NULL CHECK(hold_active IS TRUE)`，测试角色未获该字段的 UPDATE 权限。没有 `release`、`approve`、`handoff` 等反向 API。暂存的单调 sequence 和 head digest 只允许受限更新。
- `tests/helpers/v3-2-115-m02-postgres-review-hold.mjs` 在 `SERIALIZABLE` 事务内，重新检查 V113 原指派摘要、V112 当前 intake head、V114 当前生命周期 head、上条 HOLD 事件与事件链摘要，之后原子追加 HOLD 事件并推进 head。来源变更、同原因重放、跨机构访问、数据库错误都不得生成释放。
- `scripts/v3-2-115-setup-review-hold.mjs` 校验一次性测试库名称与管理员角色，不新增生产迁移 039。
- COMMIT 后复核已持久的 HOLD 记录和来源摘要。即使最终身份签名在 COMMIT 后发生新撤销或修订，也仅返回 `BLOCKED_HOLD_EVENT_RECORDED_SOURCE_CHANGED`。COMMIT 后确认信道丢失时不谎称失败已回滚，应重新读取审计数据库。

## 隔离测试与回归

`tests/integration/v3-2-115-m02-review-invalidation-hold.test.mjs` 共 17 项（HOLD-01 至 HOLD-17），包括无记录也要阻断、真实测试 SQL 永久 HOLD、模拟撤权/来源故障、伪造签名、证据更新、模拟回避、相同原因重放、新原因链式追加、提交前回滚、提交后响应丢失、撤销变化、双实例并发、跨机构 RLS、禁止解除暂停/修改历史/资金表、非法放行参数、head 篡改以及原 V112/V113 历史保持不变。

CI 同时回归 V114—V106 的一次性 PostgreSQL 与签名负向回执用例、V105 外部准入阻断和 V82—99 的 18 阶段安全套件。CI 通过只能说明隔离 fixture 和临时数据库按当前约束运行，不代表正式生产可用。

## 外部权威与跨系统缺口

本期模拟状态签名不证明真实 IAM / 人事任命，不具备现实组织可信根。已持久的 SQL HOLD 事件也只是**测试环境的审计事实**，不能保证真实销售、财务和教务系统事件会及时送达，不能跨外部服务原子冻结人员授权或业务事务。最后一次核验完成后仍可能发生撤权，真实外部事件 outbox、投递去重、持续监听、运行时阻断、事务性接收与补偿协议都没有实现。

真实六方责任人依旧 UNASSIGNED，独立销售、财务、教务身份/资金/课时对账、三方正式验收和原子交接回执依旧缺失。16 项外部准入、R01—R10、六类真实业务权威、企业 PostgreSQL、Chromium 和正式合同 UAT 都是 UNVERIFIED，合同 `proposed-unimplemented`。

业务权限坚持 `external_authority_verified=false`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。学生为主要管理单位，家庭仅当确有同一家庭多子女时按需关联；原订单、付款、SaleEvent、课时、补偿历史保留，不原地覆盖。

继续 Draft、不合并、不部署，不修改 `edu-management-system`、现有 CRM 文档、应用生产入口或真实数据库，市场销售技术说明单独维护。
