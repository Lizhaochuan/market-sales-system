## 登录后看到什么

| 角色 | 首页 | 数据范围 |
|---|---|---|
| 销售人员 | 我的待办 | 本人客户、跟进、面谈/试听、方案、报名 |
| 销售主管 | 我的待办，可切换销售团队 | 本机构销售客户和待办，不进入市场工作台 |
| 市场人员 | 我的市场线索 | 本人录入的市场线索和交接状态，不读取销售跟进 |
| 市场主管 | 市场管理 | 本机构市场人员及线索，不读取销售记录 |
| 总管理者 | 两部门总览 | 本机构市场和销售，可分别进入对应工作台 |

独立核款员沿用财务核实入口，不因此获得市场或销售客户详情权限。部门权限每次请求从有效角色重新读取；无角色不默认当成销售。只有总管理者可以同时跨部门。严格员工数据库/真实 IAM 权限不作放宽。

## 销售日常操作

1. 登录先看“我的待办”。默认今天，显示需要跟进人数和事项数。逾期未完成单独显示，未来事项通过选择日期查看；主管可切换本人/销售团队。
2. 待办来自此前保存的下一步和预约。点“查看进展 / 继续跟进”，直接进入该客户，看到学生、进展、来源、上次沟通和主要下一步。
3. 客户概览只给出“记跟进”“约面谈 / 试听”“课程方案”等操作卡片。选一项才渲染该项表单；有效方案具备后才出现“办理报名”。允许跳过试听直接做方案和报名。
4. 保存后显示对应结果或预约确认卡，后续时间自动进入待办。未结案仍必须有明确下一步，原 V3.4 原子性、幂等性、版本及 DB 断链约束保留。
5. 已约面谈/试听的主要待办，点击执行先选择记录结果或改期，一次只进入一张操作卡片。
6. 联系方式、来源修正、重新安排、结案、转交和完整历史收进“更多操作”。方案/报名资料按需进入业务记录处理，保留所有旧版本和独立复核。

## 电话查询与市场交接

销售进入“新建 / 查询 Leads”，输入电话后离开输入框自动查询，也可按回车或查询按钮。

- 匹配到待交接市场线索：只展示必要联系人、学生、获客来源。点“接收并安排首次跟进”，沿用同一 Lead ID、原来源和市场归属；首次待办和负责人交接同事务保存。
- 已归本人或主管管理范围：直接打开原客户。
- 已归其他销售：只提示已有负责人，不展示学生/联系人详情和记录，不提供抢单。转交继续走销售主管独立审批及接手流程。
- 没有匹配：补充联系人、来源及首次安排，建立销售自建线索，不重复填写电话。
- 一个号码存在多个历史学生/Lead：保留独立记录并列出候选，选择要接收或打开的记录；不按手机号自动合并学生。新建遇到已有电话须先处理已有候选，不能绕过查询重复创建。

电话号码保存在新增的隔离目录扩展，不向旧 contacts 表增加电话字段。去除空格、括号和连字符；中国大陆手机的 +86/0086 形式统一到国内号码，其他国际号码保留国家码。查重为同机构范围的精确标准化匹配。旧非结构化联系方式不猜测为电话，需要销售按需补充。

市场可录入、查询自己的线索，主管可看市场团队；交接后仍可看原市场信息和“已交接销售”状态，看不到销售进展、沟通、金额或报名。市场内部备注保留在目录中，销售查询/详情/报表都不返回它。总管理者有权分别查看两部门。

## 数据与接口

新增 opt-in `db/workspace-migrations/040_role_workspaces.sql`，复用 ms.leads、学生、联系人、工作流及记录历史；新增一对一 `ms_workspace.lead_directory`，存标准化电话、部门、市场归属和交接事实。市场尚未被接收的线索处于交接队列，接收后立即建立受 V3.4 Open Lead 不变量约束的销售工作流。原已受管理客户保持在销售，不根据旧来源猜测跨部门所有权。

- `POST workflow/lookup`：只允许销售，按电话返回最小必要候选，不使用 URL 记录电话。
- `GET/POST workflow/market`：市场本人/市场主管/总管理者读取或录入。
- `POST workflow/{leadId}/claim`：销售接收匹配电话的市场 Lead，同时创建首次安排。
- 原销售详情、跟进、预约、财务和审批接口继续复用；市场角色全部拒绝。旧通用业务 API 在新版部门模式中对非总管理者关闭，避免绕过部门入口读取交叉资料。
- 电话接单使用组织内电话事务锁；同一市场 Lead 交接另加行锁。两个销售同时接收仅一个成功；重复防重编号返回原结果。
- 旧权限、审计和严格员工模式兼容路径保留。新版不启用“历史与管理”的跨部门入口；真实渠道/活动审批仍是原严格员工独立测试模块，本轮没有用宽权限演示替代其授权。

开启 `MS_ENABLE_ROLE_WORKSPACES=1`（同时必须启用 V3.4），先运行现有隔离升级脚本。新功能只支持独立虚构测试服务。

本机演示口令为 `0`；源码只在显式 `isolated-test` 接受此配置，JWT 签名密钥仍要求强密钥。演示角色由 `tests/fixtures/role-workspaces-demo.sql` 显式建立，重复运行不恢复被撤销的授权；普通真实员工需另行明确分配角色，不按姓名或旧记录自动授予权限。

### UAT：一分钟提示与录入丢失修复

部门工作台启用时，停用旧业务计划模块的定时扫描，避免每分钟请求已被部门权限关闭的旧接口。存在未保存输入时，后台/工具栏刷新只更新数据，不重绘当前表单；临时读取失败保留输入并提示，身份失效、撤权或记录不可见仍清理受限内容。日期快捷按钮也计入未保存修改。不使用浏览器持久存储。

“下一步活动”仅在确有其他有效活动可沿用时显示；只有“安排新动作”一个选项时隐藏这一层，直接填写具体事项、方式和时间。新增浏览器回归跨越61秒，验证录入不丢、没有旧扫描请求、手动刷新/暂时失败保留及撤权后清理。

### 连续销售卡片与简化待办

销售待办页仅展示所选日期事项及“逾期未完成”，移除“后续安排”。未来事项仍保存，选择对应日期即可查看；逾期按实际今天之前的日期判断，不根据所选未来日期重新划定。点击某条联系待办直接打开跟进卡片，并带入该事项、联系方式及上次沟通摘要；点击面谈/试听预约直接打开对应结果卡片，改期另有入口。

新建销售 Lead 或接收市场线索时，可以选择尚未沟通、刚完成面谈、刚完成电话或微信沟通。实际沟通记录与明确下一步在同一事务保存；已发生的沟通不能填未来时间，也不能直接把销售阶段当成已试听或已报名。

“下一步”可直接选择一次联系、已确定时间的试听或面谈。比如面谈后安排电话确定试听时间；到了联系日期，点待办完成电话记录并直接保存试听预约，不必返回概览再找另一张卡片。若录入时已经约好试听，就直接保存预约，不建立虚假的中间确认任务。未接通、待回复或其他未完成沟通结果不能借下一步选项确认新预约；界面和API均限制为继续联系或沿用已有活动。预约与后续普通待办仍复用原记录、版本、幂等及 DB 断链约束。

保存预约后显示预约确认卡和对应待办；预约的时间经过不会自动完成。销售明确选择“试听已结束”并记录反馈后，保存下一步，进入试听后续卡，可继续记录回访、制定课程方案或使用有效方案办理报名。未到场、取消、时间未定及再次预约仍各自保留明确下一步，改期不算已完成。

已知学生由原 Lead 带入；直接约试听时新学生姓名需补充一次，市场交接已有学生不再重复填写。界面仍一次只显示当前需要的表单，未保存输入的刷新保护继续保留。

新增 API/事务验收覆盖面谈补录＋接续、失败回滚、确认电话直接变预约、当场已约及市场交接；新增浏览器场景覆盖整条面谈→联系→试听→回访链，以及只看选定日期、真实逾期且不展示未来第三栏。

### 客户概览单一跟进动线与全流程缺口收敛

客户概览页收敛双入口：主要下一步为联系任务时，顶部主卡作为唯一“去跟进 / 记录沟通结果”入口，下方不再重复展示“记跟进”卡片；主要下一步为已预约试听/面谈时，主卡明确区分“记录试听/面谈结果”与“预约改期”，下方辅助入口改为“补充日常沟通”。单独新建预约或重新安排下一步时，自动结清此前挂起的旧普通联系待办，避免遗留孤立旧任务。

补齐端到端业务流闭环：已有试听完成/报名意向/办理报名阶段的客户再次预约或完成补充试听时，阶段不再倒退回退，未建立有效报名单前禁止手工把阶段置为办理报名；完成已预约面谈时同步更新阶段并生成线下沟通记录；同一客户支持显式新增同家庭其他学生预约试听或办报名；新建/交接支持记录首次电话未接通并限制直接确认预约；主管端补齐待审批提醒及折扣/转交/修正驳回闭环，折扣待批或已驳回期间禁止直接提交报名；前端补齐全款核实后的“办理成交结案”卡片、无待办客户搜索筛选、单卡片未完成跟进草稿恢复（保留最新版本号）及放弃原因结案跳转带入。
