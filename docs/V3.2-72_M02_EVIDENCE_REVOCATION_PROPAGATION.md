# V3.2-72｜M02 证据撤销传播、旧版本失效和跨模块持续阻断

## 前置条件
基于 V3.2-71 Draft PR #78 修复 HEAD `16c72e6fd7330f3b794ce34b8eca1791991e9f4a`。上游最新完整 CI 必须通过，才能认定本阶段基线有效；CI 尚未通过时只能保留 Draft。

## 交付
- `src/cross-module-evidence-revocation-ledger.mjs` 仅在 Node CI 内存维护机构/异常作用域的撤销序号、来源 epoch、确定性 SHA-256 撤销摘要、严格幂等请求键和已撤销事件集合；来源 epoch 由测试运行器带外注入。
- 冻结证据的交接预检必须与**当前**撤销序号和摘要一致；一旦撤销清单变化、来源 epoch 变化、证据已撤销，旧版本必须 fail closed。即使虚构快照一致也只能是 `BLOCKED_EXTERNAL_REVOCATION_AUTHORITY_UNAVAILABLE`。
- 检查机构隔离、请求键冲突、序号跳跃、重复撤销、伪造授权字段和历史旧版本。仅验证离线逻辑，不提供 HTTP 写接口、正式权限或持久事务。
- `tests/security/v3-2-72-m02-evidence-revocation.test.mjs` 覆盖撤销前后历史失效、幂等重试、来源版本变化、跨机构、防重和拒绝执行。

## 不得越界
内存撤销清单没有生产持久性、真实权威来源签名、跨节点事务、密钥吊销或与市场销售/财务/教务真实系统的可信同步。无论测试判定如何，`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。

学生为主单位，家庭按需关联。已有错绑的订单、资金、SaleEvent 和教务课时保留原史，不得原地覆盖；真实补偿和解除隔离必须经过独立销售、财务、教务三方核验。16 项准入和 R01—R10 未完成，正式集成合同继续 `proposed-unimplemented`。生产迁移仍 001—038，无 039。不合并、不部署，不修改 `edu-management-system`。本市场销售模块技术文档继续独立维护。
