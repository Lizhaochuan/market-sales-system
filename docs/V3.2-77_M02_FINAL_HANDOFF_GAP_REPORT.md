## 已实现：严格只读、最少字段、虚构预检报告
`src/cross-module-handoff-gap-report.mjs` 组合 V3.2-76 最终交接预检返回，只接受机构、异常、来源摘要、撤销引用和测试钩子这些限定字段；不提供 HTTP 交接路由，不存真实个人信息、原流水、订单、课时或审核明文。

报告固定列出以下 **6 类外部真实证据缺口**，每项必须是 `needs_external_authority`，绝不因本地测试通过而被误标完成：
1. 财务独立签名及撤销状态；
2. 教务独立签名及撤销状态；
3. 原订单、收付款与资金归属核对；
4. 学生、课时、课程权益及履约核对；
5. 销售、财务、教务联合验收；
6. 原子交接和可信外部签收回执。

额外第七项单独展示 **虚构预检一致性**。只有 V3.2-76 返回规定的受限、全 false 业务权限响应，并且内部复核、撤销和三域虚构一致性都成功时，标记 `local_check_consistent=true`，状态仍为 `not_verified`；否则为 `blocked`。任何伪造财务授权、交接允许、资金补偿、解除隔离，或依赖失效、非法形状，均 fail closed。

## 绝对禁止的操作
所有结果固定 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`、`production_integration_allowed=false`。

这只是内存中的离线阻断报告，不是可信生产审批服务；没有真实身份核验、财务原流水、教务履约核对、跨系统事务、签名或撤销链。若未来开始真实人工 UAT，需要外部权威来源通过独立审核提交签署材料，并验证机构范围、签名有效性、撤销与重放、来源版本、资金和课时对账以及最后的事务性收件回执。不能凭此报告自动解封。

学生是主要管理单位，家庭只按实际多个孩子的关系建立。已有错误学生绑定且存在订单、资金、SaleEvent 或履约时，保留原历史和补偿轨迹，不能原地覆盖。外部 16 项准入和 R01—R10 尚未完成，正式财务及教务合同继续 `proposed-unimplemented`。生产迁移仍 001—038，无 039。不合并、不部署、不修改 `edu-management-system`，市场销售技术文档独立维护。
