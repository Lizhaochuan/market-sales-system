## 本阶段 CI-only 实现
新增 `src/cross-module-attestation-lifecycle.mjs`，基于真实 V3.2-97 测试快照对象的 `verify/audit` 及 V3.2-98 的 `report/audit`，在内存中建立独立行政撤销和**新快照重新签收关系**。独立测试适配器提供人员组织角色与时钟。它不修改现有源快照或旧签收，不接入真实生产审批或电子签名。

- **主动撤销**：仅由未参与原五步审核、当前仍具有销售内部稽核权限的测试人员执行。撤销必须绑定机构、异常、原快照 SHA-256 和原行政签收事件 SHA-256；允许为失效历史补记撤销，但同一签收不可重复撤销。撤销仅追加新事件，不能恢复任何旧签收。
- **被动失效**：每次 `inspect` 都重读 V3.2-97 当前快照核验及 V3.2-98 行政签收报告，识别旧快照被替代、来源证据变化、恢复结论撤销或过期、参与人员撤权与签收历史不可信。显式撤销优先于一切所谓当前性。
- **重新签收**：只能先由 V3.2-97 新建**后一条、当前有效**的冻结快照，再通过 V3.2-98 重新由五名有效且不同的测试人员完成申请、销售独立复核、财务复核、教务复核及销售行政签收。最后由没有参加新旧两轮五步审核的独立测试稽核人员，仅记录新旧签收之间的只追加关联。旧快照不能自行补签或续期。
- **完整性核验**：每次引用新旧签收都检查对应冻结历史和签收历史的连续序号、前驱摘要、SHA-256、同一机构/异常、输入引用摘要、五步顺序、角色与人员相互独立性、行政签收事件摘要。历史链接不允许分叉、非连续新快照、重复签收，幂等键换正文拒绝，同一机构/异常的测试写入按异步队列串行。
- 读取是非原子过程，重复核验只能缩小竞争窗口，不能提供生产事务保证；SHA-256 内存链不是可信持久审计或真实数字签名。
