## 交付
`src/cross-module-readonly-verification-facade.mjs` 导出 `createIsolatedReadOnlyVerificationFacade`，目前只能通过测试依赖注入接受以下五个接口：

| 模块/来源 | 必须调用的只读方法 | 验证边界 |
|---|---|---|
| V3.2-96 统一交接阻断 | `unifiedRecoveryGate.report` | 仍处于阻断状态；六类外部权威条件未满足；任务数量、摘要一致 |
| V3.2-97 最终快照 | `finalReview.verify` | 仅接受当前最新且未失效快照，拒绝旧版本 |
| V3.2-98 行政复核 | `attestation.report` | 五步人员分离内部复核完整，签收摘要绑定快照 |
| V3.2-99 签收生命周期 | **`attestationLifecycle.inspect`（不可省略）** | 撤销、历史重放、人员失权和旧签收必须拒绝 |
| 独立来源水位 | `getFixtureWatermark` | 机构/异常与 source epoch、revision、撤销摘要/序号、异常代数、证据摘要一致 |

调用者必须提供严格限定的 `reference`、`snapshot_digest`、`acknowledgement_digest` 和测试钩子 `afterFirstRead`；不接受多余字段和自称 `handoff_allowed=true` 的请求。跨机构或跨异常引用拒绝。每轮依次读取水位、阻断报告、快照、签收、**最新撤销层**和再次水位。连续三轮只读观察对比摘要，任一状态、来源版本、人员权限或撤销变化即 fail closed。

即使内部状态均当前，只会返回 `BLOCKED_CURRENT_FIXTURE_REVIEW_WITH_EXTERNAL_GAPS`、`fixture_internal_review_current=true` 和六项外部缺口数量；永远固定 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。测试一致性**不是生产授权**。CI 使用多次读取但不构成数据库事务、分布式锁或连续性证明；最终读取之后的并发变化仍需生产层原子验证。

## 真实来源责任边界（仅拟议，尚未实施）

| 责任系统 | 后续必须提供的可信只读证据 | 目前状态 |
|---|---|---|
| 销售 | 学生主要管理记录、关联差异、订单上下文和异常时间线 | 仅测试数据 |
| 财务 | 原订单/应收/收款/支付归属、独立签名和撤销记录 | 未获得真实系统权威 |
| 教务 | 学生权益、课时履约、调整依据、独立签名和撤销记录 | 未获得真实系统权威 |
| 身份与权限 | 可核验员工身份、组织范围、在岗及角色撤权 | 仅测试身份适配 |
| 跨模块协调 | 三方正式签收与原子交接回执、可信持久审计 | 未实现 |

**没有开发任何真实 CRM/财务/教务 API 端点或写入接口**；`src/server.mjs`、`src/app.mjs`、生产迁移和 `edu-management-system` 均不改动。JSON 机器契约 `spec/v3-2-101-m02-readonly-verification-facade.json` 固定了隔离适配方法、来源字段、阻断结果和后续生产验收条件。正式合同继续 `proposed-unimplemented`。

## 测试、剩余风险与后续
`tests/security/v3-2-101-m02-readonly-verification-facade.test.mjs` 直接运行 V3.2-97、98、99 的隔离实例，检验 V3.2-98 仍显示当前、但 V3.2-99 已撤销时，统一入口不能给出内部当前结论；还覆盖来源/撤销/异常/任务变化、人员撤权、结论到期、机构/异常越界、伪造批准、缺失回执及检查期间变更。专属 Node 22 CI 运行本期回归、上游签收及 V3.2-100 18 阶段聚合回归。它不代替完整 PostgreSQL、Chromium、合同或三方 UAT。

16 项外部准入与 R01—R10 仍未通过，六项真实外部权威与原子交接回执缺失。学生为主要管理单位，家庭按需关联；不得原地覆盖错误学生关联下的订单、收付款、SaleEvent、课时及补偿历史。上游规格中生产迁移为 001—038，本阶段没有迁移 039。不合并、不部署，市场销售技术说明单独维护，不提前并入现有 CRM 文档。

**V3.2-102 优先项：** 对五个适配接口建立严格的来源真实性、版本因果、超时与撤权错误契约，并在隔离 PostgreSQL 和合同测试中验证缺失或伪造来源必须保持阻断。只有这些证据通过后，才能讨论真实只读接口接入；尚不能打开任何资金或教务写入权限。
