# V3.2-61｜M02 财务交接资料完整性和异常阻断

上游是 Draft PR #67，基线 HEAD `28b50e1ac4a4539bdbc01ef28b413ade4f8ffbd9`。此阶段仅供 CI 虚构机构进行销售审核快照一致性核对，**不提供财务审批**。

## 新增能力

1. 在 V3.2-60 严格员工只读视图末尾追加 `readiness_status`，不改变既有字段、所有权或受限可见规则。
2. 只对 `sales_approved_pending_finance` 且本人提交或本人实际审批的活动提供结果。把冻结的名称、版本、计划预算、负责人、时间、渠道以及草稿状态与当前记录重新比较。
3. 四种有限状态：`ready_for_external_manual_check` 仅表示技术资料一致；`blocked_missing_campaign`、`blocked_campaign_not_draft`、`blocked_snapshot_mismatch` 均是阻断项，不生成财务决定、补偿或新审批。
4. 中文清单将一致与异常明确区分，读取失败仍清空；受限 PostgreSQL 只读权限、100 条上限和原审批审计历史不可变。
5. 新增真实 PostgreSQL/HTTP 状态断言与只读静态合同；生产迁移仍 001—038，不创建 039。

## 不可突破的边界

**技术资料一致不代表财务批准或已经送达财务部门。** 财务真实签名、预算审批、费用支出、活动发布、成本归集与客户归因仍未实现；即便 `ready_for_external_manual_check` 也始终 `finance_authorized=false`、`execution_allowed=false`，`marketing_campaigns.status='draft'`。

学生为主单位、家庭按需关联。错误学生绑定已有订单/收退款/教务履约时继续 `hold_active`；旧订单、支付、SaleEvent、课时不可改。16 项外部权威准入、R01—R10 未通过，财务/CRM 接口仍 `proposed-unimplemented`；`production_integration_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。不合并、不部署、不修改原 `edu-management-system`。

以本 PR 最新 HEAD GitHub Actions 完整 PostgreSQL/Node/Chromium/合同执行成功作为隔离技术验收条件。
