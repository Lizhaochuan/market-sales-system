# V3.2-108｜M02 来源签名与 SQL 提交前后竞态检查

## 上游与范围

上游 V3.2-107 Draft PR #114 HEAD `dbde3e4fb26f2c88c87af03e9957071d19041842`，真实**一次性 CI PostgreSQL** Actions #43662203065 completed/success。V3.2-107 将模拟来源签名验证连接到临时 PostgreSQL 水位事务，但其双读来源与 SQL COMMIT 并不共享真正的事务；来源可能在签名读取后、SQL 提交前后更改。

V3.2-108 是**竞态暴露和重复一致性检查**，不是跨系统原子提交功能。新增 `src/cross-module-postcommit-causal-recheck.mjs`，仅在隔离 CI 测试中组合原 V3.2-104 签名来源、V3.2-106 PostgreSQL checkpoint 存储与新测试注入的故障时点。读取同一组织/异常下的来源水位之后，必须从实际 SQL 再回读已提交 checkpoint；根据三域 keyId、版本向量、证据摘要与撤销序号重算整体水位摘要，拒绝不一致。

每次 `inspect` 做三轮已提交水位观察，比较签名来源与 SQL 结果，在预设时点注入模拟撤销或更新。**每轮来源观察会调用 `checkpointStore.advance` 推进审计水位**，因此不是纯无副作用的“只读”函数；它不会修改业务订单、付款或课时数据。真实生产设计必须继续把审计水位受限写角色和业务数据写权限隔离。

## 竞态回归矩阵

| ID | 竞争时点/故障 | 预期 |
|---|---|---|
| RACE-01 | 签名来源与 SQL 完全稳定 | 仅返回测试观察一致、全部业务权限拒绝 |
| RACE-02 | 来源在首次签名读取与 SQL COMMIT 之间改变 | 后续两轮摘要不同，拒绝沿用旧结果 |
| RACE-03 | 首次 SQL COMMIT 后出现撤销 | 新撤销推进后拒绝旧审核当前性 |
| RACE-04 | 第二轮 SQL COMMIT 后证据版本变化 | 第三轮发现并拒绝 |
| RACE-05 | SQL COMMIT 后新签名错误、来源中断或治理签名替换 | 拒绝，不生成有效业务许可 |
| RACE-06 | 已验证签名，但 PostgreSQL 在 COMMIT 前故障 | 回滚且拒绝 |
| RACE-07 | 不同机构的受限 SQL 角色尝试提交来源证明 | RLS 拒绝 |
| RACE-08 | 已签名证据在相同版本下变更 | SQL 单调水位规则拒绝改写历史 |
| RACE-09 | 最后一次检查已经返回后，来源立即变化 | **仍存在未封闭的跨系统竞态**；历史结果不获真实授权，下一次检验必须重新读取 |
| RACE-10 | 请求夹带解除隔离或错误机构参数 | 直接拒绝 |

在 GitHub Actions 一次性 `postgres:16`、数据库 `v106_isolated`、`v106_test` schema 下执行。V3.2-106 原有 SQL、专用租户角色和 PostgreSQL 强制 RLS 继续复用，没有新的业务表或生产迁移。

## 必须公开的剩余风险

**反复双读或三次读取没有办法保证最终检查与真正业务交接之间的所有状态变化。** RACE-09 刻意显示：返回模拟的 `fixture_postcommit_stable=true` 后，外部来源仍可发生新的撤销；因此这个字段只代表测试观察时点的证据一致，不能被解释成签字、业务接管或已解除隔离。若后续有外部权威，仍需独立签署、可吊销且带来源版本向量的原子屏障/租约或等效提交协议，并对 SQL 事务与外部业务处理定义一致的“检查+提交”边界。没有这种契约不能上线交接。

其他尚未完成：真实财务与教务独立签名、订单资金对账、课时权益对账、销售/财务/教务三方验收、原子交接回执；16 项外部准入与 R01—R10；正式企业 PostgreSQL、Chromium 及合同 UAT。CI 临时密钥与测试数据库并不代表真实机构来源或审批权威。合同状态始终 `proposed-unimplemented`。

本期返回仍强制 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。学生为主要管理单位，家庭按需关联；错误学生关联形成的订单、收付款、SaleEvent、课时与补偿历史不可覆盖。生产迁移按既有规格 001—038 管理，本阶段不增加 039，不修改 `edu-management-system` 或正式 CRM 运行入口，不合并、不部署；市场销售技术说明继续独立维护。
