# V3.2-43｜员工身份撤销后会话及并发读取的隔离回归

> 仅针对**虚构员工、虚构机构、隔离 PostgreSQL 和本机 UAT 只读 API** 的实际测试。依赖 V3.2-42 Draft PR #49；并非生产财务/CRM 身份吊销或真实业务安全验收。所有 PR 仍为 Draft。

## 1. 原有代码与本期增量

- 原有 `tests/security/uat-preview-api.test.mjs` 已覆盖签名身份撤销后的单次读取/导出拒绝。本期直接增强同一个现有动态测试，避免另开文件重复创建身份绑定、引入并行测试账号冲突。
- 先取得已授权的 A 机构测试数据库连接，并在该连接上调用 `ms.scoped_employee_identity_valid(issuer, subject)` 得到 true。
- 用独立受控测试数据库所有者连接将 `ms.staff_identity_bindings.revoked_at` 更新并**等待事务提交**，再在同一条已建立的 A 机构数据库连接验证 `ms.scoped_employee_identity_valid` 返回 false。关闭该连接占用后，再发起并发 HTTP 请求。
- 使用原有有效签名 JWT，撤销后并发发出 **12 条**只读请求，覆盖 7 种路径：来源列表、报告详情、Markdown 导出、历史、冻结状态、差异与差异 Markdown 导出。每项都应 403、`Cache-Control: no-store, max-age=0`，禁止在拒绝响应中回显敏感来源申请 ID。

## 2. 明确边界：撤销后新请求 ≠ 撤销前正在执行的请求

本测试只证明**撤销提交之后开始的**请求必须重新校验授权。它**不证明**在撤销提交之前已经完成鉴权、已经在运行的数据库查询会被中断；后者需要另外设计请求取消、隔离执行与争议结果处理机制，且不得将未知执行当作安全完成。

本测试也不覆盖真实外部身份提供者、长生命周期生产凭据、真实财务 CRM 的账户撤销、灾备恢复或正式独立 UAT。V3.2-40 的 T07—T10 真实环境缺口继续 **NOT PROVEN**。

## 3. 失败标准和交付解释

- 只要旧连接仍返回 true、撤销后某一路径不是 403、错误响应携带来源申请 ID、HTTP 缓存策略不符，或任一此前回归退化，CI 必须失败。
- 本阶段**不修改授权函数或数据库权限**，只强化既有 UAT 测试与追踪合同；不存在新 SQL 迁移 039。
- **最新 PR HEAD 的完整 GitHub Actions 必须 completed/success**，才能认定隔离回归技术验收成功。上游 CI 通过不能代替本版。
- 学生为主要管理单位，家庭按需关联；真正错绑且已有订单、资金、课时下游的案件继续 `hold_active`。原订单、SaleEvent、付款分配、已上/已消课时历史不可覆盖。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。两份财务/CRM OpenAPI 仍是 `proposed-unimplemented`；不连接真实系统、不合并、不部署、不修改 `edu-management-system`。
