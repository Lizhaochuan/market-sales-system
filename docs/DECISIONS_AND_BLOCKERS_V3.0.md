# 市场与销售系统 V3.0：待确认事项与实施阻断项

**日期**：2026-11-13  
**从属文档**：`MARKET_SALES_TECHNICAL_SPEC_V3.0.md`  
**说明**：本文件与新市场销售技术规格一起独立维护；不改变现有 CRM 文档。

## A. 已确认业务基线（不得私自更改）

- 学生是默认客户管理单位；家庭仅在确认有两名或以上同一家庭学生时建立关联。
- 共享家长电话不等于共享学生身份，不自动合并学生档案或授权。
- 学生首次来源、商机来源双口径；一个成交主要活动，允许辅助活动但不得重复金额。
- 一人一学生订单为默认；家长合并付款须通过明确付款分配到各订单。
- 全额付清并经财务权威确认才生成唯一正式成交事件。
- 销售业绩默认归成交时商机负责人，主管批准后多人分配比例合计100%；机构成交不重复。
- 课程及标准价、试听排课、正式学员与课时权益由现有 CRM 权威管理。
- 市场费用按实际用途分配；不明部分独立待分配。
- 预设角色+可配置权限；低风险自动执行、高风险审批。
- 独立系统与独立数据库，标准 API 逐步集成；不直接共享业务表。

## B. 业务决策待确认

| 编号 | 问题 | 优先级 | 安全默认/临时处理 |
|---|---|---|---|
| BP-01 | 部分付款是否允许先开课、开多少权益、谁审批 | P0 | 在正式政策前不自动开通未经批准权益 |
| BP-02 | 一次付款如何分配至兄弟姐妹两个订单，收款谁有分配权限 | P0 | 未确认用途的金额待分配，禁止两个订单同时虚假成交 |
| BP-03 | 报价有效期内标准售价变动时是否保障原报价 | P1 | 不自行承诺旧价有效；保存报价快照 |
| BP-04 | 兄弟姐妹折扣在学生订单/课程明细之间的分配规则 | P0 | 无确定金额明细，不生成有效正式订单 |
| BP-05 | 退款如何冲回销售业绩与已发提成 | P1 | 原比例冲回为默认建议，须核实薪酬政策 |
| BP-06 | 单校区/多校区组织及跨校区权限 | P1/P0 | 组织字段预留；不放宽数据访问范围 |
| BP-07 | 线索导入、家长联系偏好、数据保留和导出审批 | P1 | 不自动导入真实数据或发送客户推广信息 |
