# V3.2-16｜联系人交接撤回、争议复核与学生关系最小权限

**隔离边界：**仅供虚构 PostgreSQL 16 / 本机严格员工测试。此技术文档只在独立仓库维护，不并入旧教培 CRM。上游依赖 V3.2-15 Draft PR #19；本版本只创建 Draft PR，严禁合并与上线。

## 一、交接后撤回
* 仅对当前仍生效、由独立主管批准过的联系人管理权申请撤回。交接申请人及当前管理人可提出申请。申请不自动改变权限。
* 撤回申请必须提供虚构证据说明、明确业务原因和幂等键；同一联系人一次仅允许一项待决的交接/复核。
* 有效且无利益冲突的本机构主管决定「撤回恢复前任管理人 / 维持现管理权 / 驳回」；原申请人、接收人、撤回申请人或前任管理人均不得自行审核。
* 数据库锁定联系人、核验申请所指的分配仍是当前有效分配。若前任管理人失效，拒绝自动恢复，需其他合法转交路径。审批完成后，在同一事务内撤销接收方现管理权并创建新的恢复记录。新事务查询立即按当前数据库记录重新判权；已有事务在原快照完成前不能被强制中断，生产化需另外处理短期会话和缓存失效。
* 保留原审批决定及历史分配，不改创建人、既往咨询记录、学生负责人、线索、家庭、财务与业绩归因。若接收方独立拥有其他学生/线索关系，撤回不会越权删除这些独立权限；对联系人保留的最小姓名可见权不等同联系人管理权。

## 二、争议复核
* 原交接申请人、当前管理人、原联系人创建人可以针对**当前有效的交接分配**提出争议；申请时记录原因和证据引用，不在员工普通列表显示证据详情。
* 有效独立主管必须与交接双方、申请人及前任管理人不同。每项决定写入不可改写的 `contact_custody_review_decisions`，并追加中文业务审计。
* 允许维持、撤回或驳回争议。撤回通过新增反向管理权分配来实现，永不覆盖原批准记录。过时争议不能改变已经被再次合法交接的联系人。

## 三、学生关系细分授权
* 权限以**单名学生**为管理单位：学生当前负责人及已有独立批准的指定学生授权，仍通过原 `student_directory_assigned` / `scoped_legacy_student_details` 查看，不因联系人交接获得全量访问。
* 当前联系人管理人可借**已核实且有效**的联系人—学生关系，通过新的 `scoped_related_student_basic` 投影只读学生姓名、学生 ID、关系类型；待核实关系不得授予此权限。
* 该最小关系投影没有年级、学校、学生负责人、电话、其他机构数据、销售金额、家庭成员、其他学生、咨询内容、线索和财务字段。使用数据库当前 `SESSION_USER` 的受保护映射，不能通过 HTTP 机构编号切换；员工角色不产生全机构浏览权。
* 原始学生、联系人、交接、复核、财务、审计表始终不授予员工数据库账号直接 SELECT/UPDATE。旧的正式身份或其他机构数据不能经这些视图访问。
* **说明：**该新增投影只为已核实关系提供最小只读信息。未来更细的字段/用途审批与法律监护证明，需要独立产品与安全验收，不能从关系标签本身推断法定监护人身份。

## 四、真实咨询转销售线索：评估，不开放
| 步骤 | 员工独立低权限 | 必须主管核实/审批 | 当前状态 |
|---|---|---|---|
| 登记本次实际咨询 | 仅当前联系人管理人可以单次记录、幂等防重复，咨询属于记录员工 | 如咨询真实性有争议则复核 | 已隔离可测试 |
| 根据自己登记的咨询提出「转线索候选」 | 可设计为只提交意向，不写正式 leads | 审核证据、同事件是否已转过线索、拒绝营销意愿与客户身份 | **仅评估**；无新写接口 |
| 独立确认线索来源、负责人及归因 | 员工不可自批或修改已归档历史 | 主管核对原始咨询事件，跨销售争议独立复核 | **未实现** |
| 正式创建/去重线索 | 不开放旧宽权限 createLead 回退 | 需要设计函数级 INSERT、唯一约束、关联证据和撤销机制 | **关闭** |
| 关联具体学生 | 对单名学生建立待核实候选，不因联系人相同自动认定兄弟姐妹 | 必须核实具体学生关联和合法用途 | **关闭** |
| 商机、合同、收款或发课 | 员工没有由转换获得的权限 | 正式身份、合同、财务和教务另行联合验收 | **关闭** |

**建议 V3.2-17：**在不开放真实转换前，建立只可提交的「咨询转线索候选申请」，独立审核拒绝营销、重复咨询与跨员工归因，验证去重、幂等与双机构隔离；不接真实合同和教务。
