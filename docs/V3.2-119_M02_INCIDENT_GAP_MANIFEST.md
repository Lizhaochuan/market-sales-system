# V3.2-119｜M02 跨学生异常缺口汇总与可校验审计导出

## 基线

基于 V3.2-118 Draft PR #125，HEAD `1492d9ce0eed554410e0ceffff2cbcefc3a04063`。专属 GitHub Actions #43668130652 与聚合安全审查 #43668130594 均 `completed/success`。V3.2-118 可以在单个学生作用域对 HOLD、outbox 和负向回执做完整连续前缀检查，但不负责发现**同一异常中其他学生**的未扫描记录。

本期目标是防止“只导出某些学生，遗漏其他有 HOLD 的学生”以及“某学生最新扫描已经落后于 HOLD/消息实时数据”这两类虚假完整性结论。

## 管理单位与有界覆盖

- 学生始终是最小独立管理单位。`organization_id + incident_id` 是本次人工对账的汇总范围，**不是家庭默认实体**。即使将来同一家庭存在多个孩子，各学生自己的 HOLD、订单归因、业务证据和缺口仍需要分别检查。
- 不接受由浏览器或调用人自己提交的 student_id 子集。使用受限的 PostgreSQL 角色在一次 `SERIALIZABLE` 事务内，从 V115 HOLD head 表枚举该机构/异常的**全部存在 HOLD 的学生**，按 UUID 稳定排序。
- 本阶段为了审查上界，每个异常最多扫描 8 个模拟学生，每人至多 64 条 HOLD，单人最多 128 条 V118 扫描审计事件。**超过上限立即 fail closed，不截断列表**。没有任何 HOLD 学生时仍拒绝声称完成覆盖；不支持外部系统中尚未被本地 HOLD 接收的真实学生发现。
- 针对每个已发现学生，重算最新 V115 完整历史链、V116 outbox 和负向回执，核对 V118 学生扫描事件的完整链、head 水位和快照。如果没有 V118 扫描，则是 `UNSCANNED_HOLD_STUDENT`；历史扫描与当前来源数据有差异，则是 `STALE_TEST_SCAN`；一致时仅是 `CURRENT_TEST_SCAN`。**这些都不是现实业务中的“审核通过”**。

## 导出与数据安全

新模块 `src/cross-module-incident-gap-manifest.mjs` 导出 `buildIsolatedIncidentGapManifest`、`verifyIsolatedIncidentGapExport` 以及 `createIsolatedIncidentGapAudit`。

每条可复验清单包括机构和异常测试 UUID、按 student_id 排序的学生记录、每人 `checked_through`、`outbox_prefix`、`negative_receipt_prefix`、`scan_status`、来源快照 digest、每个未解决的 `hold_sequence`/原因/原 HOLD 摘要/消息摘要。还提供学生总数、HOLD 事件总数、未扫描人数、过期扫描人数及缺口总数。所有原始订单、收付款、SaleEvent、课时、赔付/补偿原件均**不包含于清单**。

`exportLatest` 仅导出本期提交成功的不可改写审计事件及清单，附两个 SHA-256 值：`manifest_sha256`、`audit_event_sha256`。独立校验函数核对 JSON 结构、计数一致性、缺项合法性、清单摘要和审计事件摘要及其相互引用。**SHA-256 只是本地字节一致性证明**，没有真实签署组织、硬件信任根、外部不可篡改存档或 WORM 保全；不可把它当成现实证据的真实性保证。

即使清单中 `unresolved_gap_count=0`、`coverage_status=CURRENT_FIXTURE_SCANS_STILL_NOT_REAL_APPROVAL`，所有返回依然是 `hold_active=true`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`。

## 临时数据库、事务与不可改写历史

- `tests/fixtures/v3-2-119-m02-incident-gap-manifest.sql` 在临时 `v106_isolated` 测试库创建 `fixture_incident_gap_manifest_events` 和 `fixture_incident_gap_manifest_heads`。事件表仅允许测试受限角色 SELECT/INSERT，head 的审计序号和已枚举学生数不得下降，`hold_active` 有 `CHECK(hold_active IS TRUE)` 且不可由受限角色更新。两表启用 `FORCE RLS`，测试机构 A 与 B 相互隔离。
- `tests/helpers/v3-2-119-m02-postgres-incident-gap-manifest.mjs` 在单笔 PostgreSQL `SERIALIZABLE` 事务内枚举该异常下所有 HOLD 学生、逐人读取来源、计算清单并将审计事件与 head 原子写入。保存时使用 source snapshot digest 去重；提交后再从新的独立只读快照检查来源是否变化。如果出现新增学生、补发消息、旧扫描过期等竞态，返回 `BLOCKED_INCIDENT_SOURCE_CHANGED_AFTER_COMMIT`，已提交审计事件作为历史事实保留。
- `scripts/v3-2-119-setup-incident-gap-manifest.mjs` 只允许 `V106_ISOLATED_PG=YES_TEST_ONLY` 并验证数据库为 `v106_isolated`。没有生产迁移 039，不进入生产 CRM 入口，不触发外部网络消息。
- `tests/integration/v3-2-119-m02-incident-gap-manifest.test.mjs` 验证真实一次性 PostgreSQL 中的人员覆盖、SHA-256 导出、时效、不可改写、并发和机构权限。

## 用例与范围

新增 20 组 MAN-01—MAN-20：

| 范围 | 检查 |
|---|---|
| MAN-01—05 | SQL 自行发现全部 HOLD 学生，部分学生未扫描、过期扫描、完整负向回执不能放行，学生 B 的完整状态不得掩盖学生 A 的缺口 |
| MAN-06—09 | 可重复导出、篡改 checksum 阻断、同快照重放拒绝、新 HOLD 学生加入后旧审计保留 |
| MAN-10—14 | 超过 8 人时拒绝截断、无学生时拒绝、SQL 提交前回滚、提交后结果丢失、提交后出现新学生 |
| MAN-15—20 | 独立并发写入、跨机构读写隔离、V118 事件摘要篡改、数据库水位/事件最小权限、非法业务放行字段、负向回执过期后旧扫描失效 |

此外，专属 GitHub Actions 仍需运行 V118—106 的完整相关临时 PostgreSQL 回归、V105 外部准入门禁，以及 V82—99 的十八阶段安全回归。

## 正式验收仍未具备

真实六方负责人仍为 `UNASSIGNED`，16 项外部准入、R01—R10、六种独立真实业务权威、财务和教务实签、三方正式交接、企业 PostgreSQL、Chromium 和合同 UAT 均为未验证，正式合同 `proposed-unimplemented`。V115 HOLD、V116 outbox、V118 扫描和 V119 清单是不同的本地事务；外部系统仍可在最后一次读取后发生变更。CI 测试没有产生真实投递、真实组织任命或正式 UAT 记录。

PR 必须保持 Draft，不合并、不部署。原始订单、收付款、SaleEvent、课时、补偿和原学生归属不可原地覆盖；家庭仅在真实兄弟姐妹关系存在时按需关联。不修改 `edu-management-system`、生产数据库、CRM 入口或现有主 CRM 文档；市场销售技术说明继续独立维护。
