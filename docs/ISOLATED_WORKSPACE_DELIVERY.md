## 本次范围与完成定义

用户已确认按现有安全默认完成隔离版。采用现有 V3.0 的 M01—M14 功能范围，不再创建后续版本的模拟安全契约；使用现有 Draft PR #129，不新开 PR，不合并、不部署、不修改生产数据、不解除隔离。

完成分两层：可在虚构数据库中独立运行的内部操作应具备页面、持久化和测试；依赖真实排课、价格、到账、提成、权益或外部审批的操作保留草稿/意向或只读阻断状态。后者不是已经接入或验收的业务能力，不能把本隔离版称为生产全功能完成。

## 可实际操作的新增闭环

1. 使用演示账号创建学生和商机，进入“业务计划与任务”。学生始终独立，不因家庭关系共享权限或金额。
2. 创建跟进任务、修改版本、完成或取消；查看每个历史版本。原跟进页面登记的沟通可在工作台查看。
3. 保存试听申请期望时间；不会创建排课或写回 CRM。
4. 录入多个拟选课程、数量及拟议单价，保存报价草稿；编辑生成新历史版本。使用整数分计算总额，禁止浮点分、溢出和未知放行字段。
5. 从未到期的当前报价版本生成报名意向。意向固化报价快照；后续报价修改不会改写旧意向。没有生成正式订单、收款、SaleEvent 或教学权益。
6. 登记费用计划；只能表示待审批用途与金额，不认定已经支出。
7. 更新商机沟通阶段并填写原因。已结束商机不能直接重开；存在学生关联隔离案件时拒绝推进。
8. 启用“未跟进 N 天”规则，在登录期间自动或手工扫描本人商机。每个规则版本/商机状态最多生成一次本地任务，不向外部联系人发送消息。

## 本机启动（全新一次性数据库）

需要 Node 22+、PostgreSQL 16 和项目依赖。数据库必须是本机新建的 `ms_workspace_test` 或 `ms_test`；初始化会拒绝已有 `ms` schema，不会删除或重置数据库。现有 001—038 迁移不修改，不创建迁移 039。

```sh
npm install --ignore-scripts
export MS_STAGE=isolated-test
export DATABASE_URL='postgresql://YOUR_TEST_USER:YOUR_TEST_PASSWORD@127.0.0.1:5432/ms_workspace_test'
export MS_WORKSPACE_SETUP=YES_EMPTY_TEST_DATABASE
npm run setup:workspace
export MS_ENABLE_ISOLATED_WORKSPACE=1
export AUTH_HMAC_SECRET='replace-with-a-local-test-secret-at-least-32-characters'
export DEV_LOGIN_SECRET='replace-with-a-different-local-demo-passphrase-at-least-32-characters'
npm run start:isolated
```

访问 `http://127.0.0.1:3100`，选择虚构账号并输入自己设置的演示口令。新增入口只在显式启用时展示。启动前检查实际数据库名和 fixture 是否存在；新增表只在 `tests/fixtures/isolated-business-workspace.sql`，没有向原受限 LOGIN 扩大授权。此演示由一次性数据库管理员运行，不是生产最小权限部署方案。

关闭 `MS_ENABLE_ISOLATED_WORKSPACE` 即恢复原入口行为；已保存的虚构数据继续留在原一次性数据库，不自动删除。

## 固定人工依赖

BP-01—BP-07 按用户批准的安全默认执行：不开部分付款权益，不自动分配共付款，不承诺旧报价，不批准无明细折扣，退款提成待批，不开放跨校区权限，不导入真实资料或发送营销消息。

真实 CRM、价格与排课、财务到账与退款、KMS/HSM、独立 WORM/可信时间、外部业务证据和六方独立 UAT 均需真实负责人、测试环境及授权。它们保持未完成状态，不再转成新的模拟契约。这些条件具备前，M07—M10/M13 的正式业务执行不能自行补成“已验收”。

`EXT-001=UNVERIFIED`、`HOLD=true`、`release_eligible=false`、`merge_authorized=false`、`deploy_authorized=false`。隔离功能交付不代表允许合并、部署或解除隔离。
