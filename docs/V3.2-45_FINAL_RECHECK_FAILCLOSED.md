# V3.2-45｜身份最终核验故障下六路径拒绝泄漏回归

> 状态：隔离动态回归已提交，最新 HEAD CI 待验。本期仅使用虚构数据、受限测试数据库 LOGIN 与本机 UAT 只读 API。上游 V3.2-44 Draft PR #51 仍是 Draft，未合并或部署。

## 1. 安全问题

V3.2-44 为所有受保护的数据输出增加响应前的员工身份复核，降低撤销提交时已读取数据的泄漏风险。但如果复核请求碰到数据库断线、超时或内部错误，**不能因为首次身份验证曾经成功就继续发送 JSON 或 Markdown**。身份状态未确认应拒绝（fail closed）。

## 2. 实际增量

直接增强 `tests/security/uat-preview-api.test.mjs` 的既有隔离 E2E，而不是引入不带真实数据库的伪造测试。

通过测试专用的 `pg.Pool.connect()` 包装器，允许每个请求的**第一次** `ms.scoped_employee_identity_valid` 通过，并只在读取数据后的**第二次**核验中模拟 PostgreSQL `08006` 连接故障；验证服务器始终返回不包含原始数据的通用 HTTP `500`，同时 `Cache-Control: no-store, max-age=0`。模拟错误不会写入数据库，包装器在子测试结束后恢复。

| 路径 | 预期 |
|---|---|
| 机构来源清单 | 最终身份核验失败时不返回列表 |
| UAT 报告 JSON | 不返回报告 |
| UAT 报告 Markdown | 不导出报告 |
| 冻结状态 | 不返回冻结数据 |
| 历史差异 JSON | 不返回差异数据 |
| 历史差异 Markdown | 不导出历史 |

共覆盖六条此前新增末次身份复核的成功响应路径；每一条失败都应触发实际核验错误，无来源 ID、测试历史引用、错误堆栈或配置秘密出现在响应中。恢复模拟故障后，原授权用户仍可正常读取自己的虚构报告。原有撤销后 12 条并发请求和 V3.2-44 在途撤销竞态测试继续保持。

## 3. 不可夸大的验证边界

本期只演练**末次身份核验故障时安全拒绝**，不保证撤销与网络发送原子化，不代表任意在途请求均能取消；不测试真实身份提供者、生产财务/CRM 服务账号或正式业务 UAT。

- 学生是主要管理单位，家庭按需关联。
- 真正错绑且已有资金、订单或课时履约的案件始终 `hold_active`，原订单、SaleEvent、资金、消课历史不改写。
- `production_integration_allowed=false`，`execution_allowed=false`，`release_allowed=false`，`merge_authorized=false`，`deploy_authorized=false`。
- 两份外部系统 OpenAPI 均为 `proposed-unimplemented`；16 项真实准入和 R01—R10 尚未通过。
- 本期无 migration 039，不接真实外部服务，不合并、不部署、不修改 `edu-management-system`。

## 4. 验收

只有本 PR 最新 HEAD 完整 CI 完成且成功，才能说明**隔离测试**中的末次核验故障拒绝能力通过；CI 不能替代真实财务、教务、安全及销售三方的正式签署。
