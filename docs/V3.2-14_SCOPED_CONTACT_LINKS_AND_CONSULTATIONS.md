# V3.2-14｜学生—联系人待核实关联与真实咨询登记：原有入口的员工级最小权限迁移

**位置**：独立市场销售系统 `Lizhaochuan/market-sales-system`，基于 V3.2-13 草稿 PR #17。  
**状态**：仅可在 `MS_STAGE=isolated-test` 的本机虚构数据和 PostgreSQL 16 中演示；非正式生产版本，不合并、不部署。  
**基本原则**：**学生是主要管理单位；只有确实存在两个以上经核实同家庭学生才按需关联家庭。** 一名家长可以联系不同孩子，但不得自动把孩子合并成一个业务客户。

## 1. 本轮实际迁移的既有两个入口

此前 V3.2-13 已在严格员工模式下迁移原有两条客户新建路径：`POST /api/v1/students`、`POST /api/v1/contacts`。

现在新增迁移：

| 原工作台可见操作 | 原路径 | 本轮严格模式行为 |
|---|---|---|
| 将联系人关联至指定学生 | `POST /api/v1/students/{studentId}/contacts` | **只能操作本人当前负责的这位学生和本人亲自登记的联系人**，关系只能标为“待核实”，不能直接标记“已核实/主要监护人” |
| 保存一次实际咨询 | `POST /api/v1/contact-events` | **只为本人亲自登记的联系人登记真实发生的一次咨询**；业务只能填写联系人、咨询方式、实际发生时间；不得自动形成多名学生的咨询、线索或商机 |

严格模式中，原中文工作台的“关联至该学生”与“保存本次咨询”按钮继续使用**原来的 HTTP 路径**，但后端实际写入必须通过该员工专用、没有原始客户表写权限的数据库账号调用受保护函数。没有账号、账号与外部签名身份不一致、联系人非本人登记或学生非本人当前负责人，一律直接拒绝，不能回退机构级写入。

### 为什么不能直接用“同一家长”判断家庭或客户归属？

示例：同一位家长咨询学生甲和学生乙。两人可能确实是兄弟姐妹，也可能是重新组建家庭、监护关系待核实或联系人复用。实际登记时：

- 甲是一条独立学生客户档案；乙也是一条独立档案。双方即使关联相同联系人，也不会自动创建 `family_groups`、新增 `family_memberships` 或把销售负责人改成同一个人。
- 每一条“学生—联系人关系”都独立保留**待核实**状态。确认监护和确认兄弟姐妹关系需要更严格的独立核实流程，不能通过普通销售创建入口绕过。
- 家长当天有**一次真实咨询**，只能新增一个 `contact_events` 事件，不能因为这位家长关联两位学生而自动算两次咨询、两份线索、两笔成交或双倍奖金。
- 销售 B 获得了学生甲的具体**查看共享**，至多在原有规则允许时看到甲关联的联系人；仍不能把该联系人关联至 B 自己负责的另一名学生，也不能读取或修改销售 A 原先记录的咨询。
- 如果联系人最初由另一位销售创建，目前严格模式**保守拒绝**自动关联/登记。现实中的交接或代办需要后续明确授权审批，不推断联系人“被看到”就意味着“归本人所有”。

## 2. 这次真正增加的数据库安全能力

### 017 号迁移

`db/migrations/017_scoped_contact_links_consultations.sql` 定义：

- `ms.link_scoped_student_contact(student,contact,relation,key)`：函数只接受四种中文关系类型，数据库检查**当前有效员工账号、学生现负责人、联系人最初登记员工、机构一致、原关系不重复**。写入时固定 `verification_state='unverified'`、`is_primary=false`、`verified_at=NULL`，**没有确认家庭关系的入口**。
- `ms.create_scoped_contact_consultation(contact,type,occurred,key)`：函数只接受四种咨询方式；真实发生时间不得早于 365 天前或晚于当前 5 分钟。数据库核对当前员工是否为这个联系人的原登记人，将 `recorded_by` 固定为当前数据库员工；不给客户端指定他人登记人、营销活动/渠道、原始个人凭据等高级字段。
- 二者都由`ms_scoped_lowrisk_writer` 仅获 EXECUTE 权限，普通员工专属数据库账号不得 SELECT/INSERT 原始学生、联系人、家庭、商机、财务、审计表。受保护函数在员工所在数据库会话中写入实际业务记录、中文审计和防重复收据。
- **沿用 016 号迁移的同一个员工防重复收据命名空间**，而不是另建一张重复收据表。同一个员工不能把一次咨询的防重复编号再拿去新建学生或联系人；并发相同操作会被事务锁串行化，相同内容重试返回相同结果，不重复创建咨询。
- 审计只记录中文业务事实（哪个学生、哪个联系人的什么待核实关系、一次咨询的方式与时间），不在员工界面显示原始 SQL、个人核验资料和内部证据代码。

### 严格模式服务安全

`src/scoped-legacy-write-adapter.mjs` 新接入 `linkContact` 和 `createEvent`，并与既有客户创建共用同一条拒绝回退的安全路径。服务器对登录身份要求是受信任的外部 RS256 测试签名 + 已审批员工身份绑定，最终数据库权威身份来自 PostgreSQL `session_user` 和管理员建立的员工映射。令牌自称“主管”、自报其他员工或其他机构不产生额外权限。

`src/scoped-lowrisk-write-api.mjs` 增加启动和每次使用连接时的权限检查，两个新函数必须真实可 EXECUTE，同时仍禁止原始业务表写权限。严格模式保留对尚未迁移的创建线索、销售商机、家庭核实审批及正式成交/收款等接口的**服务端禁止**，不是仅在界面隐藏。

## 3. 中文工作台的变化

原 `web/index.html`、`web/app.js` 保留旧虚构演示模式，另在**严格员工身份测试模式**中开放：

- “家长与联系人”页面：登记联系人，或将本人登记的联系人关联至本人负责的指定学生；显示关系仍为“待核实”，不会暗示学生已被合并为家庭。
- “咨询与线索”页面：仅显示“记录真实咨询”表单和“我的实际咨询记录”，按每条真实事件展示一次；**创建线索及线索—学生关联操作在严格模式下关闭**。
- 学生、联系人、咨询的列表都来自员工专属只读数据库视图，不包含他人的完整客户信息、身份证明、儿童年级或预测成交金额。
- 页面仍然使用本机测试管理员提供的 RSA 测试凭据（内存保存、不落本地存储），**并非正式企业身份登录**；刷新或退出须重新获取测试凭据。

## 4. 自动化验收必须证明

| 编号 | 测试内容 | 正确结果 |
|---|---|---|
| REL-01 | 销售 A 将自己的联系人关联至自己的学生甲 | 仅建立**甲这一名学生**的待核实关联，未核实、非主要监护人 |
| REL-02 | 同一联系人分别关联至甲、乙两名学生 | 两条独立学生关系，不产生家庭单位，双方仍独立管理 |

| REL-04 | 未审批身份、失效身份、跨员工数据库连接、机构错误 | 403，不回退旧机构级 SQL |

| UI-01 | Chromium 使用原中文工作台的原按钮、正式严格员工模式 | 从联系人创建 → 关联学生（待核实）→ 登记一次咨询，数据库结果相符 |
| REG-01 | PostgreSQL 001—017、V3.1 合同、双机构 RLS、安全、原有中文页面和原授权审批 | 全部通过，且 GitHub Actions SUCCESS 的 SHA 与草稿 PR 当前 HEAD 一致 |

## 5. 当前仍未完成、不可上线

1. **仅隔离虚构测试环境**，不允许导入真实儿童资料或测试真实付款。正式 IdP、OIDC 授权码+PKCE、MFA、生产会话/令牌轮换、实际 HR 账号生命周期均未完成。
2. **联系人跨销售交接**、监护证明法律审核、二次核实、纠纷与授权撤销的完整业务政策尚未定稿；本轮仅开放员工本人登记的联系人和本人负责的学生之间的待核实关联。
3. **原销售线索、销售商机、实际成交、退款、预算、合同和 CRM 教务课时写入**仍未迁移，严格模式必须拒绝而非宽权限回退。
4. 原主业务数据库连接仍参与已审批身份解析和角色读取；**身份目录查询的最终 SQL 最小权限迁移**未完成，留在后续单独阶段，不可宣称已完全去高权化。
5. 当前页面新增了实际 Chromium 自动化，**仍不等于真人员工、真实设备、跨系统集成或生产环境的完整验收**。
6. 业务归属、咨询去重之外的跨时间同一实际事件判定、渠道归因、员工代办咨询、渠道证明和真实销售绩效仍需要独立审查。

**独立交付原则**：只修改 `Lizhaochuan/market-sales-system`，不改 `Lizhaochuan/edu-management-system` 代码、数据库与任何既有 CRM 技术文档。所有上游和本轮 PR 继续 Draft，不合并、不上线。只有两套系统真正实现集成并通过权限、财务、自动化与真人联合验收后，才合并两边的技术资料。

**V3.2-15 推荐范围**：对已批准外部员工身份到机构/角色的查询路径进行受限数据库目录化；进一步实现“客户—联系人跨员工授权变更/转交”的独立审批，随后才逐项评估销售线索登记的低风险迁移。
