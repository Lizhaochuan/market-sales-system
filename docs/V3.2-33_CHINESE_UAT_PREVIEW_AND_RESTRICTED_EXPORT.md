## 二、可见内容和安全边界

界面以中文展示：
- 仅本机构受限账号有权看到的虚构财务或 CRM 来源申请。
- 对应来源的 12 项检查：销售 3 项 + 财务/教务 4 项 + 安全 5 项。
- 每项检查的任务名称、责任人、所需证据、验收动作和**必须拒绝的条件**。
- 已登记的缺失证据事件数量。**缺失事件为 0 不表示已通过。**
- 始终醒目的“真实联调暂未授权”“禁止联调”和“不得修改资金/订单/课时及解除隔离”。
- 在身份与机构权限通过后，可预览、生成并导出只包含检查文本的 Markdown；无真实合同、银行数据、课时数据或儿童姓名。

**不开发**：真实 API 连接、财务/CRM 密钥、自动通知、实际生产审批、资金冲正、订单学生改绑、课包新建/转移、课时修改、`hold_active` 解除按钮或函数。

## 三、员工身份与权限

测试界面必须通过临时 RS256 签名令牌，服务端对签发者、受众、签名和有效期进行验证，再用 `ms.scoped_employee_identity_valid(issuer,subject)` 对比当前专用 PostgreSQL LOGIN 的**已独立批准且未撤销的真实数据库员工绑定**。

- 不采信令牌中自报的 `org_id`、`role` 或 `staff_id`；机构来自受保护的 `database_principal_staff` 映射。
- 浏览器凭据只保存在 JS 运行内存，输入框提交后清空；不写 localStorage、sessionStorage、Cookie 或 URL。
- 来源列表 `GET /api/v1/uat-preview/requests`、待办报告 `GET /api/v1/uat-preview/reports/:uuid`、Markdown `GET /api/v1/uat-preview/reports/:uuid/markdown` 全部受相同的身份及机构校验；导出不是跳过鉴权的公开下载。
- API 仅本机 IP 可访问，固定静态文件白名单、严格 CSP、`no-store`、禁止查询参数、无 POST/PUT/PATCH/DELETE 业务路由。
- 两个机构使用独立专用只读数据库 LOGIN；不能直接 SELECT 原业务表或执行原业务写函数。
- 页面所有动态内容以 `textContent` 展示，不拼接 HTML，不渲染来自外部系统的可执行脚本。

## 四、人工 UAT 操作说明（本地虚构测试）

1. 本地测试管理员配置隔离 PostgreSQL 001—036、仅有 `ms_uat_preview_reader` 的专用 LOGIN，以及预先批准绑定的测试人员 RS256 公钥和签名身份。本期不提供生产账号自动创建。
2. 在本地启动只读 UAT 服务，打开 `/uat`，使用测试管理员签发的临时令牌；失败或撤销身份应显示拒绝，而不是展示页面。
3. 核对来源申请下拉框只列出当前机构、当前职责有权看的来源。不允许通过直接拼接另一机构来源 UUID 获取报告。
4. 点击“查看待办报告”，核实恰好 12 项检查、正确的销售/领域/信息安全责任及“禁止联调”文案。
5. 点击“导出本次脱敏 Markdown”，检查文件包含全部检查与阻断声明、不含任何员工身份令牌、真实学生、银行卡信息；导出前服务器必须**再次**验证当前员工与机构。
6. 测试来源变更/身份撤销/跨机构访问后，原令牌下的下一次读取和下载必须拒绝；之前下载的文件只作为离线待办参考，不可作为后续实际授权证据。
7. 以手机窄屏测试表格水平滚动和页面外溢，确保按钮清晰可见，未在浏览器持久化身份。
8. 运行完整 PostgreSQL、Node、Chromium 和 V3.1 回归；任何失败均不标记新页面通过。

## 五、保持的核心业务规则

学生是主要管理单位，家庭按需关联；不得因为同一联系人或家庭就合并不同学生的合同、收款或课时。已经发生订单/收款/履约的真实错误关联案件必须保持 `hold_active`，跨部门授权与真实补偿执行另行验收。模拟测试的 CI 全绿不能替代真正财务、教务和信息安全责任人的签字，也不能更改 `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`。
