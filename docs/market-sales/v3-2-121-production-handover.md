## 执行边界

- 此处“责任人”是**待正式指派的责任岗位/部门**，而非已确认的具体自然人。没有代替部门负责人签署，没有假设完成日期。
- 提交的证据须记录真实来源、版本、采集时间、可复核的摘要和受控存储位置；应先脱敏，不应把真实学生、订单、资金、课消或认证秘密直接提交公开代码库。
- 每项的责任部门负责准备证据，独立复核部门负责验证来源和完整性。无论是否完成交接，此清单不能触发生产解隔、合并或部署。
- 完成某项的先决条件包括：所有依赖项的**真实外部独立验收**已存在；证据包完整；复核人与准备者相互独立；记录真实签署和版本锚点。CI 全绿不能满足这些条件。

## 交接包最小要求

1. **申请**：注明 `EXT-xxx`、当前迭代版本、机构及业务事故范围、负责部门与拟定独立复核部门。
2. **证据**：逐一回应清单中的 `EXT-xxx-E1/E2` 等必备证据，附真实内部证据引用、可信内容摘要及脱敏方式。证据丢失、口头确认、模拟脚本或仅 CI 输出均不应被视为生产验收。
3. **验收**：复核方逐条执行该任务的 `acceptance_checks`，记录未通过项与需重新收集的证据。不得复用过期的调查版本或此前的审批。
4. **流转**：前置事项、证据收集、独立复核、六部门签署和部署变更审批需要分别有外部真实记录。此 Draft 仓库的 JSON 不能写入真实签署结果。
5. **阻断**：发现任何缺失、审批职责冲突、无法验证来源或历史不一致，继续保留销售、财务、教务 HOLD 和安全隔离；不修改原始订单、资金或履约记录。
