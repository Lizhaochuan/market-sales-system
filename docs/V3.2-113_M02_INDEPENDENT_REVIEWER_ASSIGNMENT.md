# V3.2-113｜M02 独立审核人指派与六类证据完整性门禁

## 已核验上游与目标

基于 V3.2-112 Draft PR #119，HEAD `b540e11d1d05f87da2a4ca72601b8ea634a220f4`；真实一次性 CI PostgreSQL #43664482100 与十八阶段聚合 #43664482069 均 `completed/success`。V3.2-112 建立的是**未核实材料接收**，不是责任人或证据的正式认证。

本阶段把隔离的六类材料完整性检查、独立**模拟**审核人签名与不可改写的审核指派记录结合；所有操作仍 CI-only。审核岗位可以在测试环境中分派，但真实负责人继续 **UNASSIGNED**，真实审核身份、财务和教务签字权均**未确认**。

## 技术实现与责任边界

新增 `src/cross-module-independent-reviewer-assignment.mjs`。只有所有条件满足时才记录一个模拟待确认审核任务：

1. 从 V3.2-112 的隔离 PostgreSQL 事件账本逐条读取、核对事件摘要链、最后一条 head 摘要、六种岗位（销售、财务、教务、身份安全、集成、数据库审计）的最新提交事件。
2. 回查各提交的**未认证元数据**，用提交时 SHA-256 与当前元数据比对。要求没有失效、没有过期、学生主键一致，按需使用的家庭主键、历史数据摘要与自述 V3.2-110 负向通知摘要一致。没有通知摘要、数据不足、版本或摘要不一致必须拒绝。
3. 测试审核人不能等于这六个岗位中的任何候选负责人或提交人；要求不同岗位的候选负责人标识不同、提交人标识不同。该规则只验证测试中的字符串分离，不能用来代替真实人事系统身份验证。
4. 使用单独固定的**测试用 Ed25519 公钥**验证拟派审核人模拟身份状态、权限版本、有效期、机构与学生范围；模拟来源版本及撤权状态也要分别前后读取。**来源角色撤权接口是未签名的测试 fixture**，不能视为真实 IAM、HR 或业务系统审核。
5. 在单独一次性 PostgreSQL 16 中通过 `SERIALIZABLE`、租户强制 RLS 和机构/异常/学生复合主键，仅追加一条 `PENDING_REAL_OWNER_CONFIRMATION` 的审核指派审计记录。记录创建成功不表示真实责任人接受任务，不开放业务系统审批按钮。
6. 提交后回读 SQL 记录、V3.2-112 最新 intake head、审核人状态与来源撤权状态。后续证据变更、人员撤权或 SQL 状态不一致，则**拒绝将模拟指派视为当前状态**，但已追加的待确认审计记录仍被保留；没有自动删除和覆盖。

记录文件：`tests/fixtures/v3-2-113-m02-reviewer-assignment.sql`、`tests/helpers/v3-2-113-m02-postgres-reviewer-assignments.mjs`、`scripts/v3-2-113-setup-reviewer-assignments.mjs`。SQL 表只允许受限测试角色 SELECT/INSERT，不允许 UPDATE/DELETE，不能访问业务付款表，且绝非生产迁移 039。

成功分派的**唯一**结论是 `BLOCKED_FIXTURE_REVIEW_ASSIGNED_NO_REAL_AUTHORITY`，`fixture_review_assignment_recorded=true`，`review_status=PENDING_REAL_OWNER_CONFIRMATION`。永远同时保持 `external_reviewer_appointed=false`、`external_owner_verified=false`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。任何测试模拟签名或 SQL 记录都不能使真实交接变成已批准。

## 缺失的真实准入条件

**尚没有真实人员的工作任命，零项真实证据被独立验证。** V3.2-112 的原证据摘要只是提交方自述；V3.2-110 通知摘要是可自填的元数据值；三方来源没有真实可信签名、真实账簿和不可抵赖履约凭证；V3.2-113 的审核人公钥来自临时测试私钥，不具备现实中的组织任命权限。即便核对六份材料的相同 SHA-256，也不能保证历史订单、收款、SaleEvent、课时或补偿内容属实。

另外，来源可能在本次最后一次身份读取后才发生撤销。隔离 SQL 审核指派也不能将来源与最终交易原子锁定；早已保存的待确认审核记录可能随着新撤权而失去当前性。没有真实三方确认、不可抵赖回执或生产交接原子性，不开放任何资金、教务、纠错、补偿或解除隔离权限。

16 项外部准入、R01—R10、六种独立财务/教务/对账/交接权威、企业 PostgreSQL、Chromium、正式合同和三方 UAT 均仍未验证。正式合同保持 `proposed-unimplemented`，所有真实负责岗位仍为 UNASSIGNED。保留学生为首要管理单位，家庭只在确实有兄弟姐妹时按需关联；原始订单、收付款、SaleEvent、课时和补偿历史一律不可覆盖。

保持 Draft，不合并、不部署，不修改 `edu-management-system`、生产入口或数据库，不新增 039，市场销售说明文档独立维护。

## V3.2-114 建议

围绕真实证据来源、审核人回避与替换审计设计隔离合同：明确可由什么外部管理方签署审核人任命，何种材料足以证明财务/教务独立来源，如何在撤权、调岗、签名失效时作出只追加的审核指派撤销记录。**在真实外部身份尚未取得前，不允许将本阶段模拟审核分派升级为现实中的业务审批。**
