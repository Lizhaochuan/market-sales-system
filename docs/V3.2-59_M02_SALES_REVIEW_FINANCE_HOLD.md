# V3.2-59｜M02 市场活动销售审核申请、独立审批与财务强制隔离

> 上游 Draft PR #65（V3.2-58）最新 HEAD `2285391d49c08e14bcfcf1d4e47542e9a48e67cf`、GitHub Actions #43598948163 `completed/success`。本期所有新表、SQL 函数及界面均只用于一次性 CI PostgreSQL 中的虚构员工和活动，不接入真实财务。

## 1. 责任边界

本阶段将三项权力分开，而不是把“主管同意计划”误当成“财务批准预算”。

| 行为 | 执行主体 | 结果 | 不产生的权限 |
|---|---|---|---|
| 提交活动草稿的销售审核请求 | 同机构、身份仍有效的活动原负责人 | `pending_sales`；绑定当前活动版本、预算、名称、起止时间、渠道清单快照 | 不改变活动状态，不产生实际成本 |
| 批准/驳回销售审核 | **另一位**当前有效的本机构销售主管；数据库重新核验角色和身份 | 批准为 `sales_approved_pending_finance`，驳回为 `sales_rejected` | 销售批准并不授予财务预算额度 |
| 财务预算复核与实际支出 | 尚无经真实权威来源核准的财务审签角色或接口 | **保持未实现、不可执行** | 不允许直接造一个“财务已批准”状态或在模拟主管名下替代财务签字 |

关键原则：**活动表 `ms.marketing_campaigns.status` 在全部步骤中始终为 `draft`**。单独的销售审核状态并不等同营销活动已启动。申请人不能自行批准；销售主管不能改变他人的原草稿或直接创建营销费用。

## 2. 实现的实际数据库和 HTTP 入口

- `tests/sql/create_v3_2_59_campaign_sales_review_finance_hold.sql`：创建 CI-only `ms.isolated_campaign_sales_reviews` 记录审核申请、活动版本、完整计划快照、理由、证据引用、提交人与销售审批人、不可重用编号。对每个活动只允许一条 `pending_sales` 或 `sales_approved_pending_finance` 的生效请求；已驳回的历史保留且允许负责人更改后重新提交。
- `ms.request_isolated_campaign_sales_review`：必须是草稿原负责人，申请版本与数据库一致，不可重复占用同一活动的在途审核；追加 `CAMPAIGN_SALES_REVIEW_REQUESTED` 审计事件。相同防重复号同内容返回原请求，同号不同内容返回 409。
- `ms.decide_isolated_campaign_sales_review`：独立销售主管必须与申请人不同、当前数据库角色未撤销，受同机构和签名员工 LOGIN 约束；审批时再次核对草稿版本、预算、渠道、负责人和时间快照。成功则追加 `CAMPAIGN_SALES_APPROVED_FINANCE_HOLD` 或 `CAMPAIGN_SALES_REJECTED`，不修改 `marketing_campaigns` 的状态或预算。
- `ms.scoped_isolated_campaign_sales_reviews` 安全屏障只读视图：普通员工仅见自己的记录；主管可见本机构其他员工**当前待审核**申请和其自己已审核的记录。只返回 ID、版本、状态、时间与是否可审，不公开审批依据、原始预算快照或申请理由。
- 修改现有 V3.2-58 草稿版本函数：一旦进入 `pending_sales` 或 `sales_approved_pending_finance`，禁止再修改活动名称、预算或渠道，避免通过编辑替换已经审核的内容。驳回保留旧审计后可以修改并重新提交。

HTTP 全部要求经批准的严格签名员工身份、专属低权限 PostgreSQL LOGIN 和 `Idempotency-Key`；旧演示登录与宽权限租户连接禁止调用。

`GET /api/v1/marketing-campaigns/sales-reviews`：返回最多 100 条受限审核记录，超限拒绝而非静默截断。

`POST /api/v1/marketing-campaigns/drafts/{campaign_id}/sales-review-requests`：负责人提交申请和当前版本。

`POST /api/v1/marketing-campaigns/sales-reviews/{review_id}/decision`：独立销售主管批准或驳回。

**没有财务批准 POST、预算实际执行 POST、活动发布 POST、成本费用 INSERT 许可。**

## 3. 中文页面及失败处理

“市场活动”页新增“提交市场活动销售审核”“销售主管独立审核”“活动销售审核与财务待确认状态”。员工只能选择本人草稿；主管只能审批具有 `can_sales_review=true` 的他人请求；销售批准显示“等待财务确认”，**不显示“预算已批准”**。申请提交后冻结版本修改。列表读取失败或签名过期，前端清空旧待办并关闭修改与审批；退出登录清空申请列表、选择项和 DOM。服务器仍独立复核，页面不成为权限来源。
