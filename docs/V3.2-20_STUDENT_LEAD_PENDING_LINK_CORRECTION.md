# V3.2-20｜正式线索关联指定学生、作废、更正与不可改写审计

**适用范围：**仅独立市场销售仓库中的虚构 PostgreSQL 16、员工专属数据库账号隔离测试；依赖未合并 Draft PR #23。此文档单独保存，不与现有教培 CRM 技术文档融合；不合并、不部署、不接真实身份、收款、合同、课时或教务。

## 一、业务规则（按单名学生，不按家庭）

- 单名学生是主要管理单位。一个联系人可能认识多名学生，但不会自动形成家庭或兄弟姐妹关系。正式线索来自单次已审核真实咨询，不能按关联学生数量拆成多条线索。
- 本人已经执行成功的 **V3.2-19 正式线索**，且本人仍是该线索负责人时，只能对**自己当前负责的一名具体学生**提交一次“待核实关联”申请。禁止直接依据同一联系电话、姓名、联系人或家庭猜测其他学生，跨机构、跨负责人学生都拒绝。
- 申请阶段只建申请记录，不写 `ms.lead_students`。本机构有效且非申请人的主管独立批准后，才为这名学生写一条 `confirmation_state='pending_review'`、`confirmed_by=NULL` 的记录。此状态是**待核实，而不是已确认的学生/监护人关系**。没有确认家庭成员，没有授予学生档案、财务、教务或其他学生访问权。
- 与同一线索另一名学生的关联必须单独申请、单独审核。重复申请同一线索—学生键拒绝；撤销、完整核实、监护人证明和跨销售学生转交均需后续独立设计。

## 二、线索更正与作废

- 本人仅能提出 `correct_note`（补充更正**业务说明**）或 `invalidate`（申请作废）的调整。不能修改原咨询来源、原记录员工、联系人/线索负责人、真实销售业绩、订单、合同、财务、课时或学生负责人。
- 同一线索同时只有一项待决调整。更正说明经本机构有效独立主管批准，追加不可改写的更正效果记录，并通过受限视图显示最新说明。**不会覆盖原始线索字段。**
- 作废申请批准前在数据库事务中重新锁定并检查线索仍属原员工、状态仍可调整且不存在任何以该线索为来源的商机。通过后只将 `lead_state` 设为 `invalid`，追加不可更改审核及效果记录、中文审计。原线索、来源事件、执行台账及已有待核实学生历史关联一律保留，不删除、不重新分配、不逆向修改真实合同或资金。
- 如果已经有商机（即使尚未成交），本版禁止直接作废，必须走未来跨模块审查机制。已作废、已关闭或已转化的线索不能再新增关联或说明更正；不能借作废申请撤销 V3.2-19 的原始最终转换批准历史。
- 审核人不能与申请人相同。被拒绝的申请不可直接重写；需另行提出新申请而不是修改已归档决定。

## 三、数据库最小权限

- 新迁移 `024_lead_student_pending_links_and_adjustments.sql` 建立申请表、不可变决定表和不可变调整效果表；新增仅最小列的员工只读投影。
- 只能由受保护 `SESSION_USER` 映射出机构、员工身份。四个员工专用 `SECURITY DEFINER` 函数：`request_lead_student_association`、`decide_lead_student_association`、`request_lead_adjustment`、`decide_lead_adjustment`。
- 员工 LOGIN 没有直接 `SELECT/INSERT/UPDATE/DELETE` 原始学生关联、线索、申请、决定、财务或审计表权限；不得调用旧宽范围 `linkLead` 或修改正式订单。
- 通过行锁及 UNIQUE 约束保证请求、决定和每个线索—学生对应关系不会重复；提交、决定、待核实学生关联/作废、更正效果和中文审计在同一数据库事务。防重复编号有效且相同内容重放返回先前结果，不同内容冲突拒绝。

## 四、接口与中文界面

| 接口 | 职责 |
|---|---|
| `GET /api/v1/lead-student-associations` | 本人申请或主管待审的指定学生最小记录 |
| `POST /api/v1/lead-student-associations` | 本人提交线索—单学生待核实关联申请 |
| `POST /api/v1/lead-student-associations/:id/decision` | 独立主管允许登记待核实或驳回 |
| `GET /api/v1/lead-adjustments` | 本人申请或主管待审的更正/作废清单 |
| `GET /api/v1/lead-correction-notes` | 本人线索最新已批准的补充说明 |
| `POST /api/v1/lead-adjustments` | 本人提出作废或业务说明更正 |
| `POST /api/v1/lead-adjustments/:id/decision` | 独立主管审批并追加不可变效果 |

中文工作台明确标示“待核实不是已确认”“业务说明更正不等于改变原始咨询”以及“线索作废需要无下游商机”。不显示数据库源码、SQL、内部权限表达式或金融原始字段。
