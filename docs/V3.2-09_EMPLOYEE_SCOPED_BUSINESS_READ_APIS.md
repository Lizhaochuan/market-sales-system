# V3.2-09｜员工专属数据库权限落地：市场销售五类只读接口

**仓库**：`Lizhaochuan/market-sales-system`。  
**基础版本**：V3.2-08 PR #12（该 PR 与更早的 PR #4–#11 均仍待审、未进入主分支）。  
**环境**：PostgreSQL 16 + Node.js 22 + 本机虚构人员、学生和商业数据。  
**判定边界**：这是**真正可调用的五类只读 HTTP 接口**，但**不是现有所有销售 API 已完成迁移，也不是正式身份/支付/CRM 生产上线**。

## 1. 核心业务目标

原有销售系统已经使用学生作为主要管理单位；只有兄弟姐妹真实属于同一家庭时才在核实后建立家庭联系，不因为共享家长而合并学生、商机或成交归因。跨销售查看一位学生必须有具体的访问授权。

此前 V3.2-08 在数据库中验证了员工专属学生列表，但尚未从独立 HTTP 服务真正读取联系人、咨询记录、销售线索和商机。V3.2-09 将这一最小授权模式扩展为可调用的真实业务查询接口。

**设计原则**：对员工的业务读取权限，不能只通过前端隐藏菜单或查询条件来保护；必须使用数据库登录身份受保护的员工映射，加上数据库只读视图，验证外部身份仍获批准。

## 2. 五个实际可运行的员工专属查询接口

| 本机接口 | 返回的业务信息 | 不能看见或修改的内容 |
|---|---|---|
| `GET /api/v1/scoped/students` | 本人负责或被具体共享的学生编号、姓名、机构编号 | 年级、学校、家庭证明、课程/付款 |
| `GET /api/v1/scoped/contacts` | 本人创建、本人线索关联或本人可见学生关联的家长/联系人名称、是否拒绝联系 | 手机号、微信号、原始密文、其他销售无授权家长 |
| `GET /api/v1/scoped/contact-events` | 本人登记或可见联系人关联的咨询类型与时间 | 来源证明全文、他人无关咨询、任何修改 |
| `GET /api/v1/scoped/leads` | **本人负责**的线索编号、状态及创建时间 | 其他销售线索、原始证据、自动归因与成交 |
| `GET /api/v1/scoped/opportunities` | **本人负责且对应学生可见**的商机编号、学生编号、阶段与状态 | 其他销售商机、预测金额、合同、正式订单和收款 |

只允许 GET 请求，每类最多返回 100 条；未知路径、POST/PUT/DELETE 和带有任意查询参数的请求均被拒绝。查询不接受客户端指定组织编号、员工编号或 SQL 表名。

**为什么授权共享学生后仍看不到其他销售的线索和商机？** 学生查看授权与线索负责人、商机负责人是不同的业务权限。共享学生只应让员工获得必要的学生及其关联联系资料，**不能隐含转移另一位销售的线索所有权或商机业绩归属**。

## 3. SQL 权限实际方案

### 013 号迁移

`db/migrations/013_employee_scoped_read_business_views.sql` 包含：

- `ms.current_scoped_staff_id()`：以受数据库管理员保护的 `session_user` → 员工与机构映射确认登录员工，确认员工与机构仍启用；员工不能靠设置自定义 PostgreSQL 参数伪造身份。
- `ms.scoped_employee_identity_valid(issuer,subject)`：在**同一读事务**内核对外部已验签主体对应当前数据库员工、原独立审批记录、未撤销身份绑定和有效机构。身份未批准、未绑定、员工停用或数据库账号不匹配时拒绝。
- `ms.scoped_contacts_directory`：联系人限定在员工直接创建、员工所负责线索关联或员工有权限的学生关联范围。
- `ms.scoped_contact_events_directory`：仅本人登记或员工可查看联系人相关咨询，隐藏原始证据。
- `ms.scoped_leads_directory`：仅本人负责的线索，不因学生共享而授予他人线索访问权。
- `ms.scoped_opportunities_directory`：商机负责人必须为本人，且学生本身已获员工授权；不返回预测金额。

学生目录复用 V3.2-08 的 `ms.student_directory_assigned`。新权限授予原先的只读角色 `ms_student_assignee_reader`，**不增加对学生、联系人、员工、审核、财务等基础表的 SELECT 或任何写权限**。

数据库视图按受保护的员工登录映射确定范围，员工无法从 HTTP 请求切换数据库身份。查询先在只读、可重复读数据库事务内确认**当前批准身份**，再获取业务视图，减少身份撤销与读取的竞态；后续请求仍会重新鉴权。

### 独立本机 API

`src/scoped-employee-read-api.mjs` 使用独立 PostgreSQL 连接池和真实员工数据库 LOGIN，完成：

1. 验证可信外部 RSA 公钥签名、发行方、受众、有效期和主体。
2. 拒绝非 GET、任意 URL 和查询参数，仅保留五条精确业务路径。
3. 连接固定员工专属受限 PostgreSQL 账号，开启 `REPEATABLE READ READ ONLY` 事务。
4. 以数据库函数对照有效身份批准与数据库员工绑定；失效即 403。
5. 仅从内部五个固定视图名称查询必要字段，最多 100 条，中文结果、不返回 SQL 原文。
6. 数据库查询失败仅返回笼统错误；前端不会出现原始数据库语句或 JSON 审计字段。

`src/scoped-read-server.mjs` 可在本机以隔离测试变量启动上述服务，并在监听前运行数据库最小权限自检。必须提供**专用员工数据库 LOGIN** 和受信任公钥配置；若使用超级用户、数据库拥有者或能读取原始学生/财务表的账号，启动前拒绝。

示例环境参数只说明契约，不提供真实密钥：`MS_STAGE=isolated-test`、`DATABASE_URL`（员工专属受限账号）、`OIDC_ISSUER`、`OIDC_AUDIENCE`、`OIDC_JWKS_JSON`、`PORT=3200`。生产中不能直接使用此服务。

机器可读接口文件：`api/openapi/employee-scoped-read-implemented.v3.2.json`。

## 4. 自动化验收测试

`tests/security/scoped-business-read-api.test.mjs` 使用两个真实 PostgreSQL 员工专属数据库 LOGIN、真实 HTTP 服务器、真实测试 RSA 签名与独立主管身份审批记录，在一个隔离 PostgreSQL 16 库中验证：

| ID | 测试事项 | 必须得到的结果 |
|---|---|---|
| SEC-READ-01 | 员工账号读取基础表、家长明文/密文、员工身份、财务或 UPDATE | 数据库拒绝 |
| SEC-READ-02 | RSA 正确但员工身份待审核 | HTTP 403 |
| SEC-READ-03 | 员工 A/B 查询各自学生、联系人、咨询、线索和商机 | 五种接口各只返回授权范围 |
| SEC-READ-04 | 外部令牌伪造 `org_id`、`role`、`staff_id` | 不改变数据库员工身份 |
| SEC-READ-05 | A 员工令牌请求 B 的数据库服务 | HTTP 403 |
| SEC-READ-06 | 篡改签名或缺少令牌 | HTTP 401 |
| SEC-READ-07 | 任意业务写入方法、未知接口、查询参数注入尝试 | HTTP 404，不写入 |
| SEC-READ-08 | 将 A 学生授权给 B | B 获得必要学生、联系人、咨询查看权限；不获得 A 线索或商机 |
| SEC-READ-09 | 撤销具体共享授权 | B 立即失去上述学生、联系人和咨询权限 |
| SEC-READ-10 | 外部员工身份撤销或员工停用 | 旧有效签名令牌也无法继续读取 |

此外，GitHub Actions 必须继续执行 PostgreSQL 001—013 全部迁移、既有双机构隔离、双主管身份审批和家庭核实、所有旧业务回归、Chromium 中文实际界面、V3.1 技术合同回归。

**只有 GitHub Actions 对应 PR 最新 HEAD 的结果为 SUCCESS，才可以声称“隔离自动化测试通过”。** 机器成功不等于真人 GUI 验收、真身份接入或实际跨 CRM 集成。

## 5. 仍然必须阻断生产上线的内容

1. **正式 OIDC 身份供应商**尚未确定，没有正式 Code + PKCE、MFA、受控员工入离职同步或合法的生产浏览器会话管理。
2. 本轮**独立只读 HTTP 服务**不替代现有较宽权限 CRUD API。原业务写入口及其他读取路径仍然使用先前的机构级低风险数据库账号，未完成全业务员工级最小 SQL 权限改造。
3. 真实电话号码/微信号密文处理、敏感家长关系材料访问与撤销、联系人多学生授权边界尚需实际数据隐私合规与安全审查。
4. 机构内销售主管查看下属业务、转交客户、审批共享和撤销、跨机构调岗以及复合角色仍需正式业务决策及全表安全模型。
5. 正式财务收款、部分付款、退款、成交归因、客户订单以及 CRM 课时权益仍**关闭或仅停留在设计合同层**。不得把只读查询成功误当成相关接口已上线。
6. 演示用数据库 LOGIN 不是生产员工账号。不能将测试数据、静态开发密钥或本机受限服务直接部署公开网络。
