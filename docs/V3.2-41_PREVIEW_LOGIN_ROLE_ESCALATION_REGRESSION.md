# V3.2-41｜预览数据库 LOGIN 权限升级与跨机构隔离动态回归

> **范围：仅隔离 PostgreSQL 测试账号与虚构机构。** 本期不是生产财务/CRM 认证，也不是正式 UAT。基于已通过完整 CI 的 V3.2-40 Draft PR #47（`d4a153b379e7c53192fd3e9d3a13f324ccaac6c5`）。

## 1. 从证据清单转向可运行的拒绝验证

V3.2-40 的 T01—T06 证明仓库已有隔离测试断言，但不等于本阶段全部新检查已通过。本期新增独立测试 `tests/security/v3-2-41-preview-login-boundary.test.mjs`，以两套 **真实 PostgreSQL 非所有者测试 LOGIN**（`ms_uat_preview_a` 和 `ms_uat_preview_b`）连接同一个完全隔离的 CI PostgreSQL 服务。

| 检查 | 成功条件 | 不能据此声称 |
|---|---|---|
| LOGIN 与 RLS 基本属性 | `session_user=current_user` 为预期测试账号，且 `rolsuper=false`、`rolbypassrls=false` | 所有生产安全角色已审计 |
| 角色继承禁止 | 两账号都不能成为 `ms_integration_gap_writer`、`ms_source_readiness_writer`、`ms_fixture_uat_freeze_writer` 成员 | 真实生产服务账号已撤销 |
| 角色切换阻断 | 用测试连接实际发出 `SET ROLE`，对上述三个写角色全部得到 SQLSTATE 42501；失败后身份仍未改变 | 生产管理员权限完全正确 |
| 直接表权限 | `sales_orders`、`payment_allocations`、`crm_entitlement_links`、缺失证据事件表均没有直接 SELECT/UPDATE | 所有业务写入路径已验证 |
| 高权限函数调用 | 无权执行缺失证据写入函数和 UAT 安全冻结函数 | 所有历史领域命令已实现 |
| 双机构映射 | A/B LOGIN 的 `ms.current_scoped_organization_id()` 返回两个非空、不同的机构 | 真实财务与 CRM 的租户映射已验证 |

本检查只调用只读权限元数据函数，和预期必然失败的 `SET ROLE`；**不修改订单、支付分配、课时或审批数据，也不变更数据库角色授权**。若任何角色可以越权切换，必须让 CI 失败并保持全部业务阻断。

## 2. 未跨越的安全与业务边界

- **学生为主要管理单位，家庭按需关联。** 两名学生同家庭不自动互转订单、付款或权益。
- 真正错绑并已有订单、收款或履约的学生关联持续 `hold_active`；R01—R10 和 16 项真实准入仍缺失。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 财务/CRM OpenAPI 仍处于 `proposed-unimplemented`，不连接真实系统，不导入真实儿童、合同、银行信息。
- 本阶段不新增 039，不合并、不部署，不修改 `edu-management-system`，不触碰原始订单、资金、SaleEvent、已上课和消课历史。

## 3. 证据解释及下一步

只有本 PR 最新 HEAD 的 GitHub Actions **completed/success**，才可报告“V3.2-41 的隔离动态权限回归通过”。失败不得绕过、删除断言或据此授权生产接入。V3.2-40 中 T07—T10 所列的**真实服务角色撤销、外部权威租户映射、备份恢复及正式 UAT**仍为 NOT PROVEN；本次新增测试只覆盖模拟环境防提权，不改变这些真实缺口。
