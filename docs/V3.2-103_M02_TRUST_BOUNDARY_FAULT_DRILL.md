# V3.2-103｜M02 来源信任边界故障演练与生产准入缺口

## 基线和实施范围

基于 V3.2-102 Draft PR #109，HEAD `01a74c12bfb6bb2c6db007dd39497f67a7d186f5`，GitHub Actions #43660147528（V3.2-102）及 #43660147531（V3.2-100 聚合审查）均 `completed/success`。这些是 Node 隔离测试，不是正式 PostgreSQL、Chromium、外部合同与真实财务/教务/三方 UAT。

本期是**信任边界核查、最小防护修复和故障演练**，不会通过模拟证书、内存审计或重试机制推导生产授权。修改 V3.2-102 隔离来源工厂：必须为销售、财务、教务分别固定**不同**的 Ed25519 测试公钥，使用 SPKI DER 的 SHA-256 指纹识别重复密钥；一旦两个来源共用同一密钥，初始化直接拒绝。密钥本身仍是 CI 临时生成的，并无真实机构治理或密钥轮换协议。

## 演练覆盖和明确未解决事项

| ID | 级别 | 故障模式 | 本期结果与边界 |
|---|---|---|---|
| TRUST-01 | P1 | 不同来源复用同一公钥 | **修复：** 隔离工厂构造时拒绝；并检查交换公钥和非 Ed25519 密钥 |
| TRUST-02 | P1 | 未批准的新来源密钥出现 | 测试必须拒绝签名；不能悄然接受所谓密钥轮换 |
| TRUST-03 | P1 | 一个域断线、超时或迟到响应 | 超时与缺源 fail closed，之后健康重试可恢复**只读模拟一致性**，绝不能放行业务 |
| TRUST-04 | P1 | 来源 epoch、撤销水位/摘要、异常代数冲突 | 三域不一致均拒绝；发生版本倒退也拒绝 |
| TRUST-05 | P1 | 进程重启后重放旧但仍在模拟有效期内的签名数据 | **实证缺口：** 新进程失去高水位，单靠内存 `seen` 不能拒绝重放；必须持久可信的单调版本登记，未实施 |
| TRUST-06 | P0 | 具有模拟私钥的人生成新的“内容不真实但签名正确”的数据 | **实证缺口：** 签名只能证明拥有对应密钥，无法证明订单、收款、课时及签署人员权威；全部真实授权始终为 false |
| TRUST-07 | P1 | 缺少正式密钥托管、密钥轮换、销毁与吊销服务 | **未实施：** 不允许把测试公钥自动视为正式权威 |
| TRUST-08 | P1 | 三域虽有相同撤销序号但来源因果关系/事务切面不一致 | **未实施：** 双读校验、聚合 SHA-256 并非跨系统一致性快照或提交凭证 |
| TRUST-09 | P2 | 超时后的源端请求可能延迟返回 | 测试内部不执行写入；真实适配仍需 AbortSignal、超时取消及迟到结果处置规范 |

本阶段新增 `tests/security/v3-2-103-m02-trust-boundary-fault-drill.test.mjs`，使用真实的 V3.2-102 Ed25519 隔离读取工厂执行错误和正常场景。**测试中“重启后可接受旧数据”的断言刻意展示尚未修复的缺口，不是安全通过的证明。** 即使来源包内部一致，返回值仍固定 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。

## 生产信任边界和责任

正式系统必须由财务、教务等真实来源分别确认身份、签名权限及撤销权威；销售协调学生身份与异常管理，但不能替财务或教务签字；身份系统须建立用户与组织隔离和授权人员撤权的真实记录。来源真实性要求外部信任根/密钥治理、独立认证的撤销序号及事务边界，不能由调用方单方面提供临时公钥和自己签署数据。

需要独立验收的最小条件：可靠持久化来源高水位、签名 keyId 与生效/吊销时间契约、财务与教务权威回执、学生订单付款课时的实际只读对账、真实不可覆盖审计、多租户严格隔离、跨系统事务与竞态处理、失败及超时的可证实安全结果。16 项外部准入与 R01—R10 仍未验证，正式合同 `proposed-unimplemented`。机器风险清单保存于 `spec/v3-2-103-m02-trust-boundary-fault-drill.json`。

继续遵守：学生为主要管理单位，家庭按实际关联需要创建；原订单、资金、SaleEvent、课时与补偿历史不覆盖。没有新增生产迁移 039，不修改 `edu-management-system`、`src/server.mjs` 或 `src/app.mjs`；不合并、不部署，市场销售技术文档独立维护。
