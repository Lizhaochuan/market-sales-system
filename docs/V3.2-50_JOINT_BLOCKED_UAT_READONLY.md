# V3.2-50｜同机构财务＋教务联合只读 UAT 报告（可运行隔离实现）

> **本阶段新增实际 JavaScript 只读组合函数与隔离 PostgreSQL 角色集成测试，不是重新复制 #38 的 SQL，也不是生产联调。** 上游 V3.2-49 Draft PR #56 以 GitHub Actions #43587476814 completed/success 为验收基线。此版本自身最新 HEAD 必须另行通过完整 CI。

## 1. 现有能力和差距

现有迁移 `034_preintegration_authority_hard_gates.sql` 固定维护 16 项真实联调准入目录，迁移 `035_readonly_integration_uat_report.sql` 则为单一财务或教务虚构来源分别返回 **12 项**适用的阻断清单。此前未选的 #38 独有能力是将**同机构两份来源**合并为一份给安全负责人阅读的 16 项联合验收报告。

因此，V3.2-50 实现 `src/joint-integration-uat-blocker-report.mjs`，复用现有被选 035 SQL 的只读函数，**不创建同号 035，不创建 039，不申请新的生产权限**。

## 2. 真实代码接口

| 导出函数 | 用途 |
|---|---|
| `buildBlockedJointUatReport(financeRaw,academicRaw)` | 校验原有两份已阻断的 SQL 报告，按完整 16 项目录组合 |
| `loadBlockedJointUatReport(pool,financeRequestId,academicRequestId)` | **只允许 isolated-test** 中的独立信息安全测试 LOGIN `ms_fixture_source_security` 使用单个数据库连接分别查询两个来源；任一来源不在同机构，底层 SECURITY DEFINER 抛出 SQLSTATE `42501`，整份报告不输出 |
| `renderBlockedJointUatMarkdown(report)` | 将已组合的阻断报告转为中文 Markdown，转义来源字段，始终突出“禁止真实联调、禁止资金课时写入、禁止解除 hold_active” |

调用路径为：专用安全 LOGIN → 同一数据库会话 → `readonly_integration_uat_report(financeId)` → `readonly_integration_uat_report(academicId)` → 已有阻断校验 → 内存组合 → Markdown。

- 两份来源必须为**不同的有效 UUID**，领域固定先 finance、后 academic；不能交换、混入另一机构或伪造放行字段。
- 每份来源的原始 12 项必须完整且全部阻断，合并后是 **16 个不同 check_code**：销售 3、财务 4、教务 4、安全 5。
- 销售和安全项目虽然在清单中合并为一行，但财务来源与教务来源各自登记的缺失事件保持**两个独立计数**。不能重复假装“两个批准”，也不能丢失一方记录。
- 数据库 SECURITY DEFINER 已执行受限 LOGIN 的可信机构检查；原始订单、资金、课包表仍没有任何直接读取/改写新授权。
- 目前没有对外开放正式 HTTP 路由。这是可被隔离测试调用的真实只读**服务模块**，不是可供正式业务人员访问的生产页面。

## 3. 动态验收

`tests/security/joint-integration-uat-blocker-report.test.mjs` 使用虚构来源申请、独立财务/教务/安全数据库账号，校验：

1. 同机构的两份虚构来源真实调用现有 SQL 函数后得到 16 项联合报告，所有生产执行、释放标志持续 false。
2. 安全测试 LOGIN 可以读取本机构，但跨机构来源组合必须拒绝 `42501`；财务账号不能冒充安全账号生成联合清单。
3. 校验错领域、重复来源、缺少检查、伪造批准、两份共享项目的标签不一致等异常，要求直接失败而不是生成看似已通过的报告。
4. 共同销售/安全项目的缺失事件以**财务、教务两个来源分别保留**；演示用 Markdown 不插入恶意脚本或原始敏感数据。
5. 安全、财务、教务三个模拟数据库 LOGIN 均不能直接 UPDATE 收款分配或 CRM 权益链接。

## 4. 仍未解决的正式业务前提

- **学生为主要管理单位，家庭按需关联。** 同家庭、共享家长联系方式或虚构 UAT 报告不赋予跨学生订单、收款、学时转移授权。
- 真正错绑且已有下游订单、收退款、SaleEvent 或课时事实继续 `hold_active`，历史全部保留，不执行补偿、不重新分配。
- 16 项**真实**业务准入、R01—R10、财务和 CRM 权威映射、生产 OIDC、灾备与四方 UAT 签字仍未完成；原有 OpenAPI 继续 `proposed-unimplemented`。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 不修改 `edu-management-system`，不合并、不部署，不增加 SQL 039、不复制未选 #38 的 SQL，不接真实财务或教务服务。

## 5. 后续交付

本版只补齐**联合虚构 UAT 只读报告的逻辑和受限数据库调用能力**。若要把它变成正式业务工作台的可见功能，仍须另行设计安全员身份映射、受控只读端点、访问审计、导出水位及独立权限测试；未经正式安全评审绝不自动在生产公开此功能。
