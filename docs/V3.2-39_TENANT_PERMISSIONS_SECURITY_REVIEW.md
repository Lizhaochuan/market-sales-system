# V3.2-39｜隔离 UAT 数据库角色和跨机构边界专项预审

> **仅静态审核，不构成生产安全认证。** 基于 V3.2-38 Draft PR #45，校验主线 SQL 034—036 中权限与只读 UAT 的实际实现。真实授权、业务 UAT、数据库回滚/灾备和跨仓库集成均未完成，状态 BLOCKED / NOT AUTHORIZED。

## 1. 权限路径和核对结果

| 主线资产 | 权限约束 | 可静态确认的证据 | 仍需动态验证的风险 |
|---|---|---|---|
| `034_preintegration_authority_hard_gates.sql` | 16 项检查必须恒阻断 | `production_verified boolean NOT NULL DEFAULT false CHECK(NOT production_verified)`；原表 REVOKE，追加缺失事件不能 UPDATE/DELETE | `SECURITY DEFINER` 函数、`access_actor()` / `SESSION_USER` 是否始终绑定实际 DB 登录 |
| `ms.record_integration_missing_evidence` | 按机构、真实模拟岗位登记缺口 | `ms.access_actor()`、机构匹配 `source_readiness_requests`、部门角色断言、请求幂等 | 角色撤销与并发重复请求，管理员误授权 |
| `ms.readonly_integration_hard_gate` | 只读、按机构及有效角色看准入清单 | 依据 `access_actor()` 和 `organization_id=org` 查来源；结果 `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false` | `SECURITY DEFINER` 与 RLS 在跨角色嵌套查询中的行为，越权枚举 |
| `035_readonly_integration_uat_report.sql` | 不可把模拟材料变成真实通过 | 读取硬门槛，拒绝非 finance/academic 或任一执行标志改变；只输出未授权报告 | 不同租户请求、源缺页/未知、拒绝重放 |
| `036_scoped_uat_preview_reader.sql` | 受限只读预览 | `ms_uat_preview_reader NOLOGIN`，只继承 `ms_integration_gap_reader`，视图 `security_barrier=true` 并限定当前 DB 机构/员工 | 运行态无其他表的直接 SELECT/INSERT/UPDATE/DELETE、凭据泄漏、受限角色复用 |

## 2. 针对独立测试的验收矩阵

| 检查 | 应通过 | 应拒绝 |
|---|---|---|
| 同机构有效受限登录 | 仅查看该机构模拟来源对应的 12 项阻断报告 | 无权查看真实财务或 CRM 权威信息 |
| 另一个机构受限登录 | 仅查看其自己机构的候选 | 使用另机构 source_request_id 应收到权限拒绝 |
| 未绑定数据库员工 / 撤销角色 | 重新鉴权后读取失败 | 客户端任意声明 tenant、staff_id、role 不得提升权限 |
| UAT 读者 | 只能执行明示的只读函数/视图 | 原始 `sales_orders`、`payment_allocations`、`crm_entitlement_links` 不可直接读取或改写 |
| 异常/重放/历史审计 | 仅追加虚构缺失事实、保留先前审批 | 无权改写缺失历史、变更 `production_verified` 或伪造 R01—R10 PASS |
| 预览导出 | 每次实际执行前校验受限身份和历史版本 | 过期水位、越权范围、未知来源不得宣称成功 |

以上是**必须重复的隔离 CI 和独立真实 UAT 计划**，并非本静态报告已执行的生产测试。既有 `tests/security/integration-uat-readonly-db.test.mjs` 包含受限 DB 登录、跨机构和资金/课时表拒绝断言；真正生产的 16 项准入依然全部缺失。

## 3. 必须保留的否决条件

- 学生为主体、家庭按需关联，兄弟姐妹不得自动合并订单/收款/课时。
- 真正错绑且已有下游订单/资金/履约的案件必须持续 `hold_active`。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
- 原订单、支付流水、SaleEvent、实授消课历史不可 UPDATE/DELETE；金融及 CRM OpenAPI 仍为 `proposed-unimplemented`。
- 保持 Draft，不合并、不部署、不新建迁移 039、不修改旧 `edu-management-system`，不创建真实系统接入凭据，不释放隔离。
