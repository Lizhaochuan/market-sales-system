# V3.2-120｜M02 已导出清单失效检测与不可逆撤权追溯（CI-only）

## 已核实基线

V3.2-119 Draft PR #126 的 HEAD 为 `24636b2d03e6be76f335bcbdd7f4b26bae00aed5`。专属临时 PostgreSQL Actions #43669251225 和 M02 聚合安全检查 #43669251047 均为 `completed/success`。

V3.2-119 已提供有界、按学生独立聚合的异常级 HOLD 缺口清单以及本地 SHA-256 导出。用户持有导出的旧清单时，后续可能发生新学生 HOLD、outbox 入队、迟到负向回执、对账状态变更或后续 V119 导出。本阶段补充**针对已生成导出版本的无授权状态检查与追加式撤权证据**，不会编辑、撤销、替换原始清单文件或通知真实收件人。

## 被观察版本与四种结果

输入只接受机构 UUID、异常 UUID、**需要复核的 V119 清单 sequence**。禁止用户控制摘要或传入 `finance_authorized`、`hold_active=false` 等自称权限字段。PostgreSQL 在同一个隔离 `SERIALIZABLE` 事务内：

1. 重新读取、验证目标 V119 事件直到最新 head 的**完整 SHA-256 链**，确保目标存在、摘要和先前版本完整，避免只比较调用方传入的目标 SHA。
2. 通过复用 V119 同一套已有校验器，在**同一数据库事务快照**中重新枚举该异常所有 HOLD 学生，逐人复查 V115 HOLD 完整事件链、V116 outbox 和负向回执、V118 学生扫描历史及当前快照。
3. 查看 V120 中目标版本曾否被记录为撤权；以前已经撤权则后来的来源快照变化**永远不能使它恢复有效**。
4. 将目标 V119 版本摘要、目标来源摘要、最新 V119 版本序号及摘要、当前来源摘要、分类、前一条 V120 事件摘要与本次事件 digest 持久化为新的追加式审计记录。

| 分类 | 含义 | 业务权限 |
|---|---|---|
| `CURRENT_FIXTURE_SNAPSHOT_STILL_UNAUTHORIZED` | 在本次**临时数据库**采样时，目标仍是最新导出且来源快照尚未发现差异 | 继续 HOLD，**不能表述为正式有效** |
| `REVOKED_SOURCE_CHANGED_AFTER_EXPORT` | 当前学生/HOLD/outbox/回执/扫描视图与被导出时不一致 | 记录该目标已失效，持续阻断 |
| `REVOKED_SUPERSEDED_BY_LATER_EXPORT` | V119 已有更晚的完整清单版本，即使对旧版单独查验无误 | 不允许旧版恢复为最新版本 |
| `REVOKED_PREVIOUSLY` | 该目标已在 V120 历史审计中被撤权 | 永久保留被撤权事实，拒绝重新放行 |

此处“撤权”是**模拟导出清单有效性的撤回**，不是实际 IAM 员工权利或财务业务权限撤销。即使返回第一种分类，所有接口也固定 `hold_active=true`、`handoff_allowed=false`、`finance_authorized=false`、`academic_authorized=false`、`compensation_write_allowed=false`、`release_eligible=false`。**没有业务 release、approve、handoff、重发或生产告知接口。**

## PostgreSQL 事务和不可逆证据

- `tests/fixtures/v3-2-120-m02-manifest-revocation.sql` 在一次性 `v106_isolated` PostgreSQL16 库下建 `fixture_manifest_revocation_events`、`fixture_manifest_revocation_heads`；事件表对受限机构 A/B 角色仅 SELECT/INSERT，`FORCE ROW LEVEL SECURITY` 按机构隔离。
- `fixture_manifest_revocation_heads` 的 `revoked_export_count` 是**不同目标导出版本的累计撤权数**，不是“全部学生已认可”的数量；SQL 触发器禁止审计序号倒退、撤权计数回退或 `hold_active=false`。
- `tests/helpers/v3-2-120-m02-postgres-manifest-revocation.mjs` 在 `SERIALIZABLE` 事务内执行 V119 完整链和来源快照核验、去重、追加事件和推进 head；故障在 COMMIT 前发生则整笔回滚。COMMIT 后结果确认丢失时从 SQL 再读即可核实，不把不确定结果冒充回滚。
- 提交后再次读取来源快照以及最新 V119 head。只要有变化，返回 `BLOCKED_EXPORT_OBSERVATION_SOURCE_CHANGED_AFTER_COMMIT`；已提交的审计记录不会被覆盖。这仍无法填补最后一次核验后、跨真实业务系统发生新变更的竞态。
- `src/cross-module-manifest-revocation-audit.mjs` 只提供 `observe`、`inspect` 和纯分类校验，所有状态 fail closed。`scripts/v3-2-120-setup-manifest-revocation.mjs` 仅在 `V106_ISOLATED_PG=YES_TEST_ONLY` 与 `v106_isolated` 临时管理员下建表，**不创建生产迁移 039**。

## 正式业务边界仍为硬阻断

六类独立正式责任人全部 `UNASSIGNED`；16 项外部系统准入、R01—R10、真实财务与教务签署、三方原子交接回执、企业 PostgreSQL、Chromium、合同及生产 UAT 均 `UNVERIFIED` 或 `NOT_RUN`，合同依旧 `proposed-unimplemented`。
