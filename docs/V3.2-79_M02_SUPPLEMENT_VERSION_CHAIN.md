## 本阶段：仅虚构、CI 内存模型
`src/cross-module-supplement-version-chain.mjs` 由 V3.2-78 的不可变 `preparation.audit` 原提交记录提供锚点。每个机构、异常、六类证据要求及当前来源修订分别建链。不得把请求本身声称的“已复核”作为权威凭据。

1. 第一版补充的 `parent_digest` 必须严格匹配原 `submitted` 材料 SHA-256；后续版本必须匹配前一条冻结 `chain_digest`，版本号严格连续，不接受跳号、逆序、重复新键或被替代旧版重放。
2. 只允许原材料提交人在同一个虚构来源修订号下补充。带外注入的当前来源版本与请求版本不一致则直接拒绝；机构、异常或要求不同的原提交不可互用。每次新增记录冻结主体字段、原始提交摘要及 SHA-256 链摘要。
3. 相同幂等键和相同正文仅允许在该版本仍是链尾时返回旧记录；同一幂等键换正文拒绝。来源修订升级后，原链继续留存历史，但不再作为当前证据判断。新修订必须重新有原始提交记录，补充版本从 1 开始。
4. 报告校验每个当前版本的父摘要、版本连续性和不可变记录，仍明确 `independent_supplement_review_verified=false`。即使全链匹配，始终为 `BLOCKED_INDEPENDENT_SUPPLEMENT_REVIEW_AND_EXTERNAL_AUTHORITY_MISSING`，不得据此宣称真实财务或教务批准。
5. V3.2-78 内部审核记录并不会自动沿用到补充材料的最新版。补充材料的独立核查、真实签名、原订单/资金与课时对账、三方正式验收和外部交接回执均待后续真实权威系统验证。

## 无生产写入和解除隔离
这是单进程内存模拟，没有持久事务、防并发写入锁或外部可信身份来源。无生产数据库迁移、真实 HTTP 交接/补偿接口或可执行权限。所有结果维持 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。

学生是主要管理单位，家庭仅在确有兄弟姐妹关系时按需关联。错绑已产生的订单、付款、SaleEvent、课时履约及补偿历史全部保留，不得原地修改。16 项准入、R01—R10 未完成；正式合同仍 `proposed-unimplemented`，迁移 001—038、无 039。不合并、不部署、不修改 `edu-management-system`；市场销售文档独立维护。
