# V3.2-117｜M02 HOLD 待投递事件对账与异常取证（仅隔离环境）

## 基线与结论

基于 V3.2-116 Draft PR #123，HEAD `68e512f53fb46624b6d15df1d43eacb408c32bb4`，专属 GitHub Actions #43666863372、聚合安全审查 #43666863375 均 `completed/success`。

V3.2-115 已提供一次性测试库的追加式 HOLD；V3.2-116 已提供单独事务保存的模拟 outbox 和独立模拟接收方负向回执。两期**并没有**建立真实网络传输、自动投递/重试、真实外部签署权或 HOLD 与 outbox 的原子创建。V3.2-117 只针对现存临时 PostgreSQL 证据进行**被调用时的安全对账、状态分类和追加式异常记录**。

## 对账分类与处理边界

| 分类 | 证明了什么 | 允许的下一动作 |
|---|---|---|
| `OUTBOX_GAP` | 现存 HOLD 在本地没有对应 outbox 记录 | 人工核查待补事件；不能断言消息丢失 |
| `AWAITING_NEGATIVE_RECEIPT` | 已持久化 outbox，未有本地负向回执，仍在测试窗口内 | 继续 HOLD，安排手动核查 |
| `NEGATIVE_RECEIPT_OVERDUE` | 在**模拟阈值** 60 秒之后仍未找到回执 | 标记不确定，不能宣称远端没有收到 |
| `NEGATIVE_RECEIPT_RECORDED` | V116 临时测试库已有格式正确的负向回执 | 保留既有负向证据，依然禁止业务放行 |
| `SIGNED_FIXTURE_CANCELLATION_ADVISORY` | 临时独立测试 Ed25519 来源声明其本身撤权 | 仅形成“待人工核实取消或重新签发”建议；**不实际撤销 HOLD 或 outbox** |
| `SOURCE_PROOF_UNVERIFIED` | 来源不可达、签名伪造、过期、跨机构、绑定不符或明确 unknown | 按未知阻断；禁止将无效证明冒充真实撤权 |

新模块 `src/cross-module-hold-delivery-reconciliation.mjs` 只提供 `reconcile` 和 `inspect`，输入严格包含机构、异常、**学生**主键及 HOLD 序号。V3.2-115 的 HOLD 事件必须完整哈希链到 head，并确认 V3.2-116 的 outbox 和负向回执都属于同一机构、异常、学生和消息摘要。

签名治理**仅为测试用**：`v3.2-117-ci-source-disposition-v1` Ed25519 声明固定关联 HOLD 摘要、消息摘要、测试 issuer、来源 epoch/修订、撤权版本、有效期及 `fixture_only=true`。未知、签署不合格或来源接口错误时使用 `SOURCE_PROOF_UNVERIFIED`，没有真实安全、财务或教务来源任命及密钥托管证明。

任何分类只返回 `hold_active=true`、`handoff_allowed=false`、`finance_authorized=false`、`academic_authorized=false`、`compensation_write_allowed=false`、`release_eligible=false`，绝不创建订单、收款、课时修改、补偿、正向签收或解除隔离。

## 一次性 PostgreSQL 追加式对账审计

`tests/fixtures/v3-2-117-m02-delivery-reconciliation.sql` 只在 GitHub Actions PostgreSQL 16、`v106_isolated` 创建：

- `v106_test.fixture_delivery_reconciliation_events`：机构/异常/学生复合 scope，严格单调 sequence，前一事件 SHA、HOLD 事件及其 head SHA、outbox/负向回执摘要、来源测试签名摘要、分类/人工操作建议和原因摘要。相同证据及分类的 `cause_digest` 去重；数据库测试用户对事件表只有 SELECT/INSERT，不可修改或删除。
- `v106_test.fixture_delivery_reconciliation_heads`：只保存最新 sequence 与摘要，`hold_active` 具有 `CHECK(hold_active IS TRUE)`；受限角色无法更新该字段。机构 A/B 使用 `FORCE ROW LEVEL SECURITY` 隔离。
- `tests/helpers/v3-2-117-m02-postgres-reconciliation.mjs`：`SERIALIZABLE` 事务内重新读取并核验 V115 HOLD head + 事件、V116 outbox + 回执及上条对账事件，再一次性保存本期对账事件和 head。事务失败则 rollback；COMMIT 后再读取事件和来源快照，改变时仅返回不确定阻断，**不会删除已经提交的审计证据**。
- `scripts/v3-2-117-setup-delivery-reconciliation.mjs`：只可操作有明确一次性测试标识的 PostgreSQL 数据库；不是生产迁移 039。

对账记录本身是**继 V115 HOLD、V116 outbox 之后的第三次本地写入事务**，不能追溯把前三次事务合并成一个原子事件，也不能提供真正跨系统资金及履约锁。
