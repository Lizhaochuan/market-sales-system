# V3.2-114｜M02 审核人回避、撤权与替换审计（仅隔离环境）

## 前置核验

上游 V3.2-113 Draft PR #120，HEAD `a2566c83f5877f0b5e0f432774f2440c8e721312`；专属 CI #43665052834、V3.2-100 聚合 CI #43665052863 均 `completed/success`。V3.2-113 只能建立**测试环境中的待真实负责人确认指派**，真实企业员工、财务与教务签字人仍无一经确认。

V3.2-114 的目的不是开始业务审批，而是让“旧审核人离职/撤权/岗位变更/利益冲突后，不能偷偷覆盖旧记录”这一规则可以被真实一次性 PostgreSQL 验证。所有签名主体仍为临时 fixture，绝非真实人事、身份安全和业务系统权威。

## 业务原则

1. **回避（recuse）**：原审核人可能存在利益冲突、岗位变更或真实身份撤权的**测试声明**。记录回避后，当前待审核责任人变为 `null`，不得自动解除隔离。
2. **替换（replace）**：原审核人可被替换，或在回避后再安排新审核人。新审核人必须具有独立测试身份状态，不能是任何六类岗位的候选负责人或材料提交人，不能与 V3.2-113 原审核人相同。
3. **撤权一致性**：声称 `role_revoked` 的动作，必须具有对应身份源出示的撤权状态；其他理由不能掩盖“当前身份已失效”。若审核人任命被撤销、身份状态改动、证据重新提交，则新的审核“当前性”直接失效。
4. **历史不可改写**：V3.2-112 接收历史与 V3.2-113 初始指派不允许原地修改。回避及重新指派通过新的只追加 SQL 事件记录，变动事件携带旧审查人的标识、替换人员、签署理由、事件链前摘要与原审核快照摘要。
5. **没有真实批准**：即使审计事件提交并成功复核，也只返回 `BLOCKED_FIXTURE_REVIEWER_LIFECYCLE_RECORDED`，没有外部审核人任命、财务、教务、补偿和交接的真实权限。

## 新增技术模块

- `src/cross-module-reviewer-recusal-replacement.mjs`：`createIsolatedReviewerLifecycle` 接受 V3.2-112 的元数据事件账本、V3.2-113 的原始指派账本、V3.2-114 的生命周期事件账本、治理方模拟签名动作和独立身份方模拟签名在岗状态。治理签名与身份签名**使用不同固定测试 Ed25519 公钥**；任何一方缺签、替换、公钥共用、错误机构、错误版本、伪造期限或撤权不一致，都 fail closed。
- `tests/fixtures/v3-2-114-m02-reviewer-lifecycle.sql`：只在 `v106_isolated` 临时数据库内创建 `fixture_reviewer_lifecycle_events`（不可被受限角色 UPDATE/DELETE）及对应 head。机构、异常、学生构成复合作用域，事件请求 ID 去重，A/B 两个隔离 PostgreSQL 测试用户沿用 FORCE RLS。
- `tests/helpers/v3-2-114-m02-postgres-reviewer-lifecycle.mjs`：每次动作在一笔真实 `SERIALIZABLE` 事务内验证 V3.2-113 原审核指派、V3.2-112 接收 head、上一次生命周期事件的链摘要和当前审核人标识，再追加事件并推进 head。并发争夺同一步时不能同时写入。提交前 SQL 故障整体 rollback，提交后回读 SQL 历史与来源状态。**数据库锁只保证本地审计范围，不锁定财务、教务和身份源**。
- `scripts/v3-2-114-setup-reviewer-lifecycle.mjs`：只允许一次性 CI 测试数据库 `v106_isolated` 创建表；不修改生产迁移及任何业务表。
- `tests/integration/v3-2-114-m02-reviewer-recusal-replacement.test.mjs`：在 GitHub Actions PostgreSQL 16 上利用真实 V3.2-112 接收表、V3.2-113 审核指派表与 V3.2-114 生命周期表验证独立签署、冲突、撤权、重放、事务完整性及跨租户隔离。

## 尚未解决的真实来源与事务问题

**最大阻断仍是实际业务信任根缺失。** 目前治理和身份状态虽可以在测试中分别验证 Ed25519 签名，但签名密钥来源于临时测试脚本，并非真实组织管理方或经授权的人事/身份系统。V3.2-112 六方材料来自未核实自述，V3.2-113 原审核指派也仅为测试，所谓“来源历史摘要一致”不证明资金、课时、SaleEvent 或学生归因原始事实正确。

另有两个独立限制：第一，签署动作与 SQL 提交只能在本地审计事务内实现快照保护，**真实身份系统可能在最后一次读取之后再撤权**；第二，已提交的待确认事件仍是一条历史记录，即使其“当前性”随后失效也不可删除，应通过新追加事件及事故处置规则审计。绝不可把模拟“recused/replaced”的数据库事件当成真实三方联合业务交接或校正学生资金归属的批准。

销售、财务、教务、身份安全、集成协调、数据库六方的真实负责人仍均为 **UNASSIGNED**。真实财务与教务独立签名、订单/资金及课时履约对账、销售/财务/教务三方验收与原子交接回执均未实现。16 项外部准入、R01—R10、企业 PostgreSQL、Chromium 和正式合同 UAT 未完成，合同 `proposed-unimplemented`。

所有返回严格保持 `external_authority_verified=false`、`external_reviewer_appointed=false`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`；`merge_authorized=false`、`deploy_authorized=false`。

学生始终是主要管理单位，家庭仅在同一家庭实际多个孩子时才按需关联。历史订单、收款、SaleEvent、课时、补偿记录不可直接改写。生产迁移规格仍为 001—038，本期不新增 039；不连接 `edu-management-system`、生产应用入口、真实数据库或旧 CRM 技术文档，市场销售技术文档继续单独维护。
