# V3.2-104｜M02 治理签名密钥名册、撤销证明与原子版本水位接口

## 基线与总体结论

上游 V3.2-103 [Draft PR #110](https://github.com/Lizhaochuan/market-sales-system/pull/110)，HEAD `8f85a0b78f9e6a7e489852219de9a8a3aab75840`；三个隔离 GitHub Actions #43660468834、#43660468840、#43660468841 均 `completed/success`。本阶段不改变生产服务、数据库、财务、教务或任何真实签名权威。

V3.2-103 的两个主要缺口是：内存版本高水位在新进程丢失，以及持有模拟私钥的人可自行签署不真实的记录。V3.2-104 **只设计并通过测试模拟**一个独立治理名册及外部原子水位接口，不能据此宣称前述生产问题已经修复。

## 一、隔离实现与签名来源责任

新增 `src/cross-module-source-trust-fence.mjs`：`createIsolatedSourceTrustFence` 接收独立测试治理公钥、只读签名密钥名册、三域来源读取器、测试时间和 `checkpointStore.advance` 存储协议。

- 测试治理方使用单独固定的 Ed25519 公钥签署名册，绑定机构、版本、时效、来源密钥和逐项撤销事件。测试密钥名单中必须精确存在销售/财务/教务各一个 active 密钥，同一个公钥不得跨域复用。
- 密钥轮换仅能通过新的已签名名册和旧密钥撤销事件表达；没有撤销事件、替换治理公钥、交换源域公钥、伪造源记录、过期证明、跨机构数据一律拒绝。
- 每域的来源包签名须包含当前名册 `key_id` 和 `trust_revision`，绑定异常、来源 epoch/revision、异常代数、撤销序号/摘要和证据摘要。三域不可提供相互冲突的这些共享水位。
- 双读来源与治理名册，比较签名和摘要，任何变化都会阻断。超时和读取失败仍然 fail closed。双读不构成跨服务事务锁，更不能代替来源事实认证。
- 每个模拟读请求仅在来源和治理证据一致后，向独立的 `checkpointStore.advance(scope, checkpoint)` 传入待推进版本。**存储调用必须原子、可信、可持久化**；本期只定义其接口，并在测试中使用进程内共享模拟存储。真实 PostgreSQL 的持久事务能力尚未实现及验证。

任何成功结果只可能是 `BLOCKED_FIXTURE_TRUST_FENCE_NO_EXTERNAL_AUTHORITY`，仍有 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。模拟密钥证明与真实财务/教务签名无关。

## 二、数据库隔离验收方案（计划，不是执行记录）

后续由具备数据库验收权限的工程人员，在**完全独立的 PostgreSQL 测试库**验证以下方案，不得在当前生产 schema 中加表或新增迁移：

1. 设计机构+异常为唯一键的可信版本水位表：记录治理名册版本及摘要、三域各自的 epoch/revision 与证据摘要、共享撤销水位/摘要、异常代数、当前来源 keyId、旧 keyId 撤销证明和可信观察时间。
2. 在单个原子事务中以条件检查或 `SERIALIZABLE` 隔离执行“比较 → 拒绝回退或冲突 → 仅在满足全部约束时推进”；两个并发事务中只能有符合版本顺序和撤销规则的结果成功。
3. 把版本回退、撤销降级、同版本篡改、相同版本不同名册、未证明的密钥更换、事务中断、重复请求、跨机构读写、意外断线和进程重启重放列为数据库回归。
4. 验证重启后仍读到之前的水位；验证使用受限数据库角色访问时不能跨机构更改水位，且不能访问真实订单、收款或教务修改权限。
5. 取得真实财务/教务/人员身份来源的签名信任根、密钥托管与轮换/吊销操作规范，再核对真实订单付款课时对账、原子交接与可信回执。没有这些真实前提，数据库测试通过也不意味着可以交接。

完整可机器检查条目在 `spec/v3-2-104-m02-source-trust-fence.json` 的 `production_database_test_plan` 中。此处**没有提供生产 SQL 迁移或声称运行数据库**；共享模拟存储演示“新实例仍可读取先前记录并拒绝回退”，但并不跨进程持久，不能代替 PostgreSQL 或真实可信账本。

## 三、测试和后续门禁

`tests/security/v3-2-104-m02-source-trust-fence.test.mjs` 使用临时签名密钥和共享的单进程原子模拟存储，测试治理签名被替换、来源签名错误、没有旧密钥撤销证明、签名密钥轮换、模拟重启回退、三域因果水位冲突、来源超时或掉线、存储接口伪造成功及模拟并发竞争。专属 Node 22 CI 再运行 V3.2-103、102、101 与 V3.2-100 的隔离回归和安全规格校验。所有这些结果都只能称为**隔离模拟测试**。
