# V3.2-46｜只读响应最终鉴权明确拒绝时的全路径回归

> **隔离测试，真实系统仍禁止接入。** 本版基于 V3.2-45 Draft PR #52，保持学生为主要管理单位、家庭按需关联的规则；真正错误学生绑定且已有关联订单、资金或履约时，继续保持 `hold_active`。

## 目的与现有证据差异

V3.2-44 通过确定性竞态演练证明：读取完成到响应写出前撤销某个模拟员工的身份，会拒绝**来源列表**的返回。V3.2-45 则对六条受保护输出分支模拟末次数据库鉴权异常，要求全部 fail closed。本版补足另一个必要的条件：**初次鉴权通过，数据库已返回报告内容，但最终鉴权得到明确的 `permitted=false`**，须拒绝所有受保护输出。

直接在既有动态测试 `tests/security/uat-preview-api.test.mjs` 中重用两个受限 PostgreSQL 测试机构与签名虚构员工。仅在每个 HTTP 请求的第二次 `ms.scoped_employee_identity_valid` 调用处注入 `{permitted:false}`，第一次仍由真实隔离数据库查询。没有更改或撤销数据库中的测试身份，也不修改授权函数及任何业务数据。

## 动态验收矩阵

| 请求 | 应返回 | 输出限制 |
|---|---|---|
| 来源申请列表 | HTTP 403 | 无另一机构来源数据 |
| 报告 JSON | HTTP 403 | 无报告正文 |
| 报告 Markdown | HTTP 403 | 无导出数据 |
| 冻结状态 | HTTP 403 | 无审计细节 |
| 历史查询 | HTTP 403 | 无历史详情 |
| 差异 JSON | HTTP 403 | 无差异事件 |
| 差异 Markdown | HTTP 403 | 无历史导出 |

上述 **7 条实际 HTTP 路径**共享现有 **6 条受保护的成功响应分支**（历史查询与差异 JSON 共用分支）。每次响应必须包含 `FORBIDDEN`、`Cache-Control: no-store, max-age=0`，且不返回 `data` 或来源申请编号。必须恰好发生 7 次最终鉴权拒绝，以证明不是因初次鉴权或接口不存在而误通过。移除模拟注入后，对本机构虚构报告的正常访问必须恢复 HTTP 200。

## 严格界限

- 本测试的 `permitted=false` 是**动态请求级故障注入**，不等于七次真实员工撤销。真正的数据库身份撤销仍由 V3.2-43 与 V3.2-44 隔离测试另行覆盖。
- 不能声称撤销与网络发送已原子化，也不能声称正式财务/CRM 身份、机构映射、数据水位、补偿与安全 UAT 已通过。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`；16 项真实准入与 R01—R10 继续未完成。
- 原订单、收退款、SaleEvent 和已上/已消课时历史不得覆盖，不得自动将同家庭另一学生的付款或权益变更归属。
- 无迁移 039，不接真实来源，不合并、不部署，不修改 `edu-management-system`，不解除真正错绑的 `hold_active`。
