## 隔离实施
新增 `src/cross-module-manual-lineage-recovery.mjs`。CI 进程内存中，以真实来源不可用为前提，通过独立虚构适配器获取 V3.2-93 冻结链失败原因、机构/异常版本水位及员工身份，仅记录人为补救申请与内部三部门意见，不执行任何历史修复。

流程：销售申请 → 销售独立复核 → 财务独立复核 → 教务独立复核 → 独立销售人员行政结论。所有人员需组织、角色、在岗及 CI-only 标识匹配；同一人不能审核自己申请或前一步审核，结论人员也不得参加本轮申请或复核。证据 SHA-256、来源版本与异常代数绑定同一个待恢复缺陷。来源变化时旧事件保留但不能沿用；独立审计已经恢复正常也不能冒充仍需恢复的缺陷。

每一步追加历史，不覆盖原冻结、继承、订单、付款、SaleEvent、课时或补偿记录。状态终点 `closed_administratively` 仅说明内部审查记录齐全，不代表外部签字、业务纠错或者隔离解除。所有结果 `history_repair_allowed=false`、`automatic_recovery_allowed=false`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。六项外部独立财务/教务/三方及交接回执仍待核查。

纯内存哈希链不是可信持久审计，不存在正式跨模块补偿 API、真实人事身份或签名、外部事务锁和接收回执。16 项外部准入与 R01—R10 未完成，正式合同 `proposed-unimplemented`，生产迁移仍 001—038，无 039。学生为主单位，家庭按需关联。不合并、不部署、不修改 `edu-management-system`，市场销售文档继续独立保存。
