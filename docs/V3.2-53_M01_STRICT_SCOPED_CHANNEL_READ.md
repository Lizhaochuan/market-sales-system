# V3.2-53｜M01 严格员工模式：受限渠道目录视图与中文页面

> 仅可用于虚构机构、CI 隔离 PostgreSQL 与本机测试。基于 V3.2-52 Draft PR #59，其最新 HEAD 的 Actions #43590064940 `completed/success`。本版不能被称作生产权限迁移，不能代替渠道治理审批。

## 1. 本次代码增量

- `tests/sql/create_v3_2_53_scoped_channel_catalog.sql`：**CI 专用**，在一次性测试数据库中建立 `ms.scoped_marketing_channel_catalog`，采用 `security_barrier=true` 且只暴露 `id,organization_id,parent_id,name,channel_type,status`。由迁移所有者创建视图，仅向已有的 `ms_student_assignee_reader` 非所有者角色授予视图 SELECT；绝不向该角色开放原始 `ms.marketing_channels` 表或任何订单、收款、CRM、学生表。
- 同一视图的 WHERE 使用 `ms.current_scoped_organization_id()` 和 `ms.current_scoped_staff_id()`，其机构/员工由 PostgreSQL `SESSION_USER` 的受保护登记决定，而不是 JWT 中可伪造的机构字段或请求参数。
- `src/scoped-legacy-read-adapter.mjs` 将 `listMarketingChannels` 纳入严格模式已迁移的读取路由；每次请求继续验证经审核的 RSA 外部签名身份与当前员工数据库登录一一对应，使用 `BEGIN REPEATABLE READ READ ONLY`，只读取独立只读视图。然后复用原 M01 渠道树校验，拒绝跨机构父节点、循环与超数量。
- `web/app.js` 在严格模式下显示获客渠道导航并读取同一 GET；读失败立即清空先前渠道页面。仍不提供新增、编辑、删除、启用渠道、资金归因及营销外发。

**关键区别：** 这是一次隔离 CI 的受限视图接入，而不是正式数据库 `039` 迁移。没有生产数据库部署方案、正式数据角色授权或真实身份提供者联调证据。若没有安装 CI 专用视图，严格读取必须失败；不准退回机构级宽表读取。

## 2. 动态安全验收

`tests/security/m01-strict-channel-read.test.mjs` 在 PostgreSQL 16 真实测试账户上证明：

1. A/B 两位员工原始渠道表、财务分配与销售订单均无法直接 SELECT，也不能 UPDATE 渠道。
2. 新视图可看到已登记的同机构公共渠道，**不能看到另一机构的虚构渠道**。模拟签名 JWT 的错误 `org_id`、冒充经理角色或其他员工 ID 均无法扩展其权限。
3. 未经独立批准的签名身份得到 HTTP 403；批准后 A、B 均可读取本机构目录；交换或移除专用数据库连接池仍返回 403，且不会使用宽权限租户数据库兜底。
4. 人工插入跨机构父渠道引用，构建器返回 HTTP 500 的通用失败、无数据，不暴露其他机构渠道；撤销 A 的批准身份后旧 JWT 立即拒绝，B 仍可访问。
5. 既有 `tests/browser/strict-employee.spec.mjs` 扩展真实 Chromium 流程，证明员工严格模式下可见渠道页，渠道只读，A/B 的测试签名账号可以查看同机构渠道。

## 3. 对历史测试合同的必要修订

V3.2-51、V3.2-52 的阶段说明在当时标记严格员工渠道接口仍关闭。此版本已在**限定的 CI 隔离前提下**完成一个后续增量，所以本 PR 中旧版本合同测试的“仍关闭”断言已更新为要求：`migratedLegacyReads` 只能通过受限视图开启，隔离 OpenAPI 的 `x-strict-employee-mode-enabled=true`。历史清单仍记录各自阶段的当时范围；不以更新测试伪造历史审批。

## 4. 严格保留的项目边界

- 学生是主要管理单位；家庭只在核实兄弟姐妹时按需关联。渠道共享不代表学生、资金、销售负责人可以合并。
- 真正错绑且已有订单、收退款或履约记录，必须保持 `hold_active`。原订单、付款、SaleEvent、已上及已消课时记录不可覆盖或自动转归属。
- `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。所有 PR Draft，不合并、不部署。
- 16 项真实准入、R01—R10 仍未通过，财务与 CRM 外部 OpenAPI 仍 `proposed-unimplemented`。
- 保持既有数据库迁移 `001—038`，不创建 migration 039，不改 `edu-management-system`。
- 尚缺正式 M01 渠道编辑权限审批、运营变更审计、学生首次来源及本次商机渠道双口径归因，不能宣称 M01 全部完成。
