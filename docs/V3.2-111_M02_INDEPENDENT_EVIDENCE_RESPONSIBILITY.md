# V3.2-111｜M02 跨模块独立签署责任、历史证据与负向回执验收契约

## 基线与范围

基于 V3.2-110 Draft PR #117，HEAD `9cce8aa257e4f195bb7a340e3fc7a15ae39520d6`，两项 CI #43663447889（一次性 PostgreSQL 租约失效通知与负向回执）和 #43663447763（18 阶段集成审查）均 completed/success。其 CI-only 签名和审计事务是**本地模拟权威及真实临时 SQL 事务**，不能自动升级成销售、财务、教务真实授权。

本期目的不再增加“模拟交接成功”的业务能力，而是围绕 **V3.2-110 负向回执仍只代表阻断** 这一事实，确定真实来源应由谁提供、哪些事实由哪一方签署、员工撤权如何触发证据失效、哪些外部验收尚无责任人。当前所有真实人员均未指定。

## 六方证据责任矩阵

| 系统责任 | 拟议负责人 | 独立提供的真实只读证据 | 不能代签 |
|---|---|---|---|
| 市场销售 | 销售负责人（未指定） | 学生身份、原关联、异常单、订单/归因/SaleEvent 历史及修复后的关系差异 | 财务、教务 |
| 财务 | 财务负责人（未指定） | 原订单、应收、收款/退款、资金归属与独立签署/撤权；历史补偿记录 | 教务 |
| 教务 | 教务负责人（未指定） | 学生权益、课时及履约记录、调整原因和教务独立签署/撤权 | 财务 |
| 身份与安全 | 身份安全负责人（未指定） | 真实组织、角色、人员在岗与角色吊销、密钥托管、轮换、签署授权 | 各方业务事实 |
| 跨模块协调 | 集成负责人（未指定） | 来源版本向量、可信原子交接屏障、三方正式签收与原子回执 | 单方业务批准 |
| 数据与审计 | 数据库负责人（未指定） | 审计 checkpoint/通知/租约的受限写权限、可信持久审计、租户隔离与恢复证据 | 原订单与资金、课时的业务写入 |

每项真实签署必须由受其业务系统治理的独立来源确认人员身份及权限；临时 Ed25519 公钥、模拟在岗接口或一个拥有所有私钥的测试脚本，都不能被看成三方独立签字。

## 本期可执行 CI-only 复核契约

新增 `src/cross-module-independent-evidence-review.mjs`，通过 `createIsolatedIndependentEvidenceReview` 接受：

1. **V3.2-110 负向回执接口**：只允许 `BLOCKED_CI_LEASE_LOSS_AND_NEGATIVE_RECEIPT`。回执是 `uncertain`、不存在、假称成功、缺少拒绝权限字段或通知摘要时，立即拒绝。调用它可能会向**隔离审计账本**写入失效通知并撤销租约，绝不是纯无副作用的读操作。
2. **销售/财务/教务独立模拟证据**：分别固定不同测试 Ed25519 公钥及独立 signer_id；每份签名绑定机构、异常、学生主键、可选家庭主键、原历史摘要、领域业务证据摘要、来源修订/撤销序号、V3.2-110 通知摘要/序号、模拟时效及角色类型。签署证明的存在不能证明底层订单/收付款/课时事实是真实的。
3. **撤销状态与通知持久回读**：两次读取模拟角色撤权状态和 V3.2-110 通知 head + SQL 租约 revoked 状态。签名证据与撤销版本冲突、人员撤权、通知记录被改写或 SQL 租约重新显示 active 时，均 fail closed。当前撤权读取器只是**未认证的 CI 模拟接口**，并无真实身份系统授权或来源签名。
4. **业务历史的冻结规则**：三个证据必须绑定同一学生及同一历史摘要；家庭只在确有兄弟姐妹时按需关联，不允许由家庭自动覆盖学生身份。原订单、收款、SaleEvent、课时及补偿历史必须保留，后续只能用追加式补偿与审计更正而非原地改写。三个模拟系统签了同一个摘要不代表历史真实可信。

无论所有隔离证据是否一致，唯一“模拟当前”结论都叫 `BLOCKED_FIXTURE_INDEPENDENT_EVIDENCE_NOT_REAL_AUTHORITY`，仍返回 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。没有成功交接 API、真实批准开关或资金教务写权限。

## 回归及反例

`tests/security/v3-2-111-m02-independent-evidence-review.test.mjs` 新增 13 项对抗回归：正常三域隔离签署但拒绝交接；重复/交换公钥和代签；错误或缺失签署；不确定/虚假 V3.2-110 回执；通知摘要/序号/SQL 租约不一致；签署后撤权；两次检查之间的延迟撤权；通知持久状态被修改；错误学生或家庭关联；原历史摘要冲突；跨租户伪造放行字段；过期与篡改；以及任何模拟一致状态仍不得改变业务许可。

专属 CI 同时执行 V3.2-110 的真实一次性 PostgreSQL 负向回执回归、V3.2-109/108/107/106 数据库回归、V3.2-105 准入契约审查和十八阶段独立安全回归。测试通过仅说明当前代码库中签署协议、隔离审计与负向回执链的特定用例符合预期。

## 未满足的正式门禁

- V3.2-110 原始负向回执直接绑定的是机构和异常，**尚未以可信原子事务直接绑定学生主键**；V3.2-111 通过三方模拟证据再绑定学生，并不能填补这个正式合同缺口。
- 无可核验的真实财务/教务/销售人员授权、密钥根、不可抵赖的独立签署与即时撤权传播。
- 无经过各系统认可的原订单/付款/课时真实只读对账，也无来源之间的原子版本屏障、提交/回滚及真实三方联合交接回执。
- 最后一次撤权/签名读取之后仍可能发生新撤销；反复读取不是跨服务原子提交。
- 16 项外部准入和 R01—R10 仍未核验，六项真实外部财务/教务/对账/三方/交接权威均缺失；企业 PostgreSQL、Chromium、正式合同及三方 UAT 均未完成。

正式合同继续为 `proposed-unimplemented`，不能将 CI 模拟公钥、签名、职责矩阵或岗位名称解读为真实签字。机器规格 `spec/v3-2-111-m02-independent-evidence-responsibility.json` 逐项列明责任与缺口，所有负责人均为 `UNASSIGNED`。

本期没有新增生产迁移 039、没有接入生产服务或修改 `edu-management-system`，继续保持 Draft、不合并、不部署。市场销售技术文档单独维护，最终整合时再与现有 CRM 文档融合。
