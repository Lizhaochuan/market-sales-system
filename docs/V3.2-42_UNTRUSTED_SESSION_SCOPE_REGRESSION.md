# V3.2-42｜用户伪造会话字段不得突破数据库机构隔离（隔离动态回归）

> 本版本依赖 V3.2-41 Draft PR #48。这里只测试 **PostgreSQL 自定义 GUC / 会话上下文伪造**，不测试生产身份源、不接实际财务与 CRM。CI 必须针对本版本最新 HEAD 完整成功才能说“隔离动态回归通过”。

## 目的与信任边界

本系统中可信身份应来自 `SESSION_USER` 绑定的隔离数据库非所有者 LOGIN，不得采信外部客户端声称的 tenant、student、role、staff_id 或 `request.jwt.claims`。`V3.2-41` 已加入受限 LOGIN 反 `SET ROLE` 测试；V3.2-42 补充另一个角度：**即便攻击者可以在自己的连接设置普通自定义 GUC，也不能改变真实机构身份或读到另一机构的申请**。

| 验证 | 使用环境 | 期待结果 |
|---|---|---|
| `app.tenant_id`、`app.organization_id` | 虚构机构 A 的非所有者 LOGIN | 设置成虚构机构 B 后，`ms.current_scoped_organization_id()` 仍指向 A |
| `app.staff_id`、`app.role`、`request.jwt.claims` | A 模拟员工登录 | 当前 `session_user`、`current_user`、`ms.current_scoped_staff_id()` 不改变 |
| 查询 `ms.scoped_uat_preview_choices` | A 上下文中插入 B 的伪造 claims | 列表不可返回 B 机构已创建的虚构来源申请 |
| 调用 `ms.readonly_integration_uat_report(sourceB)` | A 带上述伪造 GUC | 必须拒绝，SQLSTATE `42501` |
| B 自己读取 `sourceB` | B 的原始非所有者 LOGIN | 返回 12 项只读阻断清单，三项生产执行/释放标志均 false |

测试在隔离数据库中创建一条虚构 B 来源申请，仅作权限验证；伪造 GUC 使用事务局部配置，并回滚事务。**不会修改原订单、真实付款或课时，不影响任何真实用户。**

## 保留的不可越过规则

1. 学生为主管理单位，家庭按需关联；同家庭不构成财务或课时转移凭据。
2. 真正错绑且已有订单、支付或履约下游的关联始终 `hold_active`；原订单、SaleEvent、收退款及课时历史不可覆盖。
3. `production_integration_allowed=false`、`execution_allowed=false`、`release_allowed=false`、`merge_authorized=false`、`deploy_authorized=false`。
4. 财务/CRM 合同是 `proposed-unimplemented`，16 项真实准入与 R01—R10 未通过；模拟测试成功不是生产安全认证。
5. 本期不新增 migration 039，不合并、不部署，不接真实财务/CRM，亦不修改 `edu-management-system`。

## 下一步

完整 CI 成功后可继续在隔离数据中覆盖“撤销后已建立连接/并发读取”以及权限缓存失效；但正式财务/CRM 账号撤销与安全 UAT 仍需要真实系统所有人独立授权，不得将本期证据变成生产放行。
