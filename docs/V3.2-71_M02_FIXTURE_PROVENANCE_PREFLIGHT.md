## 本期实现：仅离线虚构来源核对

`src/cross-module-fixture-provenance-preflight.mjs` 的 `createIsolatedProvenancePreflight` 在独立 Node 隔离测试中接收由测试运行器**带外注入**的 `getTrustedEvidenceSnapshot(organization_id, incident_id)`，而非接受客户端自己宣称已验真的来源列表。来源快照严格限定机构、事件、来源版本、SHA-256、`active/revoked` 和 `required`；逐条核对冻结包与候选来源的一致性，包含：

1. 使用 V3.2-70 的规范化包排序、固定字段序列和 SHA-256，对比当前冻结引用。冻结引用必须是现行版本，拒绝历史版本重放、过期来源版本、包正文替换和跨机构引用。
2. 拒绝同一来源事件重复、来源列表缺失或外部带外快照失效；拒绝来源撤销、事件版本不同、摘要不一致、机构/异常不匹配及来源整体修订号变化。
3. 已知为 `required=true` 的新来源事件不在冻结包内，必须拒绝；已撤销的必需事件也阻断，不允许通过删除数据假装全部通过。
4. 对一致的**虚构**数据，仅返回 `fixture_provenance_consistent=true` 和 `BLOCKED_EXTERNAL_AUTHORITIES_NOT_CONNECTED`，**不能**得出真实来源可信、合同签署、已收款或已完成教务对账的结论。

## 不得误认的权威边界

这里的 provider 不是生产来源连接器，`SHA-256` 证明候选字节一致，不证明来源真实性。V3.2-70 冻结注册仍为单进程内存，不具备持久唯一约束、跨实例事务、真实签名链、密钥吊销或权威来源反查。因此本期**不增加 HTTP 写入接口、不修改 SQL 或生产迁移，不触发真实跨部门交接**。

所有结果始终强制 `external_evidence_authenticity_verified=false`、`finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。任何失败都明确返回拒绝原因；外部不可信字段不得覆盖这些限制。

学生仍为主要管理单位，家庭按需关联。历史错绑如已产生订单、收付款、SaleEvent 或课时履约，保留原始历史；补偿只能以经过真实三方验收的追加记录推进，不能就地更改原单或解除隔离。16 项外部接入准入、R01—R10、销售独立审核、财务原流水与签名、教务核验和三方联合签收仍未完成。
