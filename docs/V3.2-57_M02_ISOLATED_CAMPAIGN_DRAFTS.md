# V3.2-57｜M02 市场活动草稿、渠道关联与计划预算保护

> 上游 V3.2-56 Draft PR #63 的 HEAD `e29eeb614912439dd48c3cf8165d658f8f6f51b1` 已通过 GitHub Actions #43594650394 `completed/success`。本版只适用于虚构机构和 CI 可销毁 PostgreSQL，不连接真实财务、教务或 CRM。

## 1. 新增隔离活动草稿（不是活动发布）

现有迁移 001 已包含 `ms.marketing_campaigns`（机构、活动名称、开始/结束时间、负责人、计划预算、活动状态）、`ms.campaign_channels`（活动—渠道）以及另行管理的营销费用和费用分摊。V3.2-57 在**不创建生产 migration 039** 的前提下，新增 CI-only `tests/sql/create_v3_2_57_isolated_campaign_drafts.sql`，建立两部分：

- `ms.scoped_isolated_campaign_drafts`：受 `SESSION_USER` 的机构/员工固定身份控制的只读视图。员工只能读取自己负责的草稿；当前有效销售主管可以读取所属机构员工草稿。仅投影活动 ID、名称、起止时间、负责人、**计划**预算（人民币分）、始终为 `draft` 的状态与渠道 ID 数组。最多 100 条，超限拒绝，不返回实际支出、线索、客户、订单、成交金额或财务成本。
- `ms.create_isolated_campaign_draft`：仅通过经签名核实员工的专用写入 LOGIN 和 SECURITY DEFINER 函数执行。负责人**由数据库绑定的员工身份决定**，HTTP 不允许提交负责人、机构、状态或实际费用字段；业务名称 2—100 字、合法可选起止日期、计划预算 0—100,000,000,000 分、关联 1—20 个不重复的本机构有效渠道。每条渠道的全部祖先均必须同机构且有效；跨机构、停用或继承停用、循环与超过 16 级全部拒绝。
- 并发防护：以员工+防重号锁定提交，再与渠道审批共用机构级 advisory lock，避免停用渠道与提交草稿竞态；防重号相同且内容相同只返回原草稿，内容不同拒绝（409）。保存成功只写入 `marketing_campaigns` 的 `status='draft'`、`campaign_channels`、隔离防重复台账和 `CAMPAIGN_DRAFT_CREATED` 审计事件。

**重要边界：** 该版本中预算属于“计划数”，不是预算审批结果。不会创建或更新 `ms.marketing_costs`、`ms.cost_allocations`、`ms.payment_allocations`、订单或收款；不会生成实际活动成本、CAC、ROI、招生归因，也没有草稿转为 `active` 的按钮或 API。活动启动、预算审批、费用核销、活动停用和负责人交接需要后续独立权限及跨部门验收，不能从本版推断已经放行。
