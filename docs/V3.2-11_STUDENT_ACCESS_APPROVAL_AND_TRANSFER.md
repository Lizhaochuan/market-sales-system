# V3.2-11｜客户转交、临时共享、授权到期和独立审批

**独立仓库**：`Lizhaochuan/market-sales-system`，基于 V3.2-10 PR #14 的待审代码。  
**状态**：仅隔离 PostgreSQL 16 / Node.js 22 / 虚构数据；**非生产、未合并、未接入真实 CRM**。  
**管理主单位**：学生。单个学生不创建无意义家庭；只有确实属于同一家庭的不同学生，才按核实结果关联家庭。共享某名学生不是授权访问其兄弟姐妹。

## 一、业务人员真正会看到的四种操作

| 中文业务操作 | 谁可以发起 | 是否需要独立审批 | 何时真正改变权限 |
|---|---|---|---|
| 临时共享某位学生 | 该学生当前负责人 | **需要另一位有效主管审批**，最多 30 天 | 审批通过后才能查看指定学生；到期自动不可见 |
| 正式转交某位学生负责人 | 该学生当前负责人 | **需要另一位有效主管审批** | 审批通过后才改变该名学生的负责人 |
| 撤销指定学生查看共享 | 当前负责人，或该项共享的被授权员工 | 低风险撤销可以立即执行，不需要等待第二次审批 | 撤销成功后立即对新查询生效 |
| 查询申请和查看授权 | 本人申请及主管待审、本人负责或获共享学生 | 只读，不改变任何业务事实 | 中文状态：待独立审批、已批准、已驳回、有效、已到期、已撤销 |

**独立主管约束**：审批人不能是申请人、该学生当前负责人或接收员工，并且必须在本机构拥有当前有效的主管角色。撤销主管角色或停用账号后，原有已登录令牌不能继续代替主管审批。

**高低风险区别**：授予他人儿童客户查看权、转交负责人均是需要第二人核实的高风险操作；缩小已经生效的单项查看权限可作为低风险立即撤销。这里的授权只涉及学生客户资料，绝不允许自动收款、退款、正式成交或修改 CRM 课时。

## 二、典型操作流程

1. 销售 A 负责学生甲。A 提出将学生甲**临时共享**给销售 B，并填写不超过 30 天的到期时间、中文原因和材料依据。
2. 在主管独立审核前，学生甲**不会**出现在 B 的授权学生列表。相同防重复编号与完全相同的申请只产生一条结果。
3. 与 A、B 都不同的有效主管审核，批准后 B 才能查看学生甲的必要字段。B 仍看不到学生甲的年级、私密家庭证明、其他销售的线索/商机或同一家长名下的其他孩子。
4. 到期后，无需后台定时任务，数据库每次查询会检查授权到期时间，B 将无法再看到学生甲。有效期内 A 或 B 均可撤销这条授权；记录留在审核历史。
5. 如果 A 申请**负责人转交**给 B，审批前学生甲仍由 A 负责；批准后负责人变为 B，版本递增，历史保存原负责人、新负责人及独立审核人。
6. 转交**不会**自动修改学生乙的负责人、共享家长的其他孩子、现有线索/商机销售归属、合同、金融收款或课时权益。需要另行确认其他对象的转交或业绩政策。

### 数据库权限

`ms_student_access_operator` 是仅可执行指定受保护数据库函数的业务角色。员工各用自己的数据库登录身份，机构与员工由管理员控制的登录映射决定。业务角色**不能直接**读取或修改学生基础表、家长联系人、审核申请/决定、财务订单或审计历史；访问由数据库函数根据有效员工身份、当前负责人和主管权限二次检查。

已批准审核记录、负责人变更记录和撤销事实被数据库触发器限制为不可修改/删除。普通业务账号无法绕过；**数据库超级用户仍然有高级权限**，因此正式生产需要额外异地审计留存、独立 DBA、备份/恢复及操作审计，不能宣称记录对超级用户不可篡改。

### 实际本机 API

- `GET /api/v1/student-access/requests`：中文申请状态及待独立审核事项。
- `POST /api/v1/student-access/requests`：提交 `share` 临时共享或 `transfer` 负责人转交的申请。
- `POST /api/v1/student-access/requests/{requestId}/decision`：独立主管批准或驳回，原子写入审批、授权/负责人变更和中文审计。
- `GET /api/v1/student-access/grants`：仅查看本人负责/本人被共享的授权，显示有效、到期和撤销状态。
- `POST /api/v1/student-access/grants/{grantId}/revoke`：负责人或被授权员工即时取消一项指定共享。

所有写入都需要防重复编号；签名有效但未绑定、未通过审批或已撤销身份的请求仍被拒绝。不接受客户端指定员工身份或机构编号来决定操作权限；无权查看的原始信息不能通过异常返回泄漏。

## 五、尚未解决的业务/生产阻断

1. **临时共享的续期、待审申请过期归档、客户转交争议处理**仍需完整工作流。当前续期须重新申请并再次独立审批；没有自动续期，也不允许单方面永久共享。历史项目可能保留无到期日的旧式授权，此次没有擅自删除旧资料或改变原有业务授权。
2. **主管团队级范围**仍没有完整政策；本阶段独立主管只获得审核职能，不自动获得所有儿童客户信息。
3. **单个机构员工数据库账号的正式开通、离职、证书轮换和灾难恢复**尚未接入真实 HR/IT 系统；本轮服务只能用测试密钥及本机隔离环境。
4. **现有销售写接口尚未全面迁移**。本轮新增的是受限授权写入，原学生、联系人、线索、商机创建、家庭核实与员工身份管理写入仍需逐项收紧权限。
5. **联系人隐私及家庭核实材料**只采用最小展示方案，真实手机号、微信号、身份材料的访问政策、留存及合规审批未完成。
6. **财务与 CRM 集成**：正式课程单价、真实部分付款、退款、成交业绩归因、开通/扣减/退回课时等高风险事项继续关闭，遵守低风险自动、高风险审批的既定原则。
7. **生产认证**：正式 IdP、OIDC 授权码+PKCE、MFA、动态机构数据库连接路由以及全面安全审核尚未完成。
