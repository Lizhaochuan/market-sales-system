## 功能：只允许原负责人修改尚未发布的草稿

V3.2-57 已实现创建活动草稿、计划预算、活动/渠道映射、受限员工身份和本人/主管只读投影。本期增加 `POST /api/v1/marketing-campaigns/drafts/{campaign_id}/revisions`：必须是同机构的**原活动负责人**、员工仍有效且严格 RSA 身份与专用数据库 LOGIN 当前授权一致，才能提交名称、计划起止日期、计划预算、关联有效渠道的修改。经理虽然能查看同机构草稿，却**不能直接修改他人的活动**，也不能通过伪造 JWT 角色或申请体转移负责人。

`tests/sql/create_v3_2_58_versioned_campaign_draft_revisions.sql` 是 **CI-only** SQL，创建隔离版本台账、修改请求防重复台账及 `ms.revise_isolated_campaign_draft` SECURITY DEFINER 函数。初始创建版本为 **1**；每个合法修改必须携带当前 `expected_version`。函数对该草稿行加锁，成功后 +1；如果另一个会话已经修改，旧版本请求返回 **409**，不会覆盖新值。相同防重复编号与相同内容重放只返回首次保存版本；同号改内容拒绝。每次成功修改在原有 `ms.audit_events` 写一笔 `CAMPAIGN_DRAFT_REVISED`，保留字段及渠道修改前后快照；**没有编辑或删除旧审计记录的功能**。

视图 `ms.scoped_isolated_campaign_drafts` 保留 V3.2-57 的机构/员工权限和 100 条上限，仅在原输出末尾增加 `version`。不授予任何受限员工对活动、渠道链接、版本台账或费用原表的直接更新权限。

## 仍被禁止的状态流转和预算操作

本版的 `status` **始终是 `draft`**。编辑仅是内部计划信息变更，不是活动审核，不允许 `active`、`approved`、`launched` 或正式投放状态；不开放改负责人、实际预算审批、广告投放、营销成本报销、`marketing_costs`、`cost_allocations`、`payment_allocations`、成交归因、学生归属或课时权益。每次修改渠道均核验当前机构，所有祖先均有效，拒绝跨机构、直接停用或继承停用、循环和过深层级。计划预算的所有数字仍为**人民币分**，不能被用作资金执行额度。

## 中文页面与双层验证

`web/index.html` 与 `web/app.js` 新增“修改我负责的活动草稿”卡片。只列出本人草稿并显示版本；修改表单从受限 GET 填充，提交显式携带当前版本。服务端无条件重新核对负责人和版本。读取或渠道目录失败清空旧选项并关闭编辑；退出清空版本、列表和表单选项。

扩展 `tests/security/m02-isolated-campaign-draft-api.test.mjs`，通过真实 PostgreSQL 和签名员工检验：初始 v1、本人修改后 v2、同号回放、同号不同请求 409、旧版本 409、主管改他人的草稿 403、跨机构/停用渠道、预算及日期错误 422；审计中 v1/v2 及预算的前后快照保持不变。原销售订单和财务表仍无读写授权，宽权限连接调用次数必须为 0。

扩展 `tests/browser/m01-channel-approval.spec.mjs`：从虚构渠道真实审批创建草稿后，在 Chromium 中文页面修改名称和预算，看到 v2，数据库仍 `draft`，经理只能查看不能编辑别人草稿，沿用原读取故障及登出清空测试。
