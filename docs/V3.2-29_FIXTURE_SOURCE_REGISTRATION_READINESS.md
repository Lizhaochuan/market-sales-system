# V3.2-29｜财务与 CRM 来源登记审批准备（仅虚构来源）

**阶段性质：隔离 PostgreSQL 模拟登记与权限验收；未完成真实来源审批、未获真实只读 API 权限。**
**基线：** V3.2-28 Draft PR #33，已验证提交 `d120beca17a67be0a2f0c356d7064ae6a6babdf3`。仅市场销售独立仓库，不修改原 CRM 代码及技术文档。

## 1. 来源登记基本规则

来源必须明确：所属机构、部门（财务或教务）、数据权威负责人、业务目的、最小只读字段、真实机构账套或 CRM tenant 映射、合同/监护必要依据、数据保留与删除政策、签名和密钥的发行/撤销人、来源修订版本和完整水位。以上**真实属性仍需业务和安全负责人独立签字，并且不能由销售单方面确定**。

本版本只允许以 `fictional_` 开头的虚构来源别名和虚构 tenant 别名，记录**模拟准备状态**；不存真实网址、银行卡、API token、证书私钥或实际儿童数据。没有生产凭证发放、外部连接器或实际账务/课程读取。

## 2. 权限分离和不可改历史

迁移 `032_fixture_source_registration_readiness.sql` 建立：
- `ms.source_readiness_requests`：财务/教务本机构具有相应角色的员工，提出仅包含虚构来源名称、机构租户别名、中文读取目的和虚构证据引用的申请。
- `ms.source_readiness_reviews`：业务审核须由同一领域**另一名**有效人员签署；安全审核由独立的 `source_security_reviewer` 签署。申请人不可审批自己，任何同一自然人不能同时署两个审核部门。
- 审核仅有 `fixture_ready`（虚构测试准备合格）、`return_for_revision`（退回）、`rejected`（拒绝），**没有“生产来源已批准”**。
- 新申请、新审批均只追加，禁止 UPDATE/DELETE；相同操作编号相同内容幂等，不同内容冲突拒绝。
- `scoped_fixture_source_readiness` 只提供本机构受限可见的简要状态：即使两人都通过，`production_source_approved=false`、`credentials_approved=false`、`real_readonly_connection_enabled=false`、`execution_allowed=false`、`release_allowed=false`。
- 专用数据库角色只拥有受限函数的 EXECUTE 和最低权限只读状态视图，不得直接读写登记原表或销售订单、支付分配、CRM 课时表。真实人员身份继续由 SESSION_USER 可信映射，不信调用方自报身份。
- 新增模拟安全员工 `ms_fixture_source_security`；不是生产信息安全凭证或财务/教务账户。

## 3. 正式接口的必备审批清单

| 关口 | 财务权威来源 | 教务/CRM 权威来源 | 本期 |
|---|---|---|---|
| 实际系统身份 | 收款/退款/拒付/分配的唯一权威 | 课程、实际消课和剩余权益的唯一权威 | 未核定 |
| 机构映射 | 合同签约主体、账套、订单分配用途 | institution、student_id、package_id 及 tenant | 未核定 |
| 独立业务审批 | 财务负责人＋合同责任人 | 教务负责人＋CRM 系统所有人 | 仅虚构角色测试 |
| 安全审批 | 来源证书、受众、密钥轮换和撤销 | 同左及学生信息最小化 | 仅虚构角色测试 |
| 只读授权 | 真实最小权限服务账号，明确禁止退款或资金调整 | 真实最小权限服务账号，禁止发课、扣课和更新包 | 未取得 |
| 版本完整性 | 经济事件唯一键、付款、退款、拒付和水位 | 实授、消课、课包和独立水位 | 仅模拟验证 |
| 运行恢复 | 持久化幂等、断线重试与遗漏核对 | 超时 unknown、不可换键重复发课 | 尚无生产实现 |
| 交叉验收 | 财务、教务、安全、销售同时验收异常 | 同左 | 未发生 |

## 4. 不可突破的边界

V3.2-24—28 的隔离、不可变历史、三方审批、补偿拟议记录和只读权威候选保护继续有效。**模拟来源审核通过，不得解释为可以执行补偿**；尤其不能修改旧订单学生、付款用途、真实退款、CRM 权益或 `hold_active`。学生是基础管理单位，同一家庭第二名学生只能按需关联，绝不自动共用付款、合同与课时。
