# V3.2-35｜UAT 虚构证据的单向审计冻结、权限撤销及一致性保护

**交付属性**：仅独立市场销售系统的本机/CI 隔离虚构演练。真实财务、教务 CRM 权威来源从未接入；不修改原 edu-management-system、真实学生或付款/课时。

**已验收基线**：V3.2-34 Draft PR #41；HEAD `e4165f18d4b4dd0a11311cc11565ec23c63905cb`。原数据库迁移 001—037、订单/资金/履约/错误关联隔离安全规则全部保留。

## 1. 冻结不是验收通过

本阶段的 `freeze` **只表示某个虚构来源的 UAT 证据引用历史不可再增加或撤销**，不表示真实外部来源已经授权、合同主体已修正、资金或课包已经对账完成。完整生命周期仍然固定：
- `production_integration_allowed=false`
- `execution_allowed=false`
- `release_allowed=false`

真实错误学生关联的案件若已经生成订单、收款或履约记录，仍维持旧版本规定的 `hold_active`，未经跨模块验收不得修改原订单、款项用途、SaleEvent、课包消课或解除隔离。以学生为主要管理单位，家庭仅按实际多学生需要关联，不自动共用资金或课时。

## 2. PostgreSQL 038：安全独立冻结

文件 `db/migrations/038_fixture_uat_security_freeze_and_consistent_export.sql`：

- 新表 `ms.fixture_uat_source_freezes`：每份虚构来源申请只允许一次单向冻结。记录冻结当时最新审计版本、测试冻结原因、虚构证据引用、独立安全审核人及时间。原记录只追加，不可 UPDATE/DELETE；**本期没有解冻函数**。
- `ms.freeze_fixture_uat_source`：只有真实受限数据库身份对应的本机构 `source_security_reviewer` 才有权执行。禁止普通财务/教务/销售写入角色、UAT 页面、其他机构、安全人员本人是该来源申请人时执行冻结。相同操作键和完全相同内容幂等；重复冻结但更换原因/操作键拒绝。
- `ms.guard_fixture_uat_append_freeze`：原 `fixture_uat_evidence_events` 表的 INSERT 冻结检查。与新增和撤销函数共同对来源申请行取得 `FOR UPDATE` 锁。即使并发请求先后到达，**冻结提交后的任何新增/撤销均拒绝**，不会留下断开的版本号或冻结水位。
- 冻结表启用 RLS，禁止 UAT 登录账号读取原表。无支付、订单、CRM 课时读写权限或解除隔离角色授予。
- `ms.readonly_fixture_uat_freeze_state`：保留原有员工/机构授权，返回当前版本、冻结状态、冻结水位和固定禁止执行状态；不返回密钥、员工姓名、合同或外部资金数据。
- `ms.readonly_fixture_uat_diff_guarded`：导出时在**同一数据库语句的稳定快照**内验证预览时的期望最高版本。如果当前已经有新事件或冻结水位异常，拒绝旧预览导出，而不是凭浏览器端一次较早的查询宣称一致。

## 3. API、中文页面和受限导出

沿用 V3.2-33、34 的独立 localhost-only 服务和最小数据库只读 LOGIN。本期补充：

| 只读接口 | 作用 |
|---|---|
| `GET /api/v1/uat-preview/reports/:uuid/freeze-state` | 已签名员工身份+机构权限下，查看是否单向冻结、冻结版本 |
| `GET /api/v1/uat-preview/reports/:uuid/history` | 默认仅显示最新 200 条，早期历史仍可用指定区间查询 |
| `GET /api/v1/uat-preview/reports/:uuid/diff/:from/:to` | 连续指定版本的只读差异；超过 200 条被拒绝 |
| `GET /api/v1/uat-preview/reports/:uuid/diff/:from/:to/markdown` | **必须**提供形如 `If-Match: "17"` 的预览版本，服务器在同一数据库快照里重新校验 |

若未提交版本条件，返回 428；版本已变化或冻结一致性校验失败时返回 412。身份不匹配、员工绑定撤销、跨机构访问继续返回 403。**所有接口仅 GET**，不会建立审批、写业务记录、真正解冻或发课付款的操作路由。

浏览器本次增加“历史已单向冻结”的中文提示。导出仍重新核查员工签名与来源权限，既不会持久保存令牌，也不会把冻结当作真实业务授权。

## 4. 必须通过的反面验收

1. 财务、教务、销售、UAT 预览账号、机构 B 不能冻结机构 A；只有本机构独立安全审核员允许冻结。
2. 安全审核员模拟被撤销原审核角色后，新的冻结申请必须立即被数据库拒绝；恢复测试角色只为保持后续独立隔离回归，不涉及真实员工权限变更。
3. 一份虚构来源新增两条引用以后，旧期望版本 1 的导出必须失败；正确版本 2 的快照允许导出，但状态仍然禁止真实联调。
4. 冻结前有有效引用时，冻结记录保留精确水位；冻结以后新增和撤销、二次冻结或改写冻结历史均被拒绝。
5. 并发模拟审核写入与安全冻结争用同一来源锁；允许冻结前完整提交的事件，但冻结后不得出现新的提交，历史序号必须连续。
6. 单来源创建 205 条虚构引用，要求一次查询 205 条时明确拒绝；按 100 条窗口查询早期和末期版本均成功，不能截断旧历史，也不能跨机构泄露。
7. 浏览器真实 Chromium 核对冻结状态和历史，审计导出需含正确 If-Match、旧预览失败、手机窄屏和本地存储为空。
8. 完整 PostgreSQL 001—038、非所有者真实数据库 LOGIN、安全 Node、既有及新增 Chromium 中文页面和 V3.1 合同回归。

## 5. 使用注意事项及后续

这只是**虚构 UAT 证据引用**的冻结，不能作为真实合同、支付、退款或教务课时的法定审计留存证明。正式来源证书、只读服务账号、机构账套映射和业务四方审批仍由真实负责人负责，不能因本阶段 CI 全绿而跳过。

建议 V3.2-36 转入**跨模块纠错总览与版本交接清单**：整理 V3.2-24—35 的批准/阻断链、业务责任矩阵、接口依赖及尚未获得真实来源的事项，供实施团队后续在正式授权条件下逐项执行。
