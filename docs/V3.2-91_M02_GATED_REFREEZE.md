## 本阶段 CI-only 实现
新增 `src/cross-module-gated-refreeze.mjs`。读取 V3.2-90 当前失效分类计划，基于其旧冻结摘要、当前来源水位摘要、复核比较摘要及失效类别生成唯一计划指纹。四项内部复核必须分别完成：
1. 来源与撤销水位重新核对（销售协调）；
2. 证据差异与逐项复核重建（销售协调）；
3. 三域恢复一致性与独立重新确认（销售协调）；
4. 六类真实外部授权缺口重新确认**仍然缺失**（财务内部检查角色，不构成真实财务批准）。

每项按 `start → complete` 顺序记录，且测试中的完成者须与开始者不同、带外身份绑定同机构且仍有效。来源、撤销或任务版本变化导致当前计划指纹变化后，所有旧完成记录只保留历史，不作为新计划完成结论。复核人撤权、伪造授权、同键改写、缺失任务、异常依赖全部 fail closed。

新冻结只能通过**显式调用** `requestFixtureRefreeze`，在所有四项检查仍然有效时，重新取计划状态并调用 V3.2-89 的离线冻结适配器。新冻结必须使用新幂等键；成功也只能返回 `BLOCKED_NEW_FIXTURE_FREEZE_NOT_REAL_HANDOFF`、`fixture_refreeze_recorded=true`，绝不返回真实可交接权限。没有自动生成、后台调度或真实生产写入。
