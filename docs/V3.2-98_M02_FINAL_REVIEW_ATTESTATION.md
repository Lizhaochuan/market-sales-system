## 隔离实现
新增 `src/cross-module-final-review-attestation.mjs`，直接依赖 V3.2-97 `verify/audit`（安全测试使用真实 V3.2-97 类实例，而非仅返回虚构的成功布尔值），并从独立 CI 适配器获取人员身份/权限和单调测试时间。执行以下五个有序操作：

1. `apply` — 销售提出内部签收申请。
2. `review_sales` — 其他销售人员独立审核。
3. `review_finance` — 财务人员独立审核。
4. `review_academic` — 教务人员独立审核。
5. `acknowledge` — 另一名销售人员记录**行政签收**。

同一轮的五个参与者必须互不相同；每一步校验机构、人员角色、在岗状态，并在写入内存事件之前重新验证 V3.2-97 的**当前最新快照**。签收必须绑定 `snapshot_digest` 与快照的交接输入摘要；快照中包含恢复结论事件摘要、到期时间、来源版本、撤销水位、异常代数、复核任务与六项外部缺口。不存在“由申请人自己签收”的旁路。

每项测试事件仅追加到同机构/异常的 CI 内存历史中，包含前驱 SHA-256 摘要、连续序号、人员、角色、动作、快照摘要、时间及固定业务隔离状态。重复请求只作为历史重放；同一幂等键换内容拒绝。旧快照被替代、证据/任务变化、恢复结论到期/撤销、人员撤权或来源失效时，不能继续签收或将旧记录解释为当前有效；保留旧历史供核查。

即使五项内审完成，`report` 也仅可能返回 `BLOCKED_CI_ATTESTATION_COMPLETE_NO_EXTERNAL_AUTHORITY` 和 `fixture_acknowledgement_current=true`。这两个值只表示测试快照与行政流程当前一致，**不代表真实财务签名、教务签名、三方验收、合同签署、法律电子签名、跨模块交接授权或解除隔离**。
