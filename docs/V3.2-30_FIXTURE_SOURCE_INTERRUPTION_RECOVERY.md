# V3.2-30｜只读来源中断、缺页、重放和人工安全复核

**范围：** 独立市场销售仓库的虚构测试，不是生产财务/CRM 数据接入或真正故障恢复。
**基础：** V3.2-29 来源登记准备 Draft PR #34，V3.2-28 虚构 Ed25519 来源模拟。保留 V3.2-24—29 错绑学生的 `hold_active` 隔离。

## 1. 业务规则

任何财务或 CRM 来源的超时、500、来源撤销、签名错误、消息重复但内容不同、版本水位下降、页码断层、租户不一致，都不得被当作“没有收款”“没有发课”或“纠错完成”。如有未确认结果，维持隔离，安排独立人工核对；不得重试创建新支付、退款或 CRM 课包。

## 2. 新增数据结构

迁移 `033_fixture_source_recovery_incidents.sql` 引入：

- `fixture_source_recovery_incidents`：由本机构对应领域的模拟财务或教务员工登记来源超时、缺页、序号缺失、水位回退、签名错误、来源撤销、机构不匹配及重复内容冲突，保留观察时的序号/水位、原因和证据引用。
- `fixture_source_recovery_reviews`：原报告人禁止自审；领域业务复核必须由同部门另一人进行；安全调查和模拟重放核对必须由独立信息安全角色进行。每个类别只允许一次不可变决定，一人不能在同一事件冒充不同审核类别。
- `scoped_fixture_source_recovery`：本机构最小必要信息，始终呈现“继续隔离、人工复核”；`production_source_restored=false`、`true_external_reconciliation=false`、`execution_allowed=false`、`release_allowed=false`。
- 专用 `ms_fixture_recovery_writer`：只具有两项安全记录函数的执行权，没有对原订单、资金、合同或 CRM 课时的 SELECT/UPDATE/DELETE 权限。
- 历史全部追加，不允许 UPDATE/DELETE；重复同编号同内容返回原记录，改动旧编号的内容拒绝。

## 3. 故障恢复工作流的最低准入

1. **发现：** 对单来源机构/领域和记录序号登记虚构异常，明示当前结果“未知”。
2. **隔离：** 对应真实纠错案件维持 `hold_active`，不能因恢复任务、负责人操作或已存在虚构来源签名而开放。
3. **领域复核：** 财务确认款项应查询外部唯一经济事件，教务确认课包、已消、余额和源请求幂等键；当前不具备真实权威读取接口，只能留下待办。
4. **信息安全复核：** 确认来源密钥是否被撤销、来源机构/租户、版本水位、签名及断页问题；任何假设性补页不能作为实际执行回执。
5. **正式恢复前置条件：** 两方真实授权来源、稳定高水位、完整消息链、原业务对象版本一致、金额守恒/权益守恒、无未知结果和三方执行后复核；当前全部未实现。
6. **最终处理：** 本期不存在“恢复成功”“纠错已执行”“允许解除隔离”的状态与函数。只有模拟安全复核事件，不生成真实支付、退款、重开订单或发课行为。

## 4. 测试与验收

需基于本 PR 最新 HEAD 执行 PostgreSQL **001—033**、真实非所有者模拟 DB LOGIN、两机构隔离、源重复/异常负例、报告人自审拒绝、跨部门/跨机构拒绝、不可变历史、Node 全量业务回归、旧 Chromium 中文界面和 V3.1 合同回归。

没有新增正式来源恢复业务 UI；旧 UI 回归不代表已开发新的来源控制台。
