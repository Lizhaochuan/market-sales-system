## 本期隔离实现
`src/cross-module-blocker-triage.mjs` 基于 V3.2-83 `audit.verify` 和 `audit.audit` 从带外测试审计获取机构、异常、审计序号和记录摘要，校验哈希链与具体记录一致，绝不从调用方自行宣布“已审批”的字段取得授权。

- 从 V3.2-83 原始 gate_reason_code 派生分类与责任：财务证据问题交财务，教务/课时问题交教务，来源版本漂移及外部交接授权问题交销售；其他跨模块原因先由销售协调。类别与责任均是测试工单归属，不构成业务授权。
- 异常流程只允许 `open → in_review → closed_administratively` 的单向顺序，人员由独立的测试身份服务核对机构、在岗与部门角色，最终关闭者必须与前一步处理人不同。
- 每个工单事件严格绑定源审计记录摘要和来源修订，生成连续哈希的只追加状态历史；相同幂等键同正文返回“历史重放”阻断消息，换正文拒绝；错机构、错审计摘要、非法跳转、人员撤权均拒绝。
- 源修订变化后，旧异常报告变为 `stale_source_reopen_required`，禁止把过期工单关闭状态视作当前处理完成。原事件历史保留，需对新审计快照重新创建对应工单。
- **行政工单关闭只代表内部跟进已结束**，不代表真实跨系统问题修复、资金结算、教务确认、交接批准或解除隔离。所有返回均固定 `hold_active=true`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`。
