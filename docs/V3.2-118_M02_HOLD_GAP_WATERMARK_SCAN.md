# V3.2-118｜M02 HOLD 完整事件缺口扫描与单调水位（隔离测试）

## 上游基线与原则

上游 V3.2-117 Draft PR #124，HEAD `cbc615a8f654121af7ba57332e6f6ae4f5240408`；真实一次性 PostgreSQL CI #43667559639 和聚合安全 CI #43667559449 已完成且通过。

V3.2-115 建立测试 HOLD 事件；V3.2-116 分开建立 outbox 和负向回执；V3.2-117 能对某一条消息分类。**V3.2-118 解决跨整段历史的潜在错判：最新一条回执齐全，不等于第 1 条、第 2 条等旧事件也齐全。** 只有严格从第一条开始连续存在的消息或负向回执才可以提高对应水位。

本阶段仍只适用 GitHub Actions 一次性 `postgres:16`，并非实时生产扫描服务，不接通真实外部网络、财务、教务或组织身份源。

## 三个水位及逐条缺口

| 字段 | 含义 | 禁止误读 |
|---|---|---|
| `checked_through` | 已检查完整 V115 HOLD 哈希链截至第 N 条 | 不是已投递 N 条 |
| `outbox_prefix` | 从第 1 条起连续存在、元数据验证成功的 V116 outbox 数 | 后面的孤立 outbox 不能跳过旧缺口 |
| `negative_receipt_prefix` | 从第 1 条起连续存在且绑定消息的**负向测试回执**数 | 不等于外部已经批准或解除 HOLD |

每个缺项必须包含原始 HOLD 序号、原因、对应历史事件摘要、可选 outbox 消息摘要，原因只有 `OUTBOX_MISSING`、`NEGATIVE_RECEIPT_PENDING`、`NEGATIVE_RECEIPT_OVERDUE`。后续负向回执补齐时，必须生成新审计快照，**旧缺项仍作为历史留存**。60 秒阈值只是一次性测试配置，不是实际 SLA，也不能证明网络已经丢包。

若存在 1、2 两个 HOLD，只有第 2 条消息和负向回执，即使第 2 条完全可验证，`outbox_prefix=0`、`negative_receipt_prefix=0`，第 1 条仍为 `OUTBOX_MISSING`。若 1、2 的 outbox 完整，但第 1 条回执缺失且第 2 条存在，则 `outbox_prefix=2`、`negative_receipt_prefix=0`，第 1 条仍须保留缺项。若前两条负向测试回执全部存在，连续水位可以达到 2，**但业务仍完全阻断**。

## 实现范围

- `src/cross-module-hold-gap-watermark-scan.mjs` 的 `computeIsolatedHoldGapReport` 为确定性、无副作用的完整事件链和连续前缀校验，`createIsolatedHoldGapScanner` 提供 `scan`、`inspect`。完整核对 V115 所有 HOLD 事件前摘要、最新 head、V116 outbox 消息摘要重新计算、负向回执格式和消息关联。不能仅取数据库的最大 sequence 冒充连续成功。
- `tests/helpers/v3-2-118-m02-postgres-hold-gap-scan.mjs` 在单笔 `SERIALIZABLE` SQL 事务中读取同一个数据库快照，并在同一事务中追加扫描事件、单调推进 head；数据库锁限制机构、异常和学生作用域。COMMIT 后分别回读扫描事件及当前来源快照，发生变化则返回 `BLOCKED_GAP_SCAN_SNAPSHOT_CHANGED`。
- `tests/fixtures/v3-2-118-m02-hold-gap-scan.sql` 创建 `fixture_hold_gap_scan_events`（只追加，包含整个缺项列表及前链摘要）和 `fixture_hold_gap_scan_heads`。SQL `BEFORE UPDATE` 触发器禁止扫描版本、已检查范围、消息连续前缀或负向回执前缀回退；`hold_active` 只能为 true。机构 A、B 均使用 `FORCE ROW LEVEL SECURITY`，事件表写入角色仅限 SELECT/INSERT。
- `scripts/v3-2-118-setup-hold-gap-scan.mjs` 校验数据库必须为 `v106_isolated`，并要求 `V106_ISOLATED_PG=YES_TEST_ONLY`。这不是生产迁移 039。
- 扫描不产生任何正向收据、自动补发任务、网络发送、解除暂停或业务审批。接口的每一种结果均包含 `hold_active=true`、`handoff_allowed=false`、`finance_authorized=false`、`academic_authorized=false`、`release_eligible=false`。

## 仍不可宣称的能力

HOLD、outbox、V117 单条对账与 V118 整段扫描是**不同的本地数据库事务**，尚无生产事件监听、自动补发、网络传输、正式业务接收人、外部签名信任根、跨服务因果屏障或真实原子交接。测试使用的负向回执只代表本地模拟接收记录；完整连续水位不能证明真实对方系统收到了每一条信息。真实可信签署者与密钥托管、真实财务/教务对账及独立审批仍未获得。

六方真实业务负责人继续 `UNASSIGNED`，16 项外部准入、R01—R10、六类外部权威、企业 PostgreSQL、Chromium、正式合同与三方 UAT 均未通过；合同 `proposed-unimplemented`。所有业务放行/财务/教务/补偿权限继续关闭、`hold_active=true`。学生是主要管理单位，家庭只有在真实兄弟姐妹关系存在时按需关联；不修改原订单、收付款、SaleEvent、课时和补偿历史。

保持 Draft、不合并、不部署，不修改 `edu-management-system`、生产数据库及主 CRM 文档，市场销售板块技术说明继续独立保存。
