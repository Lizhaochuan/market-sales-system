# 市场销售端整体优化与开发任务书 V3.4（完整版）

## 一、项目背景及开发边界

### 1.1 项目基础

项目仓库：

https://github.com/Lizhaochuan/market-sales-system

现有开发基础：

PR #129：简洁 Lead 销售工作台

原有业务模块：M01—M14。

本次开发必须建立在现有市场销售端项目基础上，不允许脱离原有实现重新开发一套系统。

开始前，先读取最新代码、需求文档、测试以及 PR #129 的实际状态，确认最新分支和已有功能。

### 1.2 项目目标

建立一套符合教育培训机构真实招生流程的市场销售系统。

主要业务路径：

获取潜在学生 → 线上联系 → 了解学习需求 → 邀约家长线下面谈 → 完成线下面谈 → 介绍课程和价格 → 预约试听 → 试听回访 → 确认报名意向 → 办理报名 → 首笔收款确认 → 报名成功 → 继续处理未完成事项 → Closed Won。

如果客户明确不再继续，可以按规则进入 Closed Lost。

这条路径只是常见业务过程，不是强制顺序。

允许：

- 线上沟通后直接报名。
- 家长主动到校。
- 不试听直接报名。
- 多次线上沟通。
- 多次线下面谈。
- 多次预约或试听。
- 家长暂缓后恢复跟进。
- 同一学生拥有多个课程意向。
- 同一学生进行多笔课程报名。

### 1.3 最重要的业务原则

**任何未正式结案的有效 Lead，都必须有明确的后续动作，直至 Closed Won 或 Closed Lost。**

后续动作必须明确：

- 下一步做什么。
- 通过什么方式。
- 什么时候执行。
- 由谁负责。

不能只记录“等待回复”“稍后联系”“换个方式联系”，然后没有进一步安排。

### 1.4 当前开发边界

严格遵守以下要求：

1. 仅修改独立市场销售端。
2. 不修改原 CRM 项目。
3. 不修改 `edu-management-system`。
4. 不开发市场销售端与原 CRM 的接口。
5. 不实施跨系统数据同步。
6. 不因未来 CRM 集成而限制当前销售端功能。
7. 保留已有权限、隔离、审批及审计设计。
8. 保留 M01—M14 中已确定且与本次规则不冲突的内容。
9. 不自行合并 PR 或部署生产环境。
10. 保持既有 Draft / HOLD / CI-only 安全边界。

市场销售端业务规则全部确定后，才另行讨论 CRM 对接。

# 二、市场销售业务流程整体设计

## 2.1 区分三个不同概念

系统必须区分：

**第一：本次沟通结果**

回答：这一次联系发生了什么？

例如：

- 无人接听。
- 已发送消息待回复。
- 已完成沟通。

**第二：当前销售进展**

回答：学生目前推进到什么程度？

例如：

- 需求已确认。
- 课程及价格已介绍。
- 已预约试听。
- 有报名意向。

**第三：下一步跟进动作**

回答：销售接下来要做什么？

例如：

- 明天再次电话联系。
- 周五微信确认到校时间。
- 周六家长到校面谈。
- 试听结束后回访。
- 下周确认报名协议。

这三个概念不得合并到同一个字段。

一次联系失败不会自动改变客户原有销售进展。

# 三、M05：沟通记录完整改进

## 3.1 沟通方式

采用两级分类。

### 一级：线上沟通

具体方式：

- 微信文字
- 微信语音
- 电话
- 视频通话
- 其他线上方式

### 一级：线下沟通

具体方式：

- 家长到校面谈
- 销售外出面谈
- 线下活动接触
- 其他线下方式

要求：

1. 保存沟通一级分类和具体方式。
2. 沟通方式不能覆盖原始获客渠道。
3. 不同沟通方式显示不同结果选项。
4. 保留历史沟通记录。
5. 已有旧数据不能凭空推断或随意改写。

## 3.2 本次沟通结果

一级结果建议为：

1. 未联系成功
2. 已发送消息待回复
3. 已完成沟通
4. 其他

其中，“未联系成功”根据联系方式展开具体原因。

### 电话、微信语音

- 无人接听
- 被拒接
- 无法接通
- 联系方式无效
- 其他

### 微信文字

- 消息发送失败
- 无法联系对方
- 其他

微信文字“消息发送成功但尚未回复”应归入“待回复”，而不是联系失败。

### 视频沟通

- 无人接听
- 连接失败
- 对方取消
- 其他

### 线下面谈

应记录实际到场与面谈完成情况。

未到场不应被当作一次已完成面谈。

# 四、核心规则：销售跟进链条不可中断

这是本次最高优先级的业务规则。

## 4.1 基本要求

只要 Lead 尚未进入 Closed Won 或 Closed Lost，就必须存在有效的下一步跟进安排。

允许有多项待办，但必须能够明确识别下一项主要动作。

每次跟进结束时，系统必须：

1. 保存本次实际结果。
2. 判断是否已经正式结案。
3. 未结案则要求确定下一步动作。
4. 创建或关联下一步待办。
5. 更新 Lead 的下一步展示信息。
6. 保留完整操作历史。

没有合法下一步安排时，不允许把本次待办标记为“已完成且无需继续”。

允许保存未完成的记录草稿，但草稿不得代替正式完成跟进。

## 4.2 场景 A：电话无人接听

销售选择：

本次沟通方式：电话。

本次沟通结果：未联系成功。

原因：无人接听。

系统立即展开：

**下一步怎么办？**

- 再次电话联系。
- 改用微信文字。
- 改用微信语音。
- 改用其他联系方式。

选择“再次电话联系”后，必须继续填写：

- 下次拨打日期。
- 下次拨打时间。
- 下次跟进事项。

选择“改用微信文字”后，也必须继续填写：

- 下次微信联系日期。
- 下次联系时间。
- 下次联系事项。

例如：

本次：11月17日电话无人接听。

下一步：11月18日10:00微信联系家长，询问是否方便安排线下面谈。

保存后：

- 追加本次电话记录。
- 生成11月18日的微信跟进待办。
- 原销售阶段保持不变。

**不能只保存“改用微信联系”，却没有具体联系时间。**

## 4.3 场景 B：微信已发送，家长未回复

本次结果：

已发送消息待回复。

下一步可选：

- 到期检查回复。
- 到期主动再次询问。
- 到期改用电话。
- 到期改用微信语音。

无论选择哪一种，必须设置日期、时间和具体事项。

例如：

11月17日发送微信，邀请家长到校。

家长尚未回复。

系统安排：

11月19日14:00检查回复情况；如仍未回复，再次发送微信询问。

到期后销售可以：

- 记录家长已回复。
- 再次联系。
- 改用电话。
- 合法关闭销售机会。

只要未结案，仍须生成后续动作。

不能无限期停留在“待回复”。

## 4.4 场景 C：线上沟通成功，但未约到线下面谈

本次：

电话沟通完成。

已了解家长需求。

家长表示本周没有时间到校。

销售选择：

邀约结果：暂时不方便。

系统要求安排：

- 下次联系时间。
- 下次联系方式。
- 下次邀约事项。

例如：

下周一19:00通过微信再次确认家长可到校时间。

保存后生成下一次邀约待办。

不能因为“家长暂时没有时间”就中断跟进。

## 4.5 场景 D：家长愿意到校，但时间未定

本次邀约结果：

家长愿意面谈，时间尚未确定。

下一步：

确认到校日期。

例如：

11月18日18:00电话联系，确定周末到校时间。

此时不能提前将预约状态标记为“已确认”。

必须等具体时间确定后再创建或确认正式面谈预约。

## 4.6 场景 E：已经确定线下面谈时间

例如：

11月21日14:00家长到校面谈。

此时系统应：

1. 保存线上沟通记录。
2. 保存邀约结果。
3. 创建线下面谈预约。
4. 把这次面谈作为下一步活动。
5. 按需要创建到访前确认提醒。

已有有效面谈预约可以满足“下一步跟进安排”的要求，不必重复创建同一时间、同一目的的普通跟进任务。

面谈结束后必须继续判断下一步：

- 安排试听。
- 再次面谈。
- 跟进课程方案。
- 跟进报名。
- 正式结案。

不能完成面谈后没有下一步动作。

## 4.7 场景 F：家长未到场

面谈当天，家长没有到校。

销售选择：

未到场。

然后选择：

- 联系家长重新预约。
- 改用电话了解原因。
- 微信询问是否需要改期。
- 家长明确拒绝后按规则申请结案。

如果选择重新预约，必须录入新的预约时间或确认预约时间的跟进日期。

原预约保留未到场事实。

不能把未到场直接视作客户流失。

## 4.8 场景 G：试听已完成

销售记录：

试听已完成。

下一步可选：

- 回访家长试听感受。
- 介绍正式课程方案。
- 跟进课程报价。
- 确认报名意向。
- 办理报名。
- 根据明确拒绝原因结案。

例如：

11月22日试听完成。

11月23日19:00电话回访家长，了解试听感受。

系统生成对应待办。

不能因为试听完成就自动结束销售跟进。

## 4.9 场景 H：家长暂缓

家长表示：

最近太忙，下个月再考虑。

销售阶段可以设置为：

暂缓。

但必须同时设置：

- 暂缓原因。
- 下次重新联系日期。
- 跟进方式。
- 跟进负责人。
- 下次具体事项。

例如：

12月10日电话回访，确认是否恢复报名计划。

**暂缓不是终止状态。**

暂缓期间的后续待办仍需保留和提醒。

## 4.10 场景 I：多次联系没有回复

系统应累计联系历史，显示：

- 联系日期。
- 联系方式。
- 联系结果。
- 连续未联系成功次数。
- 当前待办。

可以设置主管提醒。

但不能仅因联系次数达到某个数字，就自动 Closed Lost。

是否结束必须有明确规则、原因和授权。

## 4.11 场景 J：客户明确拒绝

如果家长明确表示不报名、不再接受后续招生联系，销售可以发起 Closed Lost。

必须记录：

- 流失原因。
- 客户反馈。
- 结案日期。
- 结案操作人。
- 相关沟通证据或备注。

结案后停止常规销售跟进任务。

如果客户明确要求不再联系，应遵守该要求，不得仅为维持任务链继续安排联系。

# 五、下一步跟进动作统一设计

## 5.1 下一步动作类型

统一管理：

### 联系类

- 再次电话联系
- 微信文字联系
- 微信语音联系
- 视频沟通
- 等待回复并到期检查
- 发送课程资料
- 回访家长

### 邀约类

- 首次邀约线下面谈
- 再次邀约线下面谈
- 确认家长到校时间
- 到访前提醒
- 重新预约面谈

### 试听类

- 确认试听日期
- 安排试听
- 试听前确认
- 回访试听结果
- 再次试听

### 报名类

- 确认课程方案
- 确认价格
- 确认报名协议
- 跟进首笔付款
- 跟进剩余学费
- 核实报名信息

### 其他

- 主管协助
- 内部协调
- 定期回访
- 自定义动作

## 5.2 所有下一步动作的统一字段

每个动作必须具备：

| 字段 | 要求 |
|---|---|
| Lead ID | 必填 |
| 学生或联系人 | 按现有主体规则关联 |
| 动作类型 | 必填 |
| 具体事项 | 必填 |
| 执行日期 | 必填 |
| 执行时间 | 必填 |
| 负责人 | 必填 |
| 关联沟通记录 | 可选，适用时关联 |
| 关联预约记录 | 可选，适用时关联 |
| 待办状态 | 系统维护 |
| 创建人和时间 | 自动记录 |
| 完成结果 | 完成时填写 |
| 变更历史 | 自动保存 |

系统应使用统一的待办能力管理这些动作，不能为每一种沟通结果单独开发一套互不关联的提醒系统。

# 六、销售待办状态与生命周期

## 6.1 待办状态

建议统一为：

- 待执行
- 执行中
- 已完成
- 已改期
- 已取消

逾期应优先作为根据当前时间计算的标识，而不是覆盖待办的实际生命周期状态。

## 6.2 待办完成规则

销售执行待办后，需要记录本次结果。

如果 Lead 尚未结案：

- 必须生成或关联下一步有效活动。
- 才能完成当前待办。

如果已经合法结案：

- 可以完成最后一项待办。
- 停止后续常规跟进。

不能先完成旧待办，再因新待办创建失败造成 Lead 没有后续安排。

## 6.3 改期规则

允许销售调整执行时间。

必须保留：

- 原执行时间。
- 新执行时间。
- 修改人。
- 修改时间。
- 修改原因或备注。

改期不应额外创造一次已完成跟进。

## 6.4 负责人变更

Lead 转交其他销售时：

- 继承已有待办。
- 明确新的负责人。
- 保留原负责人历史。
- 不得出现无人负责的活动。

如果新负责人尚未确认接手，应进入主管待分配队列，不得让任务从工作台消失。

## 6.5 已有异常数据

对于旧系统中没有下一步待办的活跃 Lead：

1. 识别异常。
2. 放入待补安排清单。
3. 提醒负责人或主管。
4. 要求补充下一步动作。
5. 不擅自生成虚假的联系时间。

# 七、线上邀约线下面谈的完整业务设计

## 7.1 业务目标

教育培训销售的常见目标是：

先在线上建立联系、确认基本需求，再争取家长线下面谈。

因此，线上沟通和线下面谈之间应建立明确的业务关联。

不能只记录：

“电话沟通完成”。

还需要知道：

“是否成功邀请家长到校？”

## 7.2 线上沟通目的

选择“已完成沟通”后，可以选择本次主要目的：

- 了解学生需求
- 邀约家长线下面谈
- 介绍课程及价格
- 跟进试听
- 跟进报名
- 普通回访
- 其他

普通沟通不要求填写邀约结果。

只有存在实际邀约时才展示邀约信息。

## 7.3 线下面谈邀约结果

建议包括：

1. 已发出邀请，待回复
2. 家长同意，时间未定
3. 已确认面谈时间
4. 家长暂时不方便
5. 本次邀约被拒绝
6. 其他

不同结果触发不同操作。

### 已发出邀请，待回复

要求设置：

下次检查回复时间。

### 家长同意，时间未定

要求设置：

下一次确认时间的跟进。

### 已确认面谈时间

必须录入：

- 面谈日期。
- 面谈时间。
- 面谈地点。
- 对应学生。
- 预约负责人。

保存后创建或关联面谈预约。

### 家长暂时不方便

要求：

重新联系日期和事项。

### 本次邀约被拒绝

不自动判定 Closed Lost。

可以继续线上介绍课程或重新安排其他跟进方式。

只有客户明确拒绝整个报名机会并符合结案条件时，才能 Closed Lost。

# 八、M07：线下面谈与试听管理

## 8.1 两类活动必须分开

**线下面谈不等于试听。**

面谈可能只是：

- 了解孩子学习情况。
- 介绍机构。
- 介绍课程。
- 介绍价格。
- 了解家长顾虑。
- 商议下一步试听。

试听则是学生实际体验课程。

系统必须分别管理。

## 8.2 线下面谈预约

至少记录：

- 学生
- 家长或联系人
- 预约日期
- 预约时间
- 面谈地点
- 预约负责人
- 预约状态
- 实际到场情况
- 面谈完成情况
- 面谈结果
- 备注

状态：

- 待确认
- 已确认
- 已改期
- 已完成
- 已取消
- 未到场

保留完整历史。

## 8.3 面谈后的销售记录

实际面谈结束后，销售可以记录：

- 已完成需求沟通。
- 已完成课程介绍。
- 已完成价格介绍。
- 家长对课程认可。
- 家长有疑虑。
- 家长希望试听。
- 家长有报名意向。
- 其他。

“课程及价格已介绍”只能在课程及价格确实已经介绍后选择。

不应仅因家长到校就自动推进到这个阶段。

## 8.4 试听预约

无论是否对接 CRM，销售始终可以：

1. 新增试听预约。
2. 录入试听日期。
3. 录入具体时间。
4. 录入试听课程。
5. 录入试听地点。
6. 修改预约。
7. 取消预约。
8. 确认实际试听完成。
9. 记录试听反馈。

试听日期和时间由销售根据真实业务情况录入，不依赖原 CRM。

## 8.5 试听阶段

保留销售可选的：

- 已预约试听
- 已完成试听

选择“已预约试听”时，要求存在相应试听安排。

选择“已完成试听”时，要求确认实际试听完成情况。

不允许仅因为预约日期已经过去，就自动判断学生完成试听。

## 8.6 未来对接原则

未来 CRM 对接后：

- 销售仍然可以录入试听时间。
- 销售仍然可以修改或提出改期。
- CRM 可以同步排课确认和实际试听结果。
- 系统区分销售录入与自动同步。
- 冲突必须核对。
- 不得静默覆盖历史。

本次只保留支持这些要求的业务记录能力，不开发集成逻辑。

## 8.7 试听结束后的下一步

完成试听不是销售终点。

必须继续选择：

- 回访家长。
- 跟进报名。
- 再次试听。
- 调整课程方案。
- 暂缓并安排回访。
- 按有效理由结案。

同时指定下一步日期、时间、事项和负责人。

# 九、销售阶段重新定义

## 9.1 建议阶段

1. 待了解需求
2. 需求已确认
3. 课程及价格已介绍
4. 已预约试听
5. 已完成试听
6. 有报名意向
7. 报名办理中
8. 暂缓
9. 明确不报名

这里的“已预约试听”和“已完成试听”保留为销售人员可见、可选择的阶段，同时后台维护独立试听事实记录。

“明确不报名”应进入 Closed Lost 结案确认流程，不能只是修改阶段却留下一个没有明确处理结果的 Lead。

## 9.2 阶段修改规则

- 可以跳过某些阶段。
- 不要求按照固定顺序逐级推进。
- 课程及价格可能在线上或线下介绍。
- 不要求一定先完成线下面谈。
- 不要求一定试听。
- 阶段改变必须保留历史。
- 默认保持上次销售阶段。
- 一次联系失败不影响已确认的历史进展。

## 9.3 三类状态分离

必须分别维护：

**销售进展状态**

用于了解正在推进什么。

**预约试听状态**

用于记录实际预约及试听事实。

**报名及缴费状态**

用于判断是否正式报名成功和是否缴清学费。

不得让销售人员仅通过修改阶段来伪造预约、报名或付款事实。

# 十、M08：课程方案和报价

保留原有多课程方案能力。

要求：

1. 一个学生可拥有多个意向课程。
2. 可以一次报价多门课程。
3. 记录课程名称、课时、价格。
4. 自动计算报价。
5. 区分标准价格、优惠和实际报价。
6. 保留每次报价版本。
7. 可以调整报价，但不能覆盖历史。
8. 特殊优惠需要授权审批。
9. 使用精确金额计算。
10. 不要求销售手动创建复杂商机或重复录入学生。

报价完成后：

如果尚未报名，应生成下一步跟进动作。

例如：

两天后电话询问家长对课程方案和价格的意见。

# 十一、M09：报名与收款规则

## 11.1 报名成功标准 B

正式采用：

**报名协议及订单已经有效确认，并且首笔有效款项已经到账。**

首笔款项可以是：

- 定金
- 订金
- 部分学费
- 全部学费

不要求缴清全部学费。

以下情形不能算报名成功：

- 只是口头表示愿意报名。
- 只确认课程方案。
- 只签署报名协议，没有到账。
- 只收到款项，没有确认协议。
- 销售上传付款截图，但未经有效核实。

## 11.2 报名状态

单独管理：

- 未发起报名
- 待确认协议
- 待首笔付款
- 报名成功
- 报名已取消
- 报名异常待核实

报名成功应由系统根据有效业务记录认定。

不能由销售手动直接选择。

## 11.3 收款状态

建议管理：

- 未收款
- 已收首笔款
- 部分缴费
- 已结清

退款、逾期及争议作为独立信息记录。

不能因为支付了定金就显示“全部学费已结清”。

## 11.4 独立收款确认

市场销售端暂时独立运行。

可以提供：

- 销售登记收款资料。
- 上传有效凭证。
- 授权人员核实到账。
- 确认款项对应的学生和订单。
- 更新已收金额和应收余额。

销售提交收款资料不等于正式确认到账。

## 11.5 报名成功与 Closed Won

本次继续区分：

**报名成功：** 协议确认＋首笔有效到账。

**学费结清：** 有效净收款达到应付金额。

**Closed Won：** 在本轮保留原有全款成交判断规则，未经另行确认不得擅自变更。

因此，报名成功后，如果仍有未完成的收款或成交事项，销售链条仍然需要继续推进，直到满足 Closed Won 条件。

相关任务可以是：

- 跟进约定付款。
- 确认剩余学费。
- 处理付款异常。
- 核实订单结清。

不得仅因为“报名成功”，就自动删除全部后续待办。

## 11.6 退款与取消

必须：

- 保留原报名成功事件。
- 保留原收款记录。
- 追加退款或冲正记录。
- 更新当前有效报名状态。
- 不直接覆盖历史。
- 不重复计算报名成功。
- 按规则调整业绩。

已结案后发生退款或取消，需要走有审计记录的异常纠正、撤销或重新开启流程，而不是静默修改终态。

# 十二、Closed Won 与 Closed Lost 统一管理

## 12.1 Lead 顶层状态

建议独立维护：

- Open
- Closed Won
- Closed Lost

Open 表示仍在推进。

只有 Closed Won 和 Closed Lost 是正式终点。

## 12.2 Closed Won

需要符合正式成交判定条件。

现阶段保留旧规则中经核查有效的全额付款成交口径。

不允许销售仅通过修改阶段完成 Closed Won。

必须保留：

- 结案业务依据。
- 相关有效订单。
- 有效收款信息。
- 结案日期。
- 责任人。
- 历史记录。

## 12.3 Closed Lost

允许原因包括：

- 家长明确拒绝报名。
- 价格原因。
- 课程不匹配。
- 时间安排不合适且明确不再考虑。
- 已选择其他机构。
- 联系信息无效且经过必要核实。
- 按制度批准结束持续无回应的机会。
- 其他明确原因。

必须记录原因。

不能因为一次无人接听、一次微信未回复或一次预约未到场，自动 Closed Lost。

## 12.4 重新开启

对于已经 Closed Lost 的 Lead，如客户之后主动重新咨询，可以由授权人员重新开启或创建关联的新销售机会，具体取决于现有数据模型。

必须保留原来的结案记录。

不得删除历史 Closed Lost 事实。

# 十三、Lead 工作台界面设计

## 13.1 设计原则

保持现有简洁 Lead 工作台。

目标是让销售人员尽量少切换页面。

## 13.2 页面顶部

显示：

- 学生或联系人姓名。
- 联系方式。
- 意向课程。
- 线索来源。
- 销售负责人。
- 当前销售阶段。
- 报名状态。
- Lead 是否结案。

## 13.3 主要操作

建议保留四项主要入口：

1. 记跟进
2. 约面谈 / 试听
3. 课程方案
4. 办理报名

## 13.4 记跟进表单

建议按照实际操作顺序：

第一部分：本次怎么联系。

第二部分：本次联系结果。

第三部分：本次沟通内容或邀约结果。

第四部分：当前销售进展。

第五部分：下一步动作。

不同结果动态展开对应选项。

例如：

选“电话无人接听”后，不显示课程价格介绍，而是直接进入下一步联系安排。

选“已完成线上沟通”后，可以选择是否邀约家长线下面谈。

选“已确认家长到校时间”后，直接展开面谈预约。

选“已完成试听”后，直接展开回访或报名跟进。

## 13.5 下一步待办区域

在 Lead 详情中明显展示：

- 下一步是什么。
- 什么时候执行。
- 谁负责。
- 是否逾期。

销售进入 Lead 时，首先能够看到当前最需要做的事。

## 13.6 历史时间线

按时间展示：

- 沟通记录
- 联系失败
- 待回复
- 下次跟进安排
- 跟进完成
- 线上邀约
- 预约改期
- 家长到访
- 面谈完成
- 试听预约
- 试听完成
- 课程报价
- 报名办理
- 收款确认
- 结案及异常

历史记录不得被后续操作直接覆盖。

# 十九、数据与技术实现要求

## 19.1 数据设计原则

优先复用现有数据模型，不无故创建第二套 Lead、学生或销售任务系统。

必要时扩展：

- 沟通记录
- 沟通方式
- 邀约结果
- 预约活动
- 试听事实记录
- 下一步待办
- 报名订单
- 有效收款记录
- Lead 终态
- 审计事件

不要将销售阶段、预约状态、待办状态和收款状态全部塞进一个状态字段。

## 19.2 活跃 Lead 不变量

对于正式生效、未结案且已分配负责人或处于受控分配队列的 Lead：

必须存在至少一项有效后续动作。

对于新建 Lead：

创建时必须同时指定首次联系任务或进入有明确负责人与处理期限的分配任务。

对于旧数据：

无任务的活跃 Lead 进入异常补全流程。

## 19.3 任务原子性

保存本次跟进、完成当前任务、创建下一任务必须保证一致性。

推荐使用事务或符合现有架构的等效一致性方案。

不能出现：

旧任务已完成，但新任务未创建，导致销售链条消失。

如果保存失败：

应保留原有效任务，或清晰标记恢复处理状态。

## 19.4 幂等性

以下操作必须避免重复：

- 重复点击保存。
- 网络超时重试。
- 重复创建同一预约。
- 同一任务重复完成。
- 同一收款重复确认。
- 同一报名重复认定。
- 同一结案事件重复生成。

## 19.5 并发修改

两位销售或主管同时修改同一 Lead 时，应保留现有版本校验与冲突保护。

不能默默用旧数据覆盖新记录。

## 19.6 历史数据迁移

遵循：

- 向前兼容。
- 新增迁移，不改写旧迁移。
- 旧记录保留。
- 无法确认的旧字段不自动推断。
- 必要时增加兼容映射或待核实标识。
- 迁移前后验证记录数量与业务关联。

# 二十、测试和验收标准

至少覆盖以下场景。

## 20.1 联系失败

**TC-01**

电话无人接听，选择再次电话联系。

预期：

必须填写日期、时间、事项。

保存后存在新待办。

**TC-02**

电话无人接听，选择改用微信。

预期：

必须选择微信方式及下次联系时间。

不能只保存“改用其他方式”。

**TC-03**

电话无人接听，未填写后续动作。

预期：

正式完成跟进应被阻止，允许保留草稿。

## 20.2 待回复

**TC-04**

微信消息已发送，家长未回复。

预期：

必须设置检查回复或再次联系时间。

**TC-05**

等待时间已过，仍没有回复。

预期：

待办显示逾期。

不得自动 Closed Lost。

## 20.3 线上邀约

**TC-06**

家长同意到校，但时间未定。

预期：

必须创建确认预约时间的后续动作。

**TC-07**

家长确认线下面谈时间。

预期：

创建或关联一条有效预约。

不得生成重复预约。

**TC-08**

家长拒绝本次到校邀约，但仍愿意线上了解。

预期：

继续生成线上沟通待办。

不得自动 Closed Lost。

## 20.4 面谈与试听

**TC-09**

家长预约后未到场。

预期：

记录未到场，并要求安排后续动作。

**TC-10**

家长完成面谈，但未介绍课程价格。

预期：

不能自动推进为“课程及价格已介绍”。

**TC-11**

销售录入试听时间。

预期：

不需要连接 CRM。

**TC-12**

销售修改试听日期。

预期：

新时间有效，原时间留痕。

**TC-13**

试听完成。

预期：

记录实际完成事实，并生成或关联下一步跟进。

## 20.5 跟进链条

**TC-14**

销售将 Lead 设置为暂缓。

不能重复创建有效后续任务。

**TC-16**

新任务创建失败。

**TC-17**

Lead 转交其他负责人。

**TC-18**

不得强制再创建一条重复的普通跟进待办。

## 20.6 报名及结案

**TC-20**

预期：

不算报名成功。

**TC-21**

# 二十三、最终不可违反的业务原则

### 原则一：跟进链条不能断

只要 Lead 仍处于 Open 状态，就必须存在明确的后续行动。

联系失败、待回复、暂缓、预约取消、未到场、试听完成等，都不是销售链条的终点。

### 原则二：每一步都有执行时间

“稍后联系”“等待回复”“改用其他方式”都不算完整的后续动作。

必须有具体时间、行动内容和负责人。

### 原则三：真实业务事实与销售人员判断分离

联系、预约、到场、试听、报价、报名、付款分别保存。

不得用一个销售阶段代替所有事实。

### 原则四：尽量减少操作

根据本次结果动态显示必要字段。

不强迫销售填写与本次业务无关的内容。

能复用的学生信息、预约信息和业务记录不重复填写。

### 原则五：不丢失历史

所有阶段变化、任务完成、预约改期、收款确认和结案都保留历史。

### 原则六：只有合法终态才能结束销售链条

Closed Won 和 Closed Lost 才是正式终点。

报名成功和其他中间阶段不能随意替代终态。

### 原则七：当前市场销售端完全独立

所有现阶段需要的业务能力，在市场销售端自行实现。

不等待原 CRM 对接，也不修改原 CRM。
