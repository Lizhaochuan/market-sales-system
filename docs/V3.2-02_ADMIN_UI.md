# V3.2-02｜中文管理工作台：隔离演示与交互验收

**版本**：V3.2-02，独立开发候选  
**仓库**：market-sales-system  
**依赖**：V3.2-01 后端 PR #5（未合并）、V3.1-04 整合 PR #4（未合并）  
**原则**：学生为主要客户主体，家庭关系仅按需核实；与现有教培 CRM 独立开发、独立技术文档，最终真实集成并联合验收后才融合说明。

> 目前是**可运行的本机隔离演示版**，不是正式教培 CRM 的员工登录系统，也未连接真实客户或付款。所有操作必须在虚构数据库环境中进行。

## 一、员工可直接使用的中文页面

| 页面 | 可以操作的内容 | 不提供的能力 |
|---|---|---|
| 工作概览 | 当前账号可查看的学生、联系人、线索、商机数量 | 不显示未经核实的实收金额和成交业绩 |
| 学生客户 | 建立学生档案、查看本人/授权学生 | 不自动新建家庭；不通过电话自动合并 |
| 家长与联系人 | 新建称呼、设置拒绝主动联系、将已授权联系人关联学生 | 不采集明文手机号、微信号；不把联系人视为学生身份 |
| 咨询与线索 | 记录真实咨询、将咨询转化为线索、关联具体学生 | 不复制真实咨询事件；未知学生不创建假学生 |
| 销售商机 | 为指定学生建立商机、填写预计金额（元） | 预计金额不代表实际付款或正式成交 |
| 跟进记录 | 一次沟通可同时关联两名不同学生 | 不因两个学生计算两通电话 |
| 家庭关系核实 | 主管提交两名以上学生的待核实申请 | **没有最终核实/审批功能，不会自动生效** |
| 业务变更记录 | 针对有权查看的学生/线索/商机查看中文业务操作 | 不直接展示原始 JSON、数据库字段或程序源码 |

界面为中文响应式布局，支持桌面与窄屏。业务记录采用中文姓名、可理解状态和金额单位；所有用户填入的文本以安全纯文本方式显示。

## 二、真实 API 与前端说明

- `web/index.html`：工作台结构、登录、八个中文业务模块。
- `web/styles.css`：响应式设计，原生字体，无第三方资源。
- `web/app.js`：业务表单、列表、数据刷新、消息与权限错误提示；**会话令牌只保存在页面内存中，不写浏览器 localStorage**。
- `src/ui-assets.mjs`：本机静态页面资源，严格 Content-Security-Policy、禁止缓存、禁止第三方脚本。
- `src/dev-login.mjs`：只向固定虚构员工签发**隔离测试会话**；必须有本机专用环境口令，不能认证真实员工。
- `src/app.mjs`：新增按机构和销售范围受限的学生/联系人/咨询/线索/商机/家庭只读列表。
- `tests/fixtures/fictional_ui_demo_seed.sql`：虚构机构、销售A/B、主管；只用于演示和测试。
- `tests/ui/admin-ui.http.test.mjs`：通过 HTTP 验证静态页面、隔离演示登录、三个员工的可见范围和禁止跨员工认领联系人。
- `api/openapi/core-implemented.v3.2.json`：V3.2-01 已实现的14条低风险 API。V3.2-02 新增的列表及演示登录需要**另外的接口补充规范**，不可误认为原 V3.2-01 规范已覆盖全部。

## 三、如何在隔离环境运行

**只适用于一台已经安装 Node 22、PostgreSQL 16+ 的开发电脑。不要在已有 CRM 的数据库、正式客户数据或公开服务器执行。**

1. 克隆本仓库 V3.2-02 分支，确认独立测试数据库已经创建。
2. 运行 `npm install` 安装独立后端依赖。
3. 依次执行 `db/migrations/001_initial_schema.sql`、`002_financial_integrity_draft.sql`、`003_low_risk_api_idempotency.sql`、`004_contact_event_owner_scope.sql`。
4. **只对全新虚构数据测试数据库**执行 `tests/fixtures/fictional_ui_demo_seed.sql`，生成销售 A、销售 B、销售主管三个演示身份。
5. 在本地 shell 配置：

```bash
export MS_STAGE=isolated-test
export DATABASE_URL='postgresql://<仅测试用数据库账号>:<本地测试密码>@127.0.0.1:5432/<新的空测试库>'
export AUTH_HMAC_SECRET='<自行生成32字符以上的随机测试令牌密钥>'
export DEV_LOGIN_SECRET='<自行生成32字符以上的随机演示访问口令>'
export AUTH_ISSUER=market-sales-test-issuer
npm run start:isolated
```

6. 本机打开 **http://127.0.0.1:3100/**，选择「销售顾问 A」「销售顾问 B」或「销售主管」，输入本机设置的演示口令。登录后页面可填写并保存**虚构学生、家长、咨询和商机**。
7. 在同一个测试数据库中切换 A/B/主管账号，核对权限边界。不要把这个演示访问方式用作生产环境员工登录。

**特别说明**：`DEV_LOGIN_SECRET` 不是 CRM 或 GitHub 账号密码；正式生产登录与多因素认证仍需专门设计。测试口令不允许提交仓库。

## 四、核心交互验收

| ID | 场景 | 必须观察到的表现 |
|---|---|---|
| UI-01 | 本机打开工作台 | 有登录选择及演示环境警示，不显示原始代码 |
| UI-02 | 使用错误口令 | 拒绝进入 |
| UI-03 | 销售 A 创建学生 | 可以看到自己的学生及完整中文姓名 |
| UI-04 | 销售 B 登录 | 不能看到销售 A 的学生档案或商机 |
| UI-05 | 主管登录 | 能查看本机构两个销售的学生 |
| UI-06 | 一名家长联系两个学生 | 仍是两份学生档案，没有自动家庭合并 |
| UI-07 | 其他销售尝试认领未授权联系人 | 被服务端拒绝；主管可以授权关联 |
| UI-08 | 咨询时尚不明确学生 | 能先创建咨询和未识别线索 |
| UI-09 | 一次跟进涉及两个学生 | 系统只创建一条跟进事件和两条业务关联 |
| UI-10 | 主管提交家庭核实 | 明确显示“待核实”，不得展示“已核实家庭” |
| UI-11 | 查看学生审计 | 显示人能读懂的“学生、负责人、关系”等中文业务变更 |
| UI-12 | 在浏览器访问正式订单/财务/课时路径 | 不存在操作页面或接口，不能创建真实交易 |
| UI-13 | 在窄屏下查看模块 | 页面布局能收缩，文字和表单不应溢出 |

**已编写的 HTTP 测试不等于以上全部 GUI 验收通过。** 如果加入浏览器自动化测试，也应区分自动浏览器与真人手工实操。记录实际 CI 链接、Git SHA、成功/失败步骤后才能判定对应测试。

## 五、当前不允许正式上线的原因

- 仅使用环境变量中的演示访问口令和虚构账号，**不是正式身份提供商**。
- 目前列表固定最多读取100条，尚无完整分页、搜索、撤销/转移归属及字段级权限完善。
- 可共享联系人必须由有权限的员工/主管关联，**当前没有受控联系资料跨团队转移审批流程**。
- 家庭关系核实只是“待核实申请”，未形成真实审批完成状态。
- 业务中文审计仍需更完整的业务前后差异模板和全部字段合法性校验。
- 真实手机号/微信号的加密保存、查询、授权、保留和删除政策未开发。
- 真实 CRM 学员映射、标准课程价格、试听预约、正式收款和教务权益仍未接入。
- 没有真实浏览器、微信开发者工具/真机人工验收证据之前，**不得宣称完成生产 GUI 验收**。
