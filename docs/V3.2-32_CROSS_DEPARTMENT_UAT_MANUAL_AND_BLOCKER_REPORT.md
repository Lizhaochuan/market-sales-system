## 一、执行原则与报告接口

V3.2-31 的 16 个准入条件仍然是跨系统的不可突破门槛。V3.2-32 只把它们映射为**可以阅读、逐项收集材料和开展未来 UAT 的任务报告**。

- `db/migrations/035_readonly_integration_uat_report.sql`：新增 `ms.readonly_integration_uat_report(uuid)`。通过受保护的 PostgreSQL `SESSION_USER` 和 V3.2-31 机构授权链，读取指定虚构来源的 12 项相关 UAT 检查，所有任务状态均为 `blocked_real_approval_missing`。
- `src/integration-uat-blocker-report.mjs`：纯 JavaScript 只读报告生成器 `buildBlockedUatTasks`、`renderBlockedUatMarkdown`；接受上述数据库只读 JSON，校验机构申请 UUID、领域、12 项不重复的编号、缺失事项数量与**所有批准/执行字段均为 false**，才输出 Markdown 格式待办报告。
- **任何多余的“已经批准”“真实联调成功”“解除隔离”标记均不能使报告变成完成状态。** 伪造 `execution_allowed=true`、`ready_for_production=true` 或缺失/重复任务，报告生成器会拒绝生成。
- 报告只显示检查编号、责任人、证据类型、验收动作、拒绝条件、缺失记录数量。**不包含真实 API 凭证、账户、儿童隐私、资金详情、正式合同原文，也不执行发送/审批/签字。**
- 新报告没有正式 Web 操作界面，也没有自动发送给负责人。须在 V3.2-32 以后的、经真实权限批准的单独阶段设计安全展示/导出。当前可由隔离测试的受限 DB LOGIN 取到 JSON，再用纯函数离线生成中文 Markdown。

| `finance_authority_owner` | 财务负责人、支付源系统所有人 | 唯一权威来源与负责人签署 | 财务账务权威角色已核实 | 靠销售人员自报银行来源 |

## 三、UAT 操作剧本（正式授权前仅纸面演练）

### UAT-01：正确学生与原合同

**前提：** 错误学生关联、已有订单或收付款、已产生课时/履约；原案件仍处于 `hold_active`。销售和合同责任人逐项核查原学生和真实目标学生，而不是根据姓名或家庭自动选择。必须保留原商机、订单、SaleEvent、合同和归因历史。任何原合同缺失、目标学生证据冲突，直接拒绝并升级人工核查。

### UAT-02：财务来源最小只读

只有经财务系统所有人、机构账套负责人和信息安全负责人独立批准，才允许在未来正式受控环境验证**只读访问**。UAT 应验证越机构请求被拒、账号不能收款/退款/修改付款分配，且单个经济事件在退款、拒付、拆分分配下不重复计算。版本缺页、水位不完整或来源 unknown：保持隔离，不得自行作废原支付。

### UAT-03：CRM 学生、课包和实授记录

教务与 CRM 所有人核对正确学生、原学生、课包、排课、已上/已消与剩余权益。测试账号只能查询，不能发课或扣课。超时、无 package_id、版本突变或剩余课时冲突必须保持未知状态；历史实授与消课不允许删除。

### UAT-04：信息安全、故障与恢复

至少模拟错误机构、伪造签名、已撤销密钥、重复消息、同序号不同内容、缺页、分页游标错误、数据水位回退、超时未知、掉电重启。先登记故障，财务/教务业务人员与安全人员独立复核，未经权威补查不得升级状态。真实可信密钥、持久账本和恢复机制仍待正式批准，本阶段的模拟验收不能给出生产通过。

### UAT-05：跨模块终验与不解除隔离

销售、财务、教务分别核验自己的真实权威证据；信息安全确认来源、访问权和审计。只有未来真正补偿执行有完整独立批准、原记录留存和 R01—R10 全部满足，才可另行设计释放授权。**本阶段即使纸面检查全部填写完整，也仍禁止实际补偿、原订单改绑与解除隔离。**

## 四、每项证据的最低提交模板（供未来负责人填写，不是本期已提交材料）

| 字段 | 说明 |
|---|---|
| 检查编号 | 例如 `finance_reconciliation` |
| 机构与来源 | 独立明确机构、财务账套或 CRM tenant；禁止混用 |
| 负责人与复核人 | 不同自然人、真实岗位和经核实的系统身份 |
| 来源引用和版本 | 权威单据/课包 ID、版本、水位、查询时间；敏感数据通过受控系统保存，不放公开 Git |
| 原始事实与拟议补偿 | 原订单/金额/课包记录保持只读；计划只追加不执行 |
| UAT 操作及预期 | 明确只读查询、越权拒绝、异常输入、幂等与回滚边界 |
| 实测证据 | 经批准环境中的审计编号与脱敏截图、断言日志、复核签署 |
| 结果与阻断 | 通过/未通过由未来真实权威验收系统记录；**不能写入本期的固定阻断函数** |
