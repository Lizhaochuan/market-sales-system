# V3.2-28｜财务与 CRM 只读来源认证准备、版本水位及失败恢复

**交付状态：独立市场销售系统的隔离技术验证；尚未接入真实财务或教务权威。**
**基线：** V3.2-27 Draft PR #32（验收提交 `5e3662a234563b53b772e947ad5b5dbeb604e1da`）。
**范围：** 仅虚构 Ed25519 来源密钥、测试签名、受保护的本地数据库权限和拒绝执行的预审；不修改旧 edu-management-system、原 CRM 技术文档、真实学生数据或资金/课时。

## 1. 本期实际完成什么

- `src/cross-module-fixture-source-verifier.mjs`：纯本地、无网络、无数据库写入的**测试环境来源签名验证器**。在 V3.2-27 只读候选合同上，追加由测试调用端配置的来源身份、机构租户、用途受众、Ed25519 公钥、生效/失效时间、签名验证、连续分页、逐事件序号与单调水位。
- `tests/security/cross-module-fixture-source-verifier.test.mjs`：运行时生成虚构密钥（私钥不写入仓库），测试有效签名与拒绝伪造来源、跨租户、错受众、过期密钥、篡改载荷、重放、跳页、版本倒退、未知结果等案例。
- `db/migrations/031_readonly_source_trust_readiness_gate.sql`：只增加**只读、永久受阻**的生产来源准备门槛，复用 V3.2-27 原有的机构和员工身份核查。其返回值固定 `execution_allowed=false` 和 `release_allowed=false`，并列出缺失的真实授权、持久重放账本、完整水位和资金/课时对账条件。
- 不新增真实来源密钥配置表、真实接口 URL、外部 token、网络读取服务、执行队列、资金/订单/CRM 写入接口或解除隔离函数。

**安全含义：测试签名校验成功 ≠ 真实来源已认证。** 一个测试私钥持有者仅能证明模拟消息确实经过其签名；不能因此成为机构真实财务部门、银行、收银系统、教师或 CRM 的权威人员。所有测试验证结果仍返回 `source_authenticated=false`、`finance_authority_verified=false`、`crm_authority_verified=false`、`execution_allowed=false`、`release_allowed=false`。

## 2. 测试环境信封协议

信封版本 `v3.2-28-fixture-transport-v1`，包含：
- `department`：finance 或 academic；必须匹配**调用端已有的**部门。
- `source_system` / `source_tenant`：必须在**调用端已有的**机构—来源允许清单中；不能由消息自报增加。
- `issuer`、`audience`、`key_id`：与预先配置的唯一虚构测试公钥匹配；错误 issuer/audience/密钥一律拒绝。
- `batch_id`、`page_index`、`previous_cursor`、`next_cursor`、`is_final_page`：分页必须逐页连续；结束页无 next_cursor；新批次必须在前一批完整结束后开始。
- `source_sequence`、`source_watermark`：同一来源、部门、机构、候选对象流中，序号连续增长，水位不得回退；断档、重复不同内容、旧序号回放拒绝。
- `issued_at`：测试签名在限定时间窗内有效（当前测试时点前 10 分钟至未来 1 分钟）。
- `payload_sha256`、`payload`、`signature`：先按 V3.2-27 精确规范化候选，重新计算摘要，并以 Ed25519 对固定字段顺序、带隔离域前缀的签名材料进行校验。

**说明：** SHA-256 仅用于检测载荷一致性，签名验证使用可信配置提供的 Ed25519 公钥。私钥在 CI 测试中即时生成；没有任何实际支付或 CRM 来源私钥可用。使用方不能通过填写 `verified` 或 `execution_allowed` 来改变结论。

## 3. 数据水位与失败恢复的最小安全要求

| 场景 | 当前测试环境处理 | 将来正式连接必须解决 |
|---|---|---|
| 同一签名和同一序号重复接收 | 识别精确重复，返回相同“未授权”状态 | 持久、事务性的去重库及多节点恢复 |
| 同序号不同内容 | 拒绝 | 跨节点签名校验与冲突审计、排查恶意重放 |
| 缺少前一页或分页游标不匹配 | 拒绝继续 | 分页完整性、服务端游标过期后全量重拉及水位原子提交 |
| 序号跳跃或水位回退 | 拒绝 | 来源可查询版本、水位/补偿事件一致性，以及迟到消息处理 |
| 上一批未结束就开始新批 | 拒绝 | 全量完成证明、落盘水位、断点重启对账 |
| 超时或查询来源 500 | 不转换为“未收款”“未发课”，仍保留未知 | 权威结果查询、指数退避、最大重试窗口与人工升级 |
| 有效签名但旧学生已产生新付款/课时 | 仅确认测试传输；现有本地指纹改变会阻断 | 再次读取真实源水位、锁定业务版本、三方重新验收 |
| 真正资金/CRM 来源连接失败 | 目前没有连接器，恒为缺失 | 连接认证、故障隔离、权限撤销、密钥轮换及证据链 |

目前的重放检查仅使用**进程内 Map**，不具有数据库事务、掉电持久化、跨副本一致性或真实防重放能力；**不能用于生产来源认证**。分页完成只证明模拟流的页码、游标和签名连续，不表示外部所有付款、退款、实际授课和消课事件都已经完整。

## 4. 真实来源上线前必须完成的授权表（仍为待定）

| 项目 | 财务责任人需批准 | 教务/CRM 责任人需批准 |
|---|---|---|
| 真实数据源 | 收款、退款、拒付、分配/冲正唯一权威 | 学生身份、课包、排课、实授、消课及权益余额权威 |
| 来源证书与密钥 | 密钥登记、发行/撤销、受众、签发者和密钥轮换规则 | 同左，不能直接信任浏览器/销售终端提供的密钥 |
| 租户与权限 | 机构、账套、合同签约主体、只读服务范围 | 机构、CRM tenant、学生/课包映射及读取范围 |
| 数据水位 | 经济事件版本、退款与拒付去重、金额守恒 | 请求幂等、包状态、已上/剩余课时和分页完成证明 |
| 异常处理 | 多订单共用收款、用途争议、晚到退款、拒付 | 已上课和未履约区分、超时结果未知、重复开课防护 |
| 实施与验收 | BP-02/BP-05、TP-03/04、合同合法业务依据 | BP-01、TP-05、教务独立负责人和 CRM API 授权 |

**每个真实来源必须先经来源负责人、信息安全负责人和机构业务负责人审批；密钥由独立安全配置管理，不入 Git 仓库、不由销售人员上传，也不由外部响应自定义。** 正式只读连接器需提供证据的长期留存、安全检索、敏感字段脱敏、回执签名与过期撤销机制。完成后还应在两个机构真实隔离测试环境验证，才能考虑将模拟验证逻辑升级。

## 5. 资金、订单和课时仍完全隔离

V3.2-24 的跨模块 R01—R10 解除条件仍然全部有效。V3.2-25 三方审批、V3.2-26 只追加的补偿清单、V3.2-27 候选记录与 V3.2-28 测试签名都**不能直接**修改：
- 原学生与正式线索、原商机、原订单学生或合同主体；
- 财务支付、退款、分配与外部权威经济事实；
- 原 SaleEvent、销售佣金历史、CRM 实际课包和已消课程；
- 原 `hold_active` 销售隔离状态。

**这是签名验证准备阶段，不是“已经连接真实财务与 CRM”的阶段。** PR 必须保持 Draft，不合并、不部署，不操作真实付款/课时或客户档案。旧 Chromium 中文页面回归不等于本阶段新增了来源认证管理页面。
