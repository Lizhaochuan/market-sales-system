# V3.2-109｜M02 来源因果屏障与限时租约的隔离契约

## 基线及本阶段结论

基于 V3.2-108 Draft PR #115，HEAD `e5196e7798fbec49cfb8ecb6536ef85aa7edffa0`，GitHub Actions #43662562811 和 #43662562502 均 `completed/success`。V3.2-108 证实：即使反复检查来源和 SQL checkpoint，也无法封闭最后一次检查后发生撤销的窗口。

本期新增**模拟来源独立签发的因果限时租约与隔离 PostgreSQL 租约围栏**。在隔离环境中把来源版本摘要、撤销序号、租约标识、持有者、作用域、单调围栏 epoch 和模拟过期时间签入 Ed25519 凭证，用真实一次性 SQL 事务约束竞争租约、租约撤销和跨租户数据读取。所有签发密钥都是临时测试密钥，**不是财务、教务或跨部门正式签署权威**。这仍是实验性契约，不是可以部署的生产业务交接协议。

## 实现

- `src/cross-module-causal-lease-fence.mjs`：`createIsolatedCausalLeaseFence` 分别接受已有 V3.2-104 来源签名与水位验证、V3.2-106 SQL checkpoint 读取、独立测试租约签发/状态接口和隔离 SQL 租约账本。签发内容必须绑定已经验证的当前来源水位摘要与撤销摘要；签名、公钥、机构/异常、租约时效、持有者与围栏版本严格核验，额外的放行字段拒绝。
- `tests/fixtures/v3-2-109-m02-lease-ledger.sql`：仅为 CI 的 `v106_isolated` 临时库创建租约围栏表，继续使用测试租户 A/B 专用角色与 PostgreSQL 强制 RLS。此文件位于 `tests/fixtures`，**不是生产迁移**。
- `tests/helpers/v3-2-109-m02-postgres-lease-ledger.mjs`：围栏绑定与撤销通过 `SERIALIZABLE` 事务、作用域 advisory lock 和 `FOR UPDATE` 实现；同一 epoch 下不同租约不能并存，活动租约不能被另一新租约静默覆盖。测试租约可显式失效，下一次读取必须阻断。
- 核验流程：验证签名来源并推进独立审计 checkpoint → 验证租约签名与来源摘要 → SQL 尝试绑定租约 → 验证租约权威的签名状态及 SQL 状态 → 再次确认来源水位、撤销、时效 → 第二次复核。任何不同、撤权、锁失效、数据库错误均拒绝。成功仍只返回 `BLOCKED_CI_CAUSAL_LEASE_OBSERVATION_NO_EXTERNAL_AUTHORITY`。

**注意：** 核验过程调用 V3.2-104 会推进**隔离审计水位**，并且新增独立 SQL 租约绑定。它不是纯无副作用的只读过程，更不能持有业务订单/资金/教务记录写权限。生产必须另行设计原子协调与外部权威。

## 测试与风险矩阵

| 用例 | 隔离测试目标 |
|---|---|
| LEASE-01 | 有效测试租约与 SQL 围栏保持全部业务权限关闭 |
| LEASE-02 | 过期凭证及伪造签名在 SQL 绑定之前拒绝 |
| LEASE-03 | SQL 绑定后签发方撤销，不能使用旧租约 |
| LEASE-04 | 签发方声称租约有效但 SQL 已撤销，必须拒绝 |
| LEASE-05 | 绑定后来源证据变化或撤销，必须拒绝 |
| LEASE-06 | 检查中到期、伪造状态签名、epoch 冲突拒绝 |
| LEASE-07 | 同机构/异常同 epoch 的并发租约不能同时成功 |
| LEASE-08 | 来源签名错误不能写入租约账本 |
| LEASE-09 | 跨机构数据库受限角色无法提交 |
| LEASE-10 | 伪造资金/交接放行字段或回执拒绝 |
| LEASE-11 | 最终核验返回后来源仍可能撤销：**已发现的因果缺口继续存在** |

这些测试在临时 PostgreSQL 16 与模拟签名密钥中运行。它们并不证明真实来源服务器会在本方 SQL 提交期间锁定版本或拒绝撤销；两个系统的租约状态查询与本地 SQL 并不构成原子事务。离开最后一次读取之后的新撤销仍然可能发生。

## 仍需的正式业务与合同验收

真实生产级因果屏障必须由独立可信的销售、财务、教务来源共同签署来源版本向量、租约持有者和释放/吊销语义；必须有可证实的跨系统原子提交或安全拒绝凭据。任何锁丢失、租约到期、真实人员撤权、不可确认 SQL 提交、伪造签收回执都必须直接拒绝真实业务交接。

六项外部权威（财务独立签字、教务独立签字、订单与收付款对账、课时履约对账、三方验收、原子交接回执）、16 项外部准入、R01—R10、正式 PostgreSQL/Chromium/合同/UAT 全部没有由本期确认。合同继续 `proposed-unimplemented`，业务权限持续 `finance_authorized=false`、`academic_authorized=false`、`handoff_allowed=false`、`compensation_write_allowed=false`、`release_eligible=false`、`hold_active=true`。

学生为主要管理单位；只有同家庭多个孩子时按需建立家庭关联。历史订单、收付款、SaleEvent、课时与补偿信息只追加保留，不原地覆盖。上游生产迁移 001—038 不变，没有 039。保持 Draft、不合并、不部署、不修改 `edu-management-system`、生产服务和数据库；市场销售技术文档独立保存。

**V3.2-110 推荐：** 先对锁失效通知、租约吊销传播和可信原子提交回执建立独立合同及否定测试，确认“租约观察当前”绝不被误读为具有真实跨模块业务交接权。
