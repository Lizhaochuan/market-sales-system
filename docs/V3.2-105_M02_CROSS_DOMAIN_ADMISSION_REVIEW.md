特别强调：所谓只读验证流程在 V3.2-104 调用 checkpointStore.advance 时，存在对**隔离审计水位**的内部写入意图。生产设计必须将受限审计版本推进角色与订单、应收、付款、课时及补偿数据的写权限彻底分离。存储端返回 accepted=true 不能独自证明持久、不可回退或原子成功。

## 生产验收所需的独立证据

**真实来源身份和授权：** 需要由独立人员提供治理方身份、组织范围、密钥生命周期、真实财务与教务签名权威和撤销凭据；临时测试密钥不得升格为生产密钥。

**真实数据库事务：** 按 V3.2-104 DB-01—DB-08，在独立 PostgreSQL 测试库实施验证：复合组织/异常唯一键、事务性比较与推进、双进程并发争用、崩溃后回读、旧密钥撤销及重放、同版本证据改写、跨机构拒绝访问和伪造成功回执。测试库的独立管理者、非生产权限、连接资料与执行记录当前都尚未确定。本期不编写 SQL 生产迁移，也没有运行数据库。

**跨系统因果和业务验收：** 三域提供相同撤销序号、来源 epoch 或业务时间，并不等于它们属于同一原子业务快照。需要明确外部签署的来源版本向量、交易屏障和统一回执。真实业务解隔离仍要求财务签名、教务签名、订单/收款对账、课时权益对账、三方验收和原子交接回执六类条件。16 项准入与 R01—R10 同样不能缺失。
