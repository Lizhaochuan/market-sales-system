# Market & Sales 修订版增量开发顺序（基于当前 V3.4 / PR #129）

日期：2026-11-19 ｜ 状态：**审计性建议，未批准开发**

> 原 Argon 的七份文件仍作为候选设计素材保留。本计划针对其过期基线与业务规则冲突进行纠偏；不声称完成本地全部源代码审计。

## Gate 0 — 校准真实代码基线（必须完成）

- 从 `chatgpt/v3-2-121-m02-revocation-notices` 取得**实时 HEAD SHA**，核对 PR #129 Draft/HOLD、HEAD 对应 CI、数据库迁移 039/040、服务器开关、代码/SQL 与浏览器测试。
- 本地检查 `git status` 及未推送文件；现有交接文档分支 `chatgpt/ms-ai-handoff-20261119` 只含文档，不等于最新业务开发分支。
- 按 `docs/ROLE_WORKSPACES.md` 的最新角色卡片和 `docs/V3.4_SALES_WORKFLOW.md` 逐项核对原60项矩阵。重新标记已完成/需改进/未完成/存在冲突/需决策。
- 对每项“缺失”必须给出当前代码路径、实际可运行模式、测试证据；不能仅依据早期入口仍存在就断定新入口没有功能。

**验收：** 重新出具当前 HEAD 的基线清单、修订60项差异矩阵，列明 Git diff、CI 与代码证据。

## Phase 1 — 优化既有销售工作台，不创建第二套销售工作流

1. 延用现有 `web/sales-workflow.js`、`src/sales-workflow.mjs`、原 Lead/学生/活动/历史和 DB 不断链约束。
2. 在**保留现有“按角色工作台 + 单项操作卡片 + 今日待办”**的前提下，结合用户研究包优化信息层级、侧边详情/列表上下文、快捷录入与筛选。不要恢复历史十模块密集 Tab 作为主工作台。
3. 保护已经验收的：通过电话查重接收市场 Lead、刚完成沟通与下一步同事务、直接约面谈/试听、真实改期/到访/课后跟进、多课程方案与独立核款、单项卡片草稿的内存安全及角色隔离。
4. 如采用新看板、日历和 Saved Views，必须基于**当前**原 Lead、活动和权限过滤进行只读展示；看板拖拽不能直接写“已报名/已到场/已收款”事实。
5. 不引入第二套 `ms.sales_tasks`、`VisitAppointment`、`lead_workflow`，除非实际最新代码审计证明必要且有数据迁移方案。

**验收：** 角色权限、回访不断链、预约/改期、报名与核款、未保存表单刷新/撤权、窄屏、既有 Playwright/Node/PostgreSQL 回归。

## Phase 2 — Boss 端：优先数据指标契约和证据化下钻

- 复用 V3.4 已有 `GET /workflow/metrics` 及真实业务账本，避免新建独立指标“事实源”。
- 先确定每项 M01—M22 的业务主体（唯一 `lead_id` 或 `student_id`，不能混用）、事件时间、快照粒度、分子分母、时间区间、费用数据质量和当期/队列口径。
- **M15 报名成功 B = 独立核实的有效协议 + 已核实有效正额净收款**；意向单/报价不是标准 B；M14 正式 Won 要求全额等既有硬约束。
- 汇总与下钻必须采用一致的 SQL 口径和授权过滤；`as_of_at` 需要真实事件/版本时态数据，不能简单以 `created_at <= as_of_at` 作为历史状态重建证明。
- 未配置真实渠道费用或缺少费用归属证据时显示“待配置成本源”。
- 所有管理动作遵守现有部门权限/转交审批/接收人确认；督办是否完成必须依据对应要求的证据，不是“任何跟进自动销项”。
- 先实现最有用的“异常 → 顾问/渠道 → 学生 → 原始事实 → 合规督办”闭环；不要为了凑齐22张卡堆砌无效图表。

**验收：** 各角色/机构隔离、样本去重、非线性路径、标准 B/Won 分离、汇总与下钻权限一致、真实财务审计、历史追溯。

## Phase 3 — 原生微信小程序（销售端、Boss 端）

- 在确认现有仓库没有小程序工程后，新建独立 `miniprogram/`，使用经过审查的身份绑定/后端最小权限接口，**不重新建设数据库/销售状态机**。
- UI 按移动研究分为销售工作台 MS-01—06 与 Boss MB-01—06；两端共用业务接口但不能宣称 WXML 与网页 DOM 是同一套可执行界面。
- 微信登录/员工绑定、合法域名、AppID、真实微信平台能力等外部依赖必须标记受限，不能用 H5 模拟已验收代替原生微信开发者工具/真机验证。
- 草稿设计优先内存和最小敏感性；如确需 `wx.setStorageSync`，另行批准缓存内容最小化、TTL、角色撤权清理和设备风险控制。不得缓存未脱敏家长资料或登录密钥。
- 小程序遵守不自动核款、不自动完成试听、不绕过负责人/公海审批等既有约束。

**验收：** PC/小程序一致性、权限、幂等、重放、弱网、冲突、草稿安全，真实小程序与 H5 分开列测试结果。

## Phase 4 — 公海池与策略参数（单独决策）

- 保留 V3.4 现有市场→销售交接与主管转交，不将二者误命名成“公海池”。
- 公海自动回收、过期阈值、值班主管、暂缓保护、已报名/已有预约的保护及审核流程须按真实业务决策做专项设计；没有审定策略时不得自动回收或越权抢单。
- 入池、认领、改派不能丢失原任务/原期限和交接责任，也不能覆盖既有审计历史。
- 用新的独立迁移编号和隔离测试管理扩展，而不是直接覆盖/回滚现有 039/040。
